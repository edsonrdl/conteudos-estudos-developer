### VPN Site-to-Site vs Remote Access

As duas arquiteturas fundamentais de VPN diferem em quem está se conectando e ao quê. Entender cada uma é essencial para projetar a solução correta para cada cenário.

---

## VPN Remote Access (Acesso Remoto)

Conecta um **usuário individual** à rede privada. O mais comum no dia a dia de equipes remotas.

```
[Laptop do funcionário] ══VPN══► [Gateway VPN da empresa]
                                          │
                                   [Rede interna]
                                   ├── Servidor de arquivos
                                   ├── Banco de dados
                                   └── Sistemas internos
```

**Características:**
- Cliente VPN instalado no dispositivo do usuário.
- Cada sessão é individual e autenticada por usuário.
- O IP do usuário na rede interna é atribuído dinamicamente.
- Protocolos comuns: OpenVPN, IKEv2/IPsec, WireGuard, SSTP.

**Caso de uso:** funcionário em home office precisa acessar sistemas internos da empresa.

---

## VPN Site-to-Site

Conecta **duas redes inteiras** de forma permanente, como se fossem uma rede local única.

```
[Filial SP]                              [Filial RJ]
 10.1.0.0/24                              10.2.0.0/24
      │                                        │
 [Gateway VPN] ════tunnel permanente══════ [Gateway VPN]
      │                                        │
 Roteadores internos                    Roteadores internos
```

**Características:**
- Configurada nos gateways (roteadores/firewalls), não nos dispositivos dos usuários.
- Túnel permanente — os usuários da filial não percebem a VPN.
- IPs de ambas as redes precisam ser roteados pelo túnel (sem sobreposição de subnets).
- Protocolos comuns: IPsec (IKEv2), BGP sobre IPsec.

**Caso de uso:** duas filiais de empresa precisam compartilhar recursos de rede como se estivessem no mesmo escritório.

---

## Comparativo

| Aspecto | Remote Access | Site-to-Site |
|---|---|---|
| Quem conecta | Usuário individual | Rede inteira |
| Onde configura | Dispositivo do usuário | Gateway/roteador |
| Persistência | Sessão por usuário | Túnel permanente |
| Autenticação | Por usuário (certificado, senha) | Por gateway (PSK ou certificado) |
| Escala | Centenas de usuários simultâneos | Poucas redes interligadas |

---

## VPN na nuvem — evolução

Provedores cloud (AWS, Azure, GCP) oferecem gateways VPN gerenciados:

- **AWS Site-to-Site VPN**: conecta data center on-premises à VPC na AWS.
- **AWS Client VPN**: acesso remoto de usuários à VPC.
- Alternativa moderna: **SD-WAN** substitui VPNs site-to-site tradicionais com mais inteligência de roteamento.

## 🧩 Quiz de Fixação

1. Em qual cenário você usaria Site-to-Site em vez de Remote Access?
2. Na VPN Site-to-Site, o usuário final precisa instalar um cliente VPN? Por quê?
3. Por que subnets sobrepostas são um problema em VPNs Site-to-Site?

**Respostas:**
1) Quando duas redes inteiras (ex.: duas filiais) precisam se comunicar de forma permanente e transparente para os usuários.
2) Não — o túnel é estabelecido entre gateways de rede; os usuários simplesmente acessam os recursos da outra rede como se fossem locais.
3) Se as duas redes usam o mesmo range (ex.: ambas 192.168.1.0/24), o roteador não sabe para qual rede enviar o pacote — causando conflito de roteamento.
