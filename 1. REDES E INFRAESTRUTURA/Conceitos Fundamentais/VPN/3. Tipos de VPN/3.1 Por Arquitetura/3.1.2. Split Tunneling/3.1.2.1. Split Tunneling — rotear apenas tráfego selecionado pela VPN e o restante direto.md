### Split Tunneling — roteamento seletivo de tráfego

Split tunneling permite que apenas parte do tráfego do usuário passe pela VPN, enquanto o restante vai diretamente pela internet. É o contraponto ao "full tunnel" (todo o tráfego pela VPN).

---

## Full Tunnel vs Split Tunnel

```
Full Tunnel (redirect-gateway):
  [Usuário] → TUDO ══VPN══► [Servidor VPN] → internet
  Incluindo: YouTube, Netflix, Google, sites externos

Split Tunnel:
  [Usuário] → Tráfego interno ══VPN══► [Rede corporativa]
            → Tráfego externo ──────► internet diretamente
```

---

## Como funciona tecnicamente

O cliente VPN instala **rotas específicas** na tabela de roteamento do SO:

```
# Full tunnel adiciona:
0.0.0.0/0 via VPN_GATEWAY   ← todo tráfego vai pela VPN

# Split tunnel adiciona apenas:
10.0.0.0/8 via VPN_GATEWAY  ← só redes internas vão pela VPN
192.168.100.0/24 via VPN_GATEWAY
# Todo o resto continua pela rota padrão (internet direta)
```

---

## Vantagens e desvantagens

| Aspecto | Split Tunnel | Full Tunnel |
|---|---|---|
| **Bandwidth corporativo** | Economiza — tráfego externo não passa pelo gateway | Consome — todo tráfego passa pelo gateway |
| **Latência** | Menor para sites externos | Maior para tudo |
| **Segurança** | Menor — tráfego externo não é inspecionado | Maior — todo tráfego pode ser filtrado |
| **Privacidade do usuário** | Mantém acesso direto à internet | Empresa vê todo o tráfego |
| **Complexidade** | Maior (precisa manter lista de rotas) | Menor |

---

## Riscos do split tunneling

**Hair-pinning attack / VPN split tunnel bypass:**
Se o dispositivo do usuário for comprometido por malware, o tráfego malicioso pode fluir pela internet diretamente — sem passar pelo firewall corporativo.

```
Dispositivo comprometido:
  Tráfego de trabalho ══VPN══► rede corporativa (protegido)
  Tráfego do malware  ──────► internet (sem inspeção)  ⚠️
```

Por isso, muitas políticas de segurança corporativa proibem split tunneling para dispositivos que acessam dados sensíveis.

---

## Split tunnel inverso (Inverse Split Tunnel)

Variação onde **tudo vai pela VPN, exceto** uma lista de exclusões (ex.: serviços de conferência de vídeo):

```
Todo tráfego ══VPN══► rede corporativa
EXCETO:
  Zoom/Teams/Meet ──────► internet direta (menor latência para chamadas)
```

## 🧩 Quiz de Fixação

1. Como o split tunneling é implementado tecnicamente no sistema operacional?
2. Por que empresas com requisitos de segurança rigorosos proibem split tunneling?
3. O que é split tunnel inverso e quando faz sentido usá-lo?

**Respostas:**
1) Instalando rotas específicas na tabela de roteamento: apenas os prefixos de rede interna são roteados pelo gateway VPN; o restante usa a rota padrão da internet.
2) O tráfego que não passa pela VPN não é inspecionado pelo firewall corporativo — dispositivos comprometidos podem vazar dados ou executar ataques sem detecção.
3) Todo o tráfego vai pela VPN exceto uma lista de exclusões. Faz sentido para aplicações sensíveis à latência como videoconferência, que degradam quando roteadas pelo gateway corporativo.
