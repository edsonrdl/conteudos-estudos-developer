### IPsec — modos, protocolos e negociação de chaves

IPsec (Internet Protocol Security) é um conjunto de protocolos que opera na camada de rede (Layer 3) para autenticar e cifrar pacotes IP. É a base de muitas VPNs corporativas e do padrão site-to-site.

---

## Os dois modos do IPsec

### Modo Transport

Cifra apenas o **payload** do pacote IP — o header original permanece intacto.

```
Original:  [IP Header | TCP Header | Dados]
Transport: [IP Header | ESP Header | TCP Header cifrado | Dados cifrados]
```

- Usado entre dois hosts que se comunicam diretamente.
- O endereço IP real dos hosts fica visível.

### Modo Tunnel

Encapsula o **pacote IP inteiro** (header + payload) dentro de um novo pacote.

```
Original:  [IP Header privado | TCP Header | Dados]
Tunnel:    [IP Header VPN | ESP Header | IP Header cifrado | TCP cifrado | Dados cifrados]
```

- Usado em VPNs site-to-site entre gateways.
- O IP original fica oculto — ideal para conectar redes privadas pela internet.

---

## Os dois sub-protocolos do IPsec

| Protocolo | Nome | Função |
|---|---|---|
| **AH** | Authentication Header | Autenticação e integridade — **sem criptografia** |
| **ESP** | Encapsulating Security Payload | Autenticação, integridade **e criptografia** |

Na prática, o ESP é quase sempre usado pois oferece criptografia. O AH sozinho é raro.

---

## IKE — Internet Key Exchange

Antes de cifrar dados, as duas partes precisam negociar as chaves. O IKE (atualmente IKEv2) faz isso em duas fases:

```
Fase 1 (IKE SA):
  - Estabelece canal seguro entre os peers
  - Autentica as partes (certificados, PSK ou EAP)
  - Negocia algoritmos (AES, SHA, DH group)

Fase 2 (Child SA / IPsec SA):
  - Negocia parâmetros específicos para o tráfego de dados
  - Deriva as chaves de sessão
  - Estabelece as Security Associations (SAs)
```

---

## Algoritmos típicos em implantações modernas

| Função | Algoritmo recomendado |
|---|---|
| Criptografia | AES-256 (GCM) |
| Integridade | SHA-256 / SHA-384 |
| Troca de chaves | DH Group 14+ (2048-bit) ou ECDH |
| Autenticação | Certificados X.509 ou PSK |

## 🧩 Quiz de Fixação

1. Qual a diferença entre o modo Tunnel e o modo Transport do IPsec?
2. Por que o ESP é preferido ao AH na maioria dos casos?
3. O que o IKE faz antes que o tráfego de dados comece a fluir?

**Respostas:**
1) Transport cifra apenas o payload, mantendo o IP original visível; Tunnel encapsula o pacote inteiro em um novo pacote, ocultando os IPs originais.
2) O ESP oferece criptografia além da autenticação/integridade, enquanto o AH só autentica sem cifrar os dados.
3) O IKE negocia algoritmos criptográficos, autentica as partes e deriva as chaves de sessão — estabelecendo as Security Associations (SAs) antes do tráfego de dados.
