### Criptografia e autenticação em VPNs

Uma VPN combina múltiplas camadas de criptografia e autenticação. Entender cada papel é essencial para avaliar a segurança de uma implementação.

---

## Os dois tipos de criptografia usados

### Criptografia Assimétrica — para troca de chaves

Usada no handshake inicial para que as partes troquem chaves sem nunca enviá-las em claro pela rede.

```
Cliente gera par de chaves (pública/privada)
Servidor gera par de chaves (pública/privada)

Troca: Diffie-Hellman (DH) ou ECDH
  - Cada lado usa a chave pública do outro + sua chave privada
  - Resultado: ambos chegam ao mesmo segredo compartilhado
  - Nenhum segredo trafegou pela rede
```

Algoritmos: RSA (legado), ECDH com Curve25519 (moderno).

### Criptografia Simétrica — para os dados

Após o handshake, os dados são cifrados com uma chave simétrica (mesma chave nos dois lados). É muito mais eficiente que a assimétrica para grandes volumes de dados.

```
AES-256-GCM:
  - AES-256: cifra os dados (256 bits de chave)
  - GCM: modo que autentica e cifra simultaneamente
  - Renegociação periódica (Perfect Forward Secrecy)
```

**Perfect Forward Secrecy (PFS):** novas chaves são derivadas periodicamente. Se uma chave de sessão for comprometida, sessões passadas e futuras permanecem seguras.

---

## Autenticação de identidade

| Método | Como funciona | Nível de segurança |
|---|---|---|
| **PSK (Pre-Shared Key)** | Senha/segredo configurado nos dois lados | Baixo a médio (segurança depende da senha) |
| **Certificados X.509** | CA assina certificados de cada peer | Alto |
| **Chaves públicas (WireGuard)** | Par de chaves por peer, sem CA | Alto |
| **EAP + MFA** | Usuário/senha + segundo fator (TOTP, push) | Muito alto |

---

## Autenticação Multifator (MFA) em VPNs

Para VPNs de acesso remoto corporativo, o padrão é combinar:

```
Algo que você TEM:   certificado no dispositivo
Algo que você SABE:  senha do usuário
Algo que você É:     TOTP (Google Authenticator) ou push (Duo, Okta)
```

Sem MFA, um certificado ou senha roubada dá acesso direto à rede interna.

---

## Algoritmos recomendados (2024+)

| Função | Recomendado | Evitar |
|---|---|---|
| Troca de chaves | ECDH Curve25519, DH 2048+ | DH 768/1024 |
| Cifra simétrica | AES-256-GCM, ChaCha20-Poly1305 | DES, 3DES, RC4 |
| Hash/MAC | SHA-256, SHA-384, BLAKE2 | MD5, SHA-1 |
| Autenticação | Certificados + MFA | PSK simples |

## 🧩 Quiz de Fixação

1. Por que a criptografia assimétrica é usada no handshake mas não para os dados em si?
2. O que é Perfect Forward Secrecy e por que é importante?
3. Um servidor VPN usa apenas PSK (pre-shared key) para autenticação. Qual o principal risco?

**Respostas:**
1) A criptografia assimétrica é computacionalmente cara — ideal para trocar chaves (pequenos dados), não para cifrar grandes volumes. A simétrica é muito mais eficiente para o tráfego contínuo.
2) É a prática de gerar novas chaves de sessão periodicamente. Se uma chave for comprometida, apenas a sessão corrente é afetada — sessões passadas e futuras permanecem seguras.
3) Se o PSK for descoberto (por força bruta, vazamento, ex-funcionário), qualquer pessoa que saiba o segredo pode autenticar — não há como revogar acesso individualmente sem trocar o PSK para todos.
