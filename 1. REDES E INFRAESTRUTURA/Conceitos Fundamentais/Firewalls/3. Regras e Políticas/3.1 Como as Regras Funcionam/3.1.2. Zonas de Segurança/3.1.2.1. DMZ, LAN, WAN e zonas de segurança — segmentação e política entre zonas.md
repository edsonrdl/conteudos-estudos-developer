### DMZ, LAN, WAN e zonas de segurança

Zonas de segurança são segmentos de rede com diferentes níveis de confiança. O firewall controla o tráfego entre elas, aplicando políticas distintas para cada par de zonas. É a base da segmentação de rede.

---

## As zonas fundamentais

```
Internet (WAN)          DMZ                    LAN (Interna)
[não confiável]    [semi-confiável]           [confiável]
      │                   │                        │
      │   ┌───────────────┤                        │
      └───┤   FIREWALL    ├────────────────────────┘
          └───────────────┘
                 │
          controla tráfego
          entre todas as zonas
```

### WAN (Wide Area Network)
- A internet — zona de menor confiança.
- Tráfego de entrada: presumido hostil até prova contrária.
- Política padrão: DENY ALL inbound.

### LAN (Local Area Network)
- Rede interna — zona de maior confiança.
- Usuários, estações de trabalho, sistemas internos.
- Política: permite saída para internet; protege contra entrada não solicitada.

### DMZ (Demilitarized Zone)
- Zona intermediária para servidores que precisam ser acessíveis pela internet.
- Servidores web, e-mail, DNS público, API gateways.
- Isolada da LAN — comprometimento da DMZ não dá acesso direto à rede interna.

---

## Política entre zonas

```
WAN → DMZ:    ALLOW apenas portas específicas (80, 443, 25...)
WAN → LAN:    DENY ALL (nada da internet acessa a rede interna diretamente)
DMZ → LAN:    DENY ALL (servidores DMZ não acessam sistemas internos)
LAN → DMZ:    ALLOW (admins acessam servidores)
LAN → WAN:    ALLOW com filtragem de saída
DMZ → WAN:    ALLOW restrito (ex: apenas para updates)
```

---

## Por que a DMZ é crítica

```
Sem DMZ (errado):
Internet → Servidor Web (na LAN) → se hackeado, atacante está na LAN

Com DMZ (correto):
Internet → Servidor Web (na DMZ) → se hackeado, atacante está na DMZ
                                    → firewall bloqueia acesso à LAN
```

O comprometimento de um servidor na DMZ não implica comprometimento da rede interna.

---

## Zonas adicionais em ambientes maiores

| Zona | Uso |
|---|---|
| **Management** | Acesso administrativo a dispositivos de rede — altamente restrita |
| **Guest** | Wi-Fi de visitantes — sem acesso à LAN |
| **OT/ICS** | Sistemas industriais (SCADA) — isolados de IT |
| **PCI** | Sistemas de pagamento — requisito de compliance |

## 🧩 Quiz de Fixação

1. Por que servidores web devem ficar na DMZ e não na LAN?
2. A política DMZ → LAN deve ser ALLOW ou DENY? Justifique.
3. Um atacante compromete o servidor web na DMZ. O que impede ele de atacar a LAN?

**Respostas:**
1) Servidores web precisam ser acessíveis da internet — se ficassem na LAN, seria necessário abrir a internet para a rede interna inteira, expondo todos os sistemas internos.
2) DENY ALL — servidores na DMZ são acessíveis pela internet e podem ser comprometidos; se pudessem acessar a LAN livremente, um servidor DMZ comprometido viraria ponto de entrada para a rede interna.
3) O firewall tem a regra DMZ → LAN: DENY ALL. O atacante está preso na DMZ — qualquer tentativa de conexão com sistemas da LAN é bloqueada pelo firewall.
