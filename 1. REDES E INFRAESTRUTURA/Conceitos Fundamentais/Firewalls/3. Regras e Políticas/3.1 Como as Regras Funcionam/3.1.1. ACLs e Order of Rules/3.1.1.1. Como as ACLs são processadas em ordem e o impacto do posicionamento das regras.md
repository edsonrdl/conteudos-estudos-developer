### ACLs e ordem de processamento das regras

A ordem das regras em um firewall não é detalhe — é fundamental. Um pacote é avaliado contra as regras em sequência e a **primeira regra que combinar** determina a ação. O posicionamento errado de uma regra pode abrir brechas ou bloquear tráfego legítimo.

---

## O modelo de processamento

```
Pacote chega
    │
    ▼
┌─────────────┐
│   Regra 1   │ ← combina? → executa ação → FIM
└──────┬──────┘
       │ não combina
       ▼
┌─────────────┐
│   Regra 2   │ ← combina? → executa ação → FIM
└──────┬──────┘
       │ não combina
       ▼
┌─────────────┐
│   Regra N   │
└──────┬──────┘
       │ nenhuma combinou
       ▼
  Regra padrão (default policy)
  └── Geralmente: DENY ALL
```

---

## Exemplo prático — ordem importa

```
# Configuração CORRETA:
Regra 1: ALLOW  TCP  192.168.1.100  →  any  :22   (admin SSH)
Regra 2: DENY   TCP  any            →  any  :22   (bloqueia SSH para todos)
Regra 3: ALLOW  TCP  any            →  any  :80   (permite HTTP)

# Configuração ERRADA (mesmas regras, ordem diferente):
Regra 1: DENY   TCP  any            →  any  :22   (bloqueia SSH para TODOS)
Regra 2: ALLOW  TCP  192.168.1.100  →  any  :22   (nunca alcançada! admin também bloqueado)
Regra 3: ALLOW  TCP  any            →  any  :80
```

A regra mais específica deve sempre vir **antes** da mais genérica.

---

## Default Deny vs Default Allow

| Política padrão | Comportamento | Uso recomendado |
|---|---|---|
| **Default Deny** | Bloqueia tudo que não foi explicitamente permitido | Ambientes de produção (mais seguro) |
| **Default Allow** | Permite tudo que não foi explicitamente bloqueado | Raramente usado (inseguro) |

O princípio de **menor privilégio** diz: só permita o que é estritamente necessário.

---

## Boas práticas de organização de regras

```
1. Regras de bloqueio de emergência (blacklist)
2. Regras específicas de permissão (hosts/serviços conhecidos)
3. Regras gerais de serviço
4. Regras de logging (para auditoria)
5. Default Deny (última regra — bloqueia tudo não coberto)
```

---

## Shadowing — regras nunca alcançadas

Quando uma regra mais ampla vem antes de uma mais específica, a específica fica "sombreada":

```
Regra 1: ALLOW  TCP  any  →  any  :80   ← abrange tudo
Regra 2: DENY   TCP  any  →  any  :80   ← nunca será alcançada (shadowed)
```

Ferramentas de análise de firewall detectam shadowing automaticamente.

---

## 🧩 Quiz de Fixação

1. Um administrador quer bloquear SSH para todos exceto seu IP. Qual a ordem correta das regras?
2. O que é shadowing em firewall rules e por que é um problema?
3. Por que Default Deny é mais seguro que Default Allow?

**Respostas:**
1) Primeiro: `ALLOW TCP [meu-IP] → any :22`; Segundo: `DENY TCP any → any :22`. A regra específica (meu IP) deve vir antes da genérica (todos).
2) Shadowing ocorre quando uma regra mais geral vem antes de uma mais específica, tornando a específica inalcançável — o tráfego é tratado pela regra geral e a intenção da regra específica é ignorada.
3) Default Deny garante que qualquer tráfego não explicitamente autorizado seja bloqueado — novos serviços/portas precisam ser conscientemente liberados. Default Allow expõe tudo por padrão e depende de bloquear cada ameaça individualmente.
