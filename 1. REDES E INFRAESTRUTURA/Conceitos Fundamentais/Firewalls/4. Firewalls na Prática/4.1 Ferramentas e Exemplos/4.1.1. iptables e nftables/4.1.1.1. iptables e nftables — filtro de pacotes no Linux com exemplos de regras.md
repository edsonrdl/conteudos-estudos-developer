### iptables e nftables — firewall no Linux

iptables é o firewall nativo do Linux há décadas. O nftables é seu sucessor moderno. Ambos controlam o tráfego de rede diretamente no kernel via Netfilter.

---

## Estrutura do iptables — Tabelas e Chains

```
Tabela FILTER (mais usada):
  ├── INPUT    → pacotes destinados ao próprio host
  ├── OUTPUT   → pacotes originados do próprio host
  └── FORWARD  → pacotes roteados pelo host (ex: gateway)

Tabela NAT:
  ├── PREROUTING  → antes do roteamento (DNAT, port forwarding)
  └── POSTROUTING → após o roteamento (SNAT, masquerade)
```

---

## Comandos essenciais

```bash
# Ver regras atuais
iptables -L -n -v --line-numbers

# Política padrão — DROP tudo
iptables -P INPUT DROP
iptables -P FORWARD DROP
iptables -P OUTPUT ACCEPT

# Permitir loopback
iptables -A INPUT -i lo -j ACCEPT

# Permitir conexões estabelecidas (stateful)
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# Permitir SSH apenas de IP específico
iptables -A INPUT -p tcp -s 203.0.113.10 --dport 22 -j ACCEPT

# Permitir HTTP e HTTPS
iptables -A INPUT -p tcp --dport 80 -j ACCEPT
iptables -A INPUT -p tcp --dport 443 -j ACCEPT

# Bloquear IP específico
iptables -A INPUT -s 198.51.100.0/24 -j DROP

# Salvar regras (Debian/Ubuntu)
iptables-save > /etc/iptables/rules.v4
```

## nftables — o sucessor moderno

Mais limpo, mais eficiente, sintaxe unificada para IPv4 e IPv6:

```bash
# Criar tabela e chains
nft add table inet filter
nft add chain inet filter input { type filter hook input priority 0 \; policy drop \; }
nft add chain inet filter output { type filter hook output priority 0 \; policy accept \; }

# Permitir established/related
nft add rule inet filter input ct state established,related accept

# Permitir SSH, HTTP, HTTPS
nft add rule inet filter input tcp dport { 22, 80, 443 } accept

# Ver regras
nft list ruleset
```

---

## iptables vs nftables

| Aspecto | iptables | nftables |
|---|---|---|
| Status | Legado (mantido) | Moderno (recomendado) |
| IPv4/IPv6 | Separados (ip6tables) | Unificado (inet) |
| Performance | Boa | Melhor (JIT compiler) |
| Sintaxe | Verbosa | Mais limpa |
| Distros modernas | Geralmente usa nftables internamente |  |

## 🧩 Quiz de Fixação

1. Qual a diferença entre as chains INPUT, OUTPUT e FORWARD no iptables?
2. Por que a regra `ESTABLISHED,RELATED` é importante em um firewall Linux stateful?
3. Por que o nftables é considerado superior ao iptables para novas implementações?

**Respostas:**
1) INPUT: pacotes chegando ao próprio host. OUTPUT: pacotes saindo do próprio host. FORWARD: pacotes passando pelo host como roteador (ex: gateway de rede).
2) Permite que respostas a conexões iniciadas pelo host passem — sem ela, o host faria requests mas bloquearia as respostas (internet inacessível mesmo com OUTPUT liberado).
3) Sintaxe mais limpa, suporte unificado a IPv4/IPv6, melhor performance com JIT compiler, e foi projetado para substituir iptables, ip6tables, arptables e ebtables em uma única ferramenta.
