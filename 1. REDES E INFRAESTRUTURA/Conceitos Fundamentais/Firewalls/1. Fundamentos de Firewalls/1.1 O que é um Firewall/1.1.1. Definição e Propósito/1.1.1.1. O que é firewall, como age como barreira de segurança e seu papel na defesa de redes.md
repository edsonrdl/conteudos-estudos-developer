### O que é firewall e seu papel na defesa de redes

Um firewall é um sistema de segurança que monitora e controla o tráfego de rede com base em regras predefinidas. Age como uma barreira entre redes confiáveis (rede interna) e não confiáveis (internet), decidindo o que pode passar e o que deve ser bloqueado.

---

## A analogia do porteiro

```
Internet (não confiável)
        │
   [ FIREWALL ]  ← porteiro que verifica cada pacote
        │
 Rede interna (confiável)
 ├── Servidores
 ├── Estações de trabalho
 └── Banco de dados
```

Assim como um porteiro verifica quem entra em um prédio, o firewall verifica cada pacote de rede — decidindo se permite, bloqueia ou registra.

---

## O que o firewall analisa

Dependendo do tipo (veremos nos próximos tópicos), um firewall pode inspecionar:

| Nível | O que analisa | Exemplo |
|---|---|---|
| Pacote (L3/L4) | IP origem/destino, porta, protocolo | Bloqueia TCP porta 23 (Telnet) |
| Estado (L4) | Se a conexão foi iniciada internamente | Permite resposta de conexão estabelecida |
| Aplicação (L7) | Conteúdo do protocolo | Bloqueia upload de arquivos no HTTP |

---

## Ações possíveis para cada regra

| Ação | Comportamento |
|---|---|
| **ALLOW / ACCEPT** | Pacote passa |
| **DENY / DROP** | Pacote descartado silenciosamente |
| **REJECT** | Pacote bloqueado + notificação enviada ao remetente |
| **LOG** | Registra o pacote (geralmente combinado com outra ação) |

A diferença entre DROP e REJECT é importante: DROP não avisa o remetente (mais seguro — não revela que o host existe), REJECT envia um erro ICMP (mais útil para diagnóstico interno).

---

## O que o firewall não é

- **Não é antivírus** — não detecta malware dentro de conexões permitidas.
- **Não é IDS/IPS** — não detecta padrões de ataque por padrão (NGFWs adicionam isso).
- **Não resolve problemas de aplicação** — uma aplicação mal codificada continua vulnerável mesmo atrás de um firewall.
- **Não é substituto de criptografia** — permite tráfego, mas não garante que ele seja seguro.

---

## 🧩 Quiz de Fixação

1. Qual a diferença entre as ações DROP e REJECT em um firewall?
2. Um firewall que analisa apenas IP e porta consegue bloquear um ataque dentro de uma conexão HTTP permitida?
3. Por que um servidor web público ainda precisa de firewall se já usa HTTPS?

**Respostas:**
1) DROP descarta o pacote silenciosamente sem notificar o remetente; REJECT descarta e envia um erro ICMP — DROP é preferido em bordas externas para não revelar a existência do host.
2) Não — inspeção de pacote simples não analisa o conteúdo da aplicação; um ataque embutido em HTTP válido passa despercebido.
3) HTTPS criptografa o canal mas não controla quais portas/serviços ficam expostos — o firewall limita a superfície de ataque bloqueando tudo exceto o necessário.
