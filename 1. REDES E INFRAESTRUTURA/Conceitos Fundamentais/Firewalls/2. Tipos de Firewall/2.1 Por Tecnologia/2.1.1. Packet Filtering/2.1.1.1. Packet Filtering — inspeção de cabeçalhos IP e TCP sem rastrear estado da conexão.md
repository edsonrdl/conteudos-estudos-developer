### Packet Filtering — inspeção de cabeçalhos sem estado

O packet filtering é a forma mais básica de firewall. Analisa cada pacote de forma independente, tomando decisões com base apenas nos campos do cabeçalho IP e TCP/UDP — sem memória de conexões anteriores.

---

## O que é inspecionado

```
Cabeçalho IP:
  ├── IP de origem
  ├── IP de destino
  └── Protocolo (TCP, UDP, ICMP)

Cabeçalho TCP/UDP:
  ├── Porta de origem
  └── Porta de destino
```

Cada pacote é avaliado isoladamente contra uma lista de regras (ACL).

---

## Exemplo de regras (ACL)

```
# Formato: ação  protocolo  origem          destino         porta
ALLOW       TCP    any         192.168.1.0/24   80     ← permite HTTP para rede interna
ALLOW       TCP    any         192.168.1.0/24   443    ← permite HTTPS
DENY        TCP    any         any              23     ← bloqueia Telnet
DENY        any    any         any              any    ← bloqueia tudo mais (default deny)
```

---

## Vantagens

- **Velocidade:** processamento mínimo — apenas lê cabeçalhos.
- **Simplicidade:** fácil de entender e implementar.
- **Baixo custo de hardware:** sem estado para manter em memória.

---

## Limitações críticas

| Limitação | Detalhe |
|---|---|
| **Sem estado** | Não sabe se o pacote faz parte de uma conexão legítima |
| **IP Spoofing** | Não valida se o IP de origem é real |
| **Fragmentação** | Pacotes fragmentados podem burlar regras de porta |
| **Sem visibilidade L7** | Não entende o conteúdo — SQL injection em HTTP passa |
| **Regras bidirecionais** | Para cada serviço, precisa de regra de ida e volta explícita |

### O problema do tráfego de retorno

```
Sem estado:
  Saída: ALLOW TCP 192.168.1.10:1234 → 8.8.8.8:80  ✓
  Retorno: 8.8.8.8:80 → 192.168.1.10:1234  ← precisa de regra explícita
           Se não tiver: BLOQUEADO
```

Isso leva à gambiarra de liberar todas as portas altas (>1024) de volta — criando brecha de segurança.

---

## Onde ainda é usado hoje

- Roteadores de borda como primeira linha de filtragem simples.
- Security Groups básicos em nuvem.
- Complemento a firewalls mais sofisticados (pré-filtragem rápida).

---

## 🧩 Quiz de Fixação

1. Por que o packet filtering precisa de regras explícitas para tráfego de retorno?
2. O que é IP spoofing e por que o packet filtering não consegue defendê-lo?
3. Um atacante envia um pacote TCP com porta de destino 80 mas com payload de ataque SQL injection. O packet filter bloqueia?

**Respostas:**
1) Por não ter estado, cada pacote é avaliado independentemente — o firewall não sabe que o pacote de retorno faz parte de uma conexão iniciada internamente.
2) IP spoofing é forjar o endereço IP de origem; o packet filter só lê o campo do cabeçalho sem verificar se o IP é genuíno.
3) Não — o packet filter só verifica a porta (80 está permitido); o conteúdo do payload não é inspecionado.
