### Firewall de camada de aplicação — inspeção profunda e proxy

O firewall de camada de aplicação (Layer 7) entende os protocolos de aplicação — HTTP, DNS, SMTP, FTP — e pode tomar decisões baseadas no conteúdo real da comunicação, não apenas nos cabeçalhos.

---

## Como funciona o proxy de firewall

Em vez de deixar o tráfego passar diretamente, o firewall age como intermediário (proxy):

```
Sem proxy:
  Cliente ──────────────────────────► Servidor

Com proxy (Application Firewall):
  Cliente ──► [FIREWALL/PROXY] ──► Servidor
               ↑
    Termina a conexão do cliente,
    inspeciona o conteúdo,
    abre nova conexão com o servidor
```

Isso permite inspeção completa do conteúdo antes de qualquer byte chegar ao destino.

---

## O que pode ser inspecionado e controlado

| Protocolo | O que o firewall de aplicação pode fazer |
|---|---|
| **HTTP/HTTPS** | Bloquear URLs específicas, tipos de arquivo, métodos (PUT, DELETE) |
| **DNS** | Bloquear domínios maliciosos, prevenir DNS tunneling |
| **SMTP** | Filtrar anexos, bloquear spam, verificar SPF/DKIM |
| **FTP** | Controlar comandos (ex: bloquear PUT mas permitir GET) |
| **SQL** | Detectar padrões de SQL injection nas requisições |

---

## WAF — Web Application Firewall

Um caso especial de firewall de aplicação focado em HTTP/HTTPS:

```
Internet → [WAF] → Servidor Web

O WAF inspeciona:
  ├── Headers HTTP suspeitos
  ├── Parâmetros de URL (ex: ?id=1 OR 1=1)
  ├── Corpo da requisição (SQL injection, XSS)
  └── Padrões de ataque conhecidos (OWASP Top 10)
```

Exemplos: AWS WAF, Cloudflare WAF, ModSecurity.

---

## SSL Inspection (HTTPS Inspection)

Para inspecionar tráfego HTTPS, o firewall precisa fazer **man-in-the-middle legítimo**:

```
Cliente → [Firewall decifra com cert próprio] → [Firewall re-cifra] → Servidor
           ↑
    Firewall tem CA interna confiável pelo cliente
    Clientes precisam ter o cert do firewall instalado
```

Controverso do ponto de vista de privacidade, mas necessário para inspecionar tráfego cifrado em ambientes corporativos.

---

## Trade-off: segurança vs performance

| Aspecto | Packet Filtering | Stateful | Application Layer |
|---|---|---|---|
| Visibilidade | Cabeçalho | Conexão | Conteúdo completo |
| Performance | Altíssima | Alta | Moderada |
| Latência adicionada | Mínima | Baixa | Perceptível |
| Complexidade | Baixa | Média | Alta |

## 🧩 Quiz de Fixação

1. Por que o firewall de aplicação consegue detectar SQL injection e o stateful não?
2. O que é SSL Inspection e por que gera controvérsia?
3. Qual a diferença entre um firewall de aplicação genérico e um WAF?

**Respostas:**
1) O stateful só verifica se a conexão é legítima (estado); o de aplicação lê o conteúdo dos pacotes e entende o protocolo HTTP — conseguindo identificar padrões maliciosos no payload.
2) É quando o firewall decifra o HTTPS, inspeciona o conteúdo e re-cifra antes de enviar ao servidor — gera controvérsia porque a empresa vê todo o tráfego "privado" dos usuários, incluindo senhas e dados pessoais.
3) O de aplicação genérico cobre múltiplos protocolos (HTTP, DNS, SMTP); o WAF é especializado em HTTP/HTTPS com regras específicas para ataques web (OWASP Top 10, SQL injection, XSS).
