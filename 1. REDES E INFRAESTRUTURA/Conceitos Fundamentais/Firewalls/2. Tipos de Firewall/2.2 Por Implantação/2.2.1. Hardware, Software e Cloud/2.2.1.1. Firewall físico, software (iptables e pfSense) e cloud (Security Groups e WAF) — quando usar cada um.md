### Firewall físico, software e cloud — quando usar cada um

Além da tecnologia de inspeção, os firewalls diferem em como são implantados. Cada forma de implantação tem casos de uso, vantagens e limitações distintos.

---

## Firewall de Hardware (Appliance)

Dispositivo físico dedicado, otimizado para processar tráfego de rede em alta velocidade.

```
Internet ──► [Appliance Firewall] ──► Switch ──► Rede interna
             (Fortinet, Palo Alto,
              Cisco, Check Point)
```

**Vantagens:**
- Hardware especializado (ASICs) para throughput muito alto.
- Solução all-in-one — firewall, VPN, IPS em um dispositivo.
- Independente do SO dos servidores internos.

**Quando usar:** data centers, filiais, bordas corporativas com alto volume de tráfego.

---

## Firewall de Software

Executado como processo no SO, sem hardware dedicado.

### iptables / nftables (Linux)

```bash
# Bloquear porta 23 (Telnet)
iptables -A INPUT -p tcp --dport 23 -j DROP

# Permitir SSH apenas de IP específico
iptables -A INPUT -p tcp -s 192.168.1.100 --dport 22 -j ACCEPT
iptables -A INPUT -p tcp --dport 22 -j DROP
```

- Nativo no Linux — sem custo adicional.
- Controle granular mas configuração manual.
- `nftables` é o sucessor moderno do iptables.

### pfSense / OPNsense

- Distribuições BSD dedicadas a firewall/roteador.
- Interface web completa sobre as mesmas capacidades do packet filter.
- Muito usado em pequenas/médias empresas como alternativa ao hardware caro.

**Quando usar:** servidores Linux (host firewall), laboratórios, PMEs com orçamento limitado.

## Firewall em Nuvem

### Security Groups (AWS) / NSGs (Azure)

Firewall stateful gerenciado pelo provedor cloud, associado a instâncias ou subnets:

```
Internet
    │
[Security Group]  ← regras inbound/outbound por porta, protocolo, CIDR
    │
EC2 Instance / VM
```

```
# Exemplo de regra Security Group AWS:
Tipo: SSH | Protocolo: TCP | Porta: 22 | Origem: 203.0.113.0/32
Tipo: HTTPS | Protocolo: TCP | Porta: 443 | Origem: 0.0.0.0/0
```

**Características:**
- Stateful por padrão (retorno automático).
- Regras aplicadas por recurso, não por topologia de rede.
- Default deny — nada entra sem regra explícita.

### WAF em Nuvem (AWS WAF, Cloudflare)

- Protege aplicações web contra ataques L7.
- Gerenciado — sem infraestrutura para manter.
- Regras gerenciadas pelos provedores (OWASP, threat intel automático).

---

## Quando usar cada um

| Cenário | Solução recomendada |
|---|---|
| Data center on-premises | Appliance NGFW |
| Servidor Linux (proteção do host) | iptables / nftables |
| Pequena empresa sem budget | pfSense / OPNsense |
| Infraestrutura AWS/Azure/GCP | Security Groups + WAF cloud |
| Aplicação web pública | WAF (Cloudflare, AWS WAF) |
| Defesa em profundidade | Todos em camadas |

## 🧩 Quiz de Fixação

1. Qual a principal vantagem de um firewall hardware sobre software em ambientes de alto tráfego?
2. Por que Security Groups são stateful mas não precisam de regra explícita de retorno?
3. O que é defesa em profundidade no contexto de firewalls?

**Respostas:**
1) Hardware especializado (ASICs) processa pacotes muito mais rapidamente que software em CPU de propósito geral — consegue inspecionar Gbps de tráfego sem degradação.
2) Porque o provedor cloud implementa o rastreamento de estado internamente — qualquer resposta a uma conexão iniciada por uma regra permitida é automaticamente autorizada.
3) Usar múltiplas camadas de firewall (ex: Security Group na instância + WAF na borda + NGFW no data center) — se uma camada falhar, as outras ainda protegem.
