### TLS — Transport Layer Security

O TLS é o protocolo que criptografa o tráfego na Internet. É o que transforma HTTP em HTTPS, SMTP em SMTPS, e protege praticamente qualquer comunicação sensível. SSL era o nome antigo — está obsoleto desde 2015, mas o termo ainda é usado coloquialmente.

---

## O que o TLS garante

| Propriedade | O que significa | Como |
|-------------|----------------|------|
| **Confidencialidade** | Dados ilegíveis para terceiros | Criptografia simétrica (AES) |
| **Integridade** | Qualquer alteração é detectada | HMAC / AEAD |
| **Autenticação** | Servidor é quem diz ser | Certificados digitais X.509 |

---

## O Handshake TLS 1.3

O TLS 1.3 (atual) reduz o handshake para 1 round-trip (vs 2 no TLS 1.2):

```
Cliente                              Servidor
  │                                     │
  │── ClientHello ──────────────────>  │
  │   (versões suportadas, cipher suites,│
  │    chave pública efêmera)           │
  │                                     │
  │<── ServerHello ─────────────────── │
  │    (cipher escolhido, chave pública,│
  │     certificado, Finished)          │
  │                                     │
  │── Finished ──────────────────────> │
  │                                     │
  │<══ Dados criptografados ══════════>│
```

**1-RTT**: depois do ClientHello, o servidor já pode responder com dados criptografados. O cliente confirma e a comunicação está estabelecida em 1 round-trip.

**0-RTT** (sessões retomadas): se cliente e servidor já se comunicaram antes, o cliente pode enviar dados já no primeiro pacote, usando a chave de sessão anterior.

## Certificados Digitais e PKI

Um certificado digital responde: "como confio que este servidor é realmente google.com?"

```
Hierarquia de confiança (PKI):
  Root CA (embutida no seu OS/browser)
    └── Intermediate CA
          └── Certificado do domínio (google.com)
                └── Assinado pela Intermediate CA
```

**Como funciona:**
1. `google.com` gera um par de chaves (pública + privada)
2. Envia a chave pública + dados do domínio para uma CA (Certificate Authority)
3. A CA verifica que você controla o domínio e assina o certificado com a chave dela
4. Seu browser tem a Root CA pré-instalada → confia na cadeia toda

**CAs conhecidas:** Let's Encrypt (gratuita e automatizada), DigiCert, Sectigo

---

## Tipos de certificado

| Tipo | Validação | Caso de uso |
|------|-----------|-------------|
| **DV** (Domain Validated) | Só verifica controle do domínio | Sites em geral, APIs (Let's Encrypt) |
| **OV** (Organization Validated) | Verifica empresa | Sites corporativos |
| **EV** (Extended Validation) | Validação rigorosa da empresa | Bancos (barra verde, hoje pouco usada) |
| **Wildcard** (`*.exemplo.com`) | Cobre todos os subdomínios | Quando há múltiplos subdomínios |

## 🧩 Quiz de Fixação

1. Qual a diferença entre TLS e SSL?
2. O que uma CA valida antes de emitir um certificado DV?
3. Por que o TLS 1.3 é mais rápido que o TLS 1.2?

**Respostas:**
1) SSL é o predecessor obsoleto do TLS (SSLv3 foi descontinuado em 2015 por vulnerabilidades). TLS é o protocolo atual. Coloquialmente "SSL" ainda é usado, mas tecnicamente o correto é TLS.
2) Para DV, a CA valida apenas que o solicitante controla o domínio — geralmente via um arquivo HTTP específico no servidor ou registro DNS. Não valida identidade da empresa.
3) TLS 1.3 reduz o handshake de 2 para 1 round-trip e remove cipher suites fracas. Também suporta 0-RTT para sessões retomadas.
