### Ameaças à Infraestrutura da Internet

A Internet foi projetada para resiliência, não segurança. Três categorias de ataques exploram fraquezas fundamentais de seus protocolos: disponibilidade (DDoS), roteamento (BGP hijacking) e resolução de nomes (DNS spoofing).

---

## DDoS — Distributed Denial of Service

Um ataque DDoS tenta tornar um serviço indisponível sobrecarregando-o com tráfego de múltiplas origens simultâneas.

```
Atacante controla botnet (milhares de dispositivos comprometidos)
  ↓
Todos enviam requisições simultâneas para o alvo
  ↓
Alvo fica sem recursos (banda, CPU, conexões) e para de responder
```

**Tipos principais:**

| Tipo | Alvo | Exemplo |
|------|------|---------|
| **Volumétrico** | Saturar a banda | UDP flood, ICMP flood, amplificação DNS |
| **Protocol** | Exaurir recursos do servidor | SYN flood (tabela de conexões TCP) |
| **Aplicação (L7)** | Exaurir CPU/memória | HTTP flood, Slowloris |

**Amplificação DNS** — ataque volumétrico poderoso:
```
Atacante envia consultas DNS com IP de origem falsificado (IP da vítima)
Servidores DNS respondem para a vítima (resposta >> requisição)
Fator de amplificação: 50x–100x
```

**Mitigação:**
- **Anycast**: distribuir o tráfego por centenas de PoPs (Cloudflare, Akamai)
- **Rate limiting**: bloquear IPs com volume anormal
- **BGP blackholing**: ISP descarta todo o tráfego para o IP atacado (sacrifica o alvo para proteger a rede)
- **Scrubbing centers**: limpam o tráfego antes de entregar ao cliente

## BGP Hijacking

Como o BGP confia em anúncios sem verificação, qualquer AS pode anunciar prefixos que não lhe pertencem.

```
Situação normal:
  AS15169 (Google) anuncia: 8.8.8.8/32 → seu tráfego vai ao Google DNS

Ataque:
  AS malicioso anuncia: 8.8.8.8/32 (prefixo mais específico vence)
  → tráfego redirecionado para o AS atacante
  → man-in-the-middle, roubo de tráfego, espionagem
```

**Casos reais:** Pakistan Telecom derrubou YouTube globalmente em 2008. Hackers russos redirecionaram tráfego de bancos em 2018.

**Mitigação:**
- **RPKI** (Resource Public Key Infrastructure): certifica criptograficamente que um AS tem autorização para anunciar determinado prefixo
- **BGPsec**: extensão do BGP que assina a cadeia de ASes — ainda em adoção lenta

## DNS Spoofing / Cache Poisoning

O atacante injeta respostas DNS falsas no cache de um resolver, fazendo usuários chegarem a servidores maliciosos.

```
Ataque de cache poisoning (Kaminsky, 2008):
  Atacante envia milhares de respostas DNS falsas para o resolver
  Com IDs de transação corretos (adivinhados por força bruta)
  Resolver aceita a primeira resposta válida → cache envenenado
  Todos os usuários daquele resolver vão para o IP falso
```

**Mitigação:**
- **DNSSEC**: assina criptograficamente as respostas DNS — resolver valida a assinatura e rejeita respostas não autorizadas
- **DNS over HTTPS (DoH)** / **DNS over TLS (DoT)**: criptografam a consulta DNS, impedindo interceptação e modificação pelo ISP ou atacante de rede

## 🧩 Quiz de Fixação

1. Por que ataques de amplificação DNS são eficientes para DDoS volumétrico?
2. O que é RPKI e qual ataque ele previne?
3. Qual a diferença entre DNS spoofing e DNS poisoning?

**Respostas:**
1) O atacante envia uma requisição DNS pequena com IP de origem falsificado (IP da vítima), e os servidores DNS respondem com pacotes muito maiores (50–100x) para a vítima — amplificando o dano com pouco esforço.
2) RPKI é uma infraestrutura de chave pública que certifica quais ASes têm autorização para anunciar quais blocos de IPs. Previne BGP hijacking ao permitir que roteadores rejeitem anúncios de prefixos não autorizados.
3) São frequentemente usados como sinônimos. DNS spoofing é o conceito geral de fornecer respostas DNS falsas; DNS cache poisoning é a técnica específica de injetar essas respostas falsas no cache de um resolver recursivo.
