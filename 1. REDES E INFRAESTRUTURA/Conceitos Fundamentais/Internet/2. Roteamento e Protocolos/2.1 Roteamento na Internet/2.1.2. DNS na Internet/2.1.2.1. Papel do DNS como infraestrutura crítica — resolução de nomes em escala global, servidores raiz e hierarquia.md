### DNS como Infraestrutura Crítica da Internet

O DNS (Domain Name System) é o sistema que traduz nomes legíveis (`google.com`) em endereços IP (`142.250.79.14`). Sem o DNS, a Internet continuaria funcionando tecnicamente, mas seria inutilizável na prática — ninguém memoriza endereços IP.

---

## A hierarquia DNS

O DNS é uma árvore distribuída de autoridade, com três níveis principais:

```
                        . (root)
                        │
        ┌───────────────┼───────────────┐
       .com            .org            .br
        │                               │
    google.com                       uol.com.br
        │
    www.google.com
```

| Nível | Quem gerencia | Exemplo |
|-------|--------------|---------|
| **Root (.)** | 13 clusters de servidores raiz (operados por ICANN, NASA, Verisign e outros) | `.` |
| **TLD** (Top-Level Domain) | Registries especializados | `.com` (Verisign), `.br` (NIC.br) |
| **Domínio** | Quem registrou o domínio | `google.com` → Google |
| **Subdomínio** | Dono do domínio | `mail.google.com` → Google |

---

## Como funciona uma resolução

```
Você digita: www.google.com

1. Sistema operacional verifica o cache local
2. Pergunta ao resolver do ISP (ou 8.8.8.8, 1.1.1.1)
3. Resolver pergunta ao servidor raiz: "quem cuida de .com?"
   → Raiz responde: "pergunte ao servidor TLD do .com"
4. Resolver pergunta ao TLD .com: "quem cuida de google.com?"
   → TLD responde: "pergunte aos nameservers do Google"
5. Resolver pergunta ao nameserver do Google: "qual o IP de www.google.com?"
   → Google responde: "142.250.79.14"
6. Resolver retorna o IP ao seu sistema operacional
   → Resultado fica em cache pelo TTL configurado
```

Esse processo leva geralmente 20–100ms na primeira consulta. Depois, fica em cache.

## Os 13 servidores raiz

Há exatamente **13 endereços IP de servidores raiz** (A a M), mas cada um é um **cluster anycast** com centenas de instâncias físicas distribuídas pelo mundo:

```
a.root-servers.net — Verisign
b.root-servers.net — USC-ISI
c.root-servers.net — Cogent Communications
...
m.root-servers.net — WIDE Project (Japão)
```

O número 13 é uma limitação histórica do UDP (os 13 endereços cabiam em uma resposta DNS de 512 bytes). Com anycast, há hoje mais de 1.700 instâncias físicas espalhadas pelo mundo.

---

## Por que o DNS é infraestrutura crítica

- **Derrubando o DNS, derruba-se a Internet funcional** — ataques DDoS contra servidores DNS afetam milhões de sites (ex: ataque ao Dyn em 2016 derrubou Twitter, Netflix, Spotify)
- **DNS spoofing/poisoning** — atacante injeta resposta falsa no cache do resolver, redirecionando usuários para sites maliciosos
- **DNSSEC** — extensão que assina criptograficamente as respostas DNS para prevenir poisoning
- **DNS over HTTPS (DoH) / DNS over TLS (DoT)** — criptografam a consulta DNS para impedir espionagem pelo ISP

## 🧩 Quiz de Fixação

1. Qual a diferença entre um servidor DNS raiz e um servidor DNS autoritativo?
2. O que é TTL no contexto DNS e qual seu impacto prático?
3. O que é DNS poisoning e como o DNSSEC mitiga esse ataque?

**Respostas:**
1) Servidor raiz responde sobre *quem é autoridade* para cada TLD — não conhece IPs de domínios específicos. Servidor autoritativo é o final da cadeia — conhece os registros reais do domínio (IP, MX, etc.).
2) TTL (Time to Live) define por quantos segundos o resultado pode ser cacheado. TTL baixo = consultas mais frequentes (mais atualizado, mais lento). TTL alto = menos consultas (mais rápido, mudanças demoram a propagar).
3) DNS poisoning injeta respostas falsas no cache de um resolver, fazendo usuários irem para IPs maliciosos. DNSSEC assina criptograficamente cada resposta DNS com a chave do dono do domínio — o resolver valida a assinatura e rejeita respostas não autorizadas.
