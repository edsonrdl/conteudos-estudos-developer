### BGP — Border Gateway Protocol

O BGP é o protocolo que faz a Internet funcionar como uma rede unificada. Enquanto protocolos como OSPF gerenciam rotas *dentro* de uma rede, o BGP gerencia rotas *entre* as redes independentes dos diferentes ISPs e organizações.

---

## Sistemas Autônomos (AS)

A Internet é composta por **Sistemas Autônomos** — redes independentes, cada uma com seu próprio conjunto de políticas de roteamento e blocos de endereços IP.

```
Exemplos de Sistemas Autônomos:
  AS7162  — Embratel (Brasil)
  AS15169 — Google
  AS16509 — Amazon AWS
  AS32934 — Meta (Facebook)
  AS13335 — Cloudflare
```

Cada AS recebe um **número de AS (ASN)** único, atribuído por RIRs (ex: LACNIC para América Latina). O BGP é o protocolo que os ASes usam para trocar informações de roteamento entre si.

---

## Como o BGP funciona

```
AS-A ──── BGP session ──── AS-B ──── BGP session ──── AS-C

AS-A anuncia: "Eu alcanço o bloco 203.0.113.0/24"
AS-B aprende isso e re-anuncia para AS-C
AS-C agora sabe: para chegar em 203.0.113.0/24, vá via AS-B → AS-A
```

O BGP **não usa métricas simples como distância ou banda** — usa atributos de política:

| Atributo | Significado |
|----------|-------------|
| `AS_PATH` | Lista de ASes que o anúncio percorreu (evita loops) |
| `NEXT_HOP` | Próximo roteador no caminho |
| `LOCAL_PREF` | Preferência interna (qual saída usar quando há múltiplas) |
| `MED` | Preferência sugerida ao AS vizinho sobre qual entrada usar |
| `COMMUNITY` | Tags personalizadas para políticas (ex: "não re-anuncie este prefixo") |

---

## BGP iBGP vs eBGP

| Tipo | Entre quem | Uso |
|------|-----------|-----|
| **eBGP** (External BGP) | ASes diferentes | Troca de rotas entre ISPs — é o BGP "da Internet" |
| **iBGP** (Internal BGP) | Roteadores do mesmo AS | Distribuição interna das rotas aprendidas externamente |

---

## BGP Hijacking

Como o BGP funciona por confiança (qualquer AS pode anunciar qualquer prefixo), **BGP hijacking** ocorre quando um AS anuncia prefixos que não são seus, redirecionando tráfego:

```
Ataque:
  AS malicioso anuncia: "Eu alcanço 8.8.8.8/32 (Google DNS)"
  Roteadores ao redor aceitam — prefixo mais específico vence
  Tráfego destinado ao Google DNS vai para o AS atacante
```

**Mitigação:** RPKI (Resource Public Key Infrastructure) — permite validar criptograficamente que um AS tem autorização para anunciar determinado bloco IP.

## 🧩 Quiz de Fixação

1. O que é um Sistema Autônomo (AS)?
2. Qual atributo do BGP impede loops de roteamento?
3. O que é BGP hijacking e como o RPKI ajuda a mitigá-lo?

**Respostas:**
1) Uma rede ou conjunto de redes sob controle administrativo comum, identificada por um ASN único, que usa política de roteamento própria.
2) O `AS_PATH` — lista todos os ASes pelo qual o anúncio passou. Se o próprio AS já aparece no caminho, ele descarta o anúncio.
3) BGP hijacking é quando um AS anuncia prefixos de IP que não lhe pertencem, sequestrando o tráfego. RPKI permite validar criptograficamente a autorização de um AS para anunciar determinado bloco, rejeitando anúncios inválidos.
