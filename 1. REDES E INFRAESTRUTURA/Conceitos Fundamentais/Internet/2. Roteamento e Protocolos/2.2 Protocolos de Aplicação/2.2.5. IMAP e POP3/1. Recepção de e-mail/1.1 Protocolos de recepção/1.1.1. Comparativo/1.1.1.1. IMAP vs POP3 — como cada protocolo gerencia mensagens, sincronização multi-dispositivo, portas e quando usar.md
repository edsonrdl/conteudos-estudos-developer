### IMAP vs POP3 — gerenciamento de mensagens, sincronização multi-dispositivo e quando usar

IMAP e POP3 são os dois protocolos de **recepção** de e-mail — o lado oposto do SMTP. Enquanto o SMTP entrega e-mails ao servidor, IMAP e POP3 permitem que clientes (Outlook, Thunderbird, apps mobile) acessem e leiam os e-mails armazenados no servidor. A diferença fundamental está na filosofia: IMAP mantém os e-mails no servidor e sincroniza múltiplos clientes; POP3 baixa e (geralmente) remove os e-mails para um único cliente local.

---

## POP3 — Post Office Protocol v3

POP3 (RFC 1939) foi projetado em uma era onde as pessoas tinham apenas um computador com conexão dial-up. O modelo é simples: conectar, baixar todas as mensagens novas, desconectar. Os e-mails ficam no computador local; o servidor apenas os armazena temporariamente.

```
Analogia: correio físico
  Você vai ao correio, pega todas as suas cartas, leva para casa.
  O correio não guarda cópia. As cartas estão só na sua casa.
  → Um único "local" para o e-mail
```

### Sessão POP3

```
Cliente: conecta ao servidor na porta 110 (ou 995 com TLS)

Servidor: +OK Dovecot ready

AUTENTICAÇÃO:
  C: USER joao@empresa.com
  S: +OK
  C: PASS senha123
  S: +OK Logged in

TRANSAÇÃO:
  C: STAT                        ← quantas mensagens / tamanho total
  S: +OK 3 12345                 ← 3 mensagens, 12345 bytes

  C: LIST                        ← listar mensagens com tamanhos
  S: +OK 3 messages
     1 4096
     2 3072
     3 5177
     .

  C: RETR 1                      ← baixar mensagem 1
  S: +OK 4096 octets
     From: remetente@origem.com
     To: joao@empresa.com
     Subject: Assunto do e-mail
     [corpo completo da mensagem]
     .

  C: DELE 1                      ← marcar mensagem 1 para deleção
  S: +OK marked for deletion

  C: UIDL                        ← IDs únicos (para "deixar no servidor")
  S: +OK
     1 abc123def456
     2 xyz789uvw
     3 mno456pqr
     .

ATUALIZAÇÃO (ao QUIT):
  C: QUIT
  S: +OK Logging out, messages deleted
  → Mensagens marcadas com DELE são removidas do servidor
```

### Comportamento padrão do POP3

```
Fluxo típico sem "deixar cópia no servidor":

1. Outlook no PC de casa baixa 5 e-mails → deleta do servidor
2. Outlook no trabalho: nenhum e-mail (servidor está vazio)
3. App mobile: nenhum e-mail

Fluxo com "deixar cópia no servidor" (opção nos clientes):
1. Outlook baixa 5 e-mails → NÃO deleta do servidor
2. App mobile baixa os mesmos 5 e-mails
3. Cada cliente tem sua própria cópia local
4. Mas: e-mail lido no PC não aparece como lido no mobile!
   → Sem sincronização de estado entre dispositivos
```

### Limitações do POP3

```
✗ Sem sincronização de estado:
  Ler no PC → não aparece como lido no mobile
  Deletar no PC → continua no servidor (se "deixar cópia" ativo)

✗ Sem pastas no servidor:
  "Enviados", "Rascunhos", "Lixeira" existem apenas no cliente
  Mudar de cliente → perder organização

✗ Sem busca no servidor:
  Busca feita localmente (todos os e-mails devem estar baixados)

✗ Um e-mail, uma cópia:
  Sem "deixar cópia": e-mail existe em apenas um dispositivo
  
✓ Vantagens:
  Funciona offline (todos os e-mails no disco local)
  Backup local automático (e-mails no disco do cliente)
  Servidor não precisa de muito armazenamento
  Menor latência para operações locais
```

### Portas POP3

```
110 → POP3 (texto puro — inseguro para credenciais)
995 → POP3S (POP3 over SSL/TLS — seguro)
     Conexão TLS imediata, sem STARTTLS
     
STLS command (STARTTLS para POP3):
  Upgrade para TLS na mesma conexão
  Semelhante ao STARTTLS do SMTP
  Menos comum — maioria usa porta 995 diretamente
```

## IMAP — Internet Message Access Protocol

IMAP (RFC 3501, versão 4rev1; RFC 9051, versão 4rev2) foi projetado para um mundo multi-dispositivo onde e-mails ficam no servidor e múltiplos clientes os acessam de forma sincronizada. O servidor é a fonte da verdade.

```
Analogia: e-mail como banco online
  Você acessa sua conta do banco de qualquer dispositivo
  O saldo e histórico estão no banco, não no seu dispositivo
  Você vê o mesmo estado de qualquer lugar
  → E-mails vivem no servidor, dispositivos apenas os visualizam
```

### Sessão IMAP

```
Cliente: conecta na porta 143 (ou 993 com TLS)

Servidor: * OK IMAP4rev1 Dovecot ready

AUTENTICAÇÃO:
  C: a001 LOGIN joao@empresa.com senha123
  S: a001 OK Logged in

  [ou com STARTTLS primeiro]
  C: a001 STARTTLS
  S: a001 OK Begin TLS
  [TLS handshake]
  C: a002 AUTHENTICATE PLAIN <base64>
  S: a002 OK Authentication successful

SELEÇÃO DE PASTA:
  C: a003 LIST "" "*"            ← listar todas as pastas
  S: * LIST (\HasNoChildren) "/" INBOX
     * LIST (\HasNoChildren) "/" "Sent"
     * LIST (\HasNoChildren) "/" "Drafts"
     * LIST (\HasNoChildren) "/" "Trash"
     * LIST (\HasNoChildren) "/" "Spam"
     a003 OK List completed

  C: a004 SELECT INBOX           ← abrir caixa de entrada
  S: * 47 EXISTS                 ← 47 mensagens no INBOX
     * 2 RECENT                  ← 2 novas desde último acesso
     * OK [UNSEEN 45]            ← 45 não lidas (desde mensagem 45)
     * OK [UIDVALIDITY 1705312800]
     * OK [UIDNEXT 1523]         ← próximo UID disponível
     a004 OK [READ-WRITE] Select completed

BUSCAS E FETCH:
  C: a005 SEARCH UNSEEN          ← buscar mensagens não lidas
  S: * SEARCH 45 46 47
     a005 OK Search completed

  C: a006 FETCH 45 (FLAGS ENVELOPE BODY[])  ← baixar mensagem 45
  S: * 45 FETCH (
       FLAGS (\Seen)
       ENVELOPE ("Mon, 15 Jan 2024 10:30:00 +0000"
                 "Relatório de Janeiro"
                 (("João Silva" NIL "joao" "gmail.com"))
                 ...)
       BODY[] {2048}
       [2048 bytes do corpo]
     )
     a006 OK Fetch completed

OPERAÇÕES:
  C: a007 STORE 45 +FLAGS (\Seen)  ← marcar como lida
  C: a008 STORE 46 +FLAGS (\Flagged) ← marcar com estrela
  C: a009 COPY 45 "Archived"       ← copiar para pasta
  C: a010 UID MOVE 47 "Trash"      ← mover para lixeira
  C: a011 EXPUNGE                  ← apagar permanentemente marcados \Deleted

DESCONECTAR:
  C: a012 LOGOUT
  S: * BYE Logging out
     a012 OK Logout completed
```

### Recursos exclusivos do IMAP

```
1. Pastas no servidor (mailboxes):
   INBOX, Sent, Drafts, Trash, Spam, pastas customizadas
   Acessíveis de qualquer dispositivo

2. Flags sincronizadas:
   \Seen    → lido
   \Answered → respondido
   \Flagged  → marcado/estrelado
   \Deleted  → marcado para deleção
   \Draft    → rascunho
   Customizadas: $Forwarded, $Junk, $NotJunk
   
   Ler no celular → aparece como lido no PC → sincronizado!

3. Partial fetch — baixar partes da mensagem:
   FETCH BODY[HEADER]       → apenas headers
   FETCH BODY[TEXT]         → apenas corpo
   FETCH BODY[1]            → apenas a primeira parte MIME
   FETCH BODY.PEEK[]        → sem marcar como lido
   
   Útil para: ver assunto antes de baixar o corpo completo
             visualizar apenas headers para triagem

4. Busca no servidor:
   SEARCH FROM "joao@gmail.com"
   SEARCH SINCE 15-Jan-2024
   SEARCH SUBJECT "urgente"
   SEARCH BODY "reunião"     ← full-text search (se servidor suportar)
   SEARCH UNSEEN             ← apenas não lidas
   SEARCH FLAGGED            ← apenas marcadas

5. IDLE — notificações em tempo real:
   C: a013 IDLE
   S: + idling
   [conexão fica aberta, servidor notifica quando chega e-mail]
   S: * 48 EXISTS             ← chegou novo e-mail!
   C: DONE
   
   IDLE é como o servidor "empurra" novos e-mails (push email)
   sem o cliente precisar fazer polling constante

6. Namespace e LSUB:
   Compartilhar pastas entre usuários
   Pastas públicas para equipes
```

### Portas IMAP

```
143  → IMAP (texto puro com STARTTLS disponível)
993  → IMAPS (IMAP over SSL/TLS — conexão TLS imediata)

Recomendado: porta 993 (IMAPS) para segurança
Muitos clientes modernos tentam STARTTLS na 143 antes de fallback
```

## Comparativo IMAP vs POP3

```
┌──────────────────────────┬────────────────────────────┬────────────────────────────┐
│ Aspecto                  │ IMAP                       │ POP3                       │
├──────────────────────────┼────────────────────────────┼────────────────────────────┤
│ E-mails ficam onde?      │ No servidor (fonte verdade)│ Baixados para o cliente    │
│ Sincronização            │ Completa (todos dispositiv)│ Nenhuma (ou parcial)       │
│ Estado (lido/não lido)   │ Sincronizado               │ Não sincronizado           │
│ Pastas                   │ No servidor                │ Apenas no cliente          │
│ Busca                    │ No servidor (server-side)  │ Local (precisa baixar)     │
│ Acesso offline           │ Cache local (parcial)      │ Completo (tudo baixado)    │
│ Armazenamento servidor   │ Alto (todos os e-mails)    │ Baixo (temporário)         │
│ Armazenamento local      │ Baixo (cache/parcial)      │ Alto (todos os e-mails)    │
│ Multi-dispositivo        │ Ideal                      │ Problemático               │
│ Backup local automático  │ Não (e-mail está no serv.) │ Sim (e-mail no disco)      │
│ Porta (sem TLS)          │ 143                        │ 110                        │
│ Porta (com TLS)          │ 993                        │ 995                        │
│ Push email (IDLE)        │ Sim                        │ Não                        │
│ Quando usar              │ Maioria dos casos modernos │ Armazenamento limitado/off │
└──────────────────────────┴────────────────────────────┴────────────────────────────┘
```

## Quando usar cada protocolo

```
Use IMAP quando:
  ✓ Múltiplos dispositivos (PC + celular + tablet)
  ✓ Acesso via webmail (Gmail, Outlook.com) + clientes
  ✓ E-mail corporativo com pastas organizadas
  ✓ Equipes que compartilham pastas
  ✓ Alta disponibilidade (servidor robusto e backupado)
  ✓ Qualquer configuração moderna

Use POP3 quando:
  ✓ Apenas um dispositivo (sem necessidade de sync)
  ✓ Backup local obrigatório (armazenar e-mails no disco corporativo)
  ✓ Servidor com armazenamento muito limitado
  ✓ Conexão intermitente que exige tudo disponível offline
  ✓ Sistemas legados que suportam apenas POP3
  ✓ Compliance que exige e-mails armazenados localmente

Na prática (2024):
  IMAP é o padrão universal — 99% dos casos usa IMAP
  POP3 persiste apenas em sistemas legados ou requisitos específicos
```

## IMAP em código

```python
# Python — imaplib para acessar e-mail via IMAP
import imaplib
import email
from email.header import decode_header

def listar_emails_nao_lidos(host: str, usuario: str, senha: str):
    # Conectar via IMAPS (TLS)
    with imaplib.IMAP4_SSL(host, 993) as imap:
        imap.login(usuario, senha)
        
        # Selecionar INBOX
        status, data = imap.select("INBOX")
        total = int(data[0])
        print(f"Total de e-mails: {total}")
        
        # Buscar e-mails não lidos
        status, msg_ids = imap.search(None, "UNSEEN")
        if status != "OK" or not msg_ids[0]:
            return
        
        ids = msg_ids[0].split()
        print(f"Não lidos: {len(ids)}")
        
        # Buscar cada e-mail (apenas headers primeiro)
        for msg_id in ids[-10:]:  # últimos 10
            status, data = imap.fetch(msg_id, "(RFC822)")
            if status != "OK":
                continue
            
            raw_email = data[0][1]
            msg = email.message_from_bytes(raw_email)
            
            # Decodificar assunto (pode estar em base64)
            subject, encoding = decode_header(msg["Subject"])[0]
            if isinstance(subject, bytes):
                subject = subject.decode(encoding or "utf-8")
            
            # Extrair remetente
            from_header = msg.get("From", "")
            
            print(f"\nDe: {from_header}")
            print(f"Assunto: {subject}")
            print(f"Data: {msg.get('Date')}")
            
            # Marcar como lido
            imap.store(msg_id, "+FLAGS", "\\Seen")
        
        imap.logout()

listar_emails_nao_lidos("imap.gmail.com", "usuario@gmail.com", "app-password")
```

```python
# Busca avançada com IMAP
import imaplib

def buscar_emails(imap, criteria: str):
    """
    Exemplos de criteria:
      'UNSEEN'                          → não lidos
      'FROM "joao@gmail.com"'           → de joao
      'SUBJECT "urgente"'               → com "urgente" no assunto
      'SINCE 15-Jan-2024'               → desde 15 jan
      'BEFORE 31-Jan-2024'              → antes de 31 jan
      'LARGER 1000000'                  → maiores que 1 MB
      'FLAGGED'                         → marcados
      '(OR FROM "joao" FROM "maria")'   → de joao OU maria
      '(UNSEEN FROM "chefe@empresa.com")' → não lido do chefe
    """
    status, ids = imap.search(None, criteria)
    return ids[0].split() if status == "OK" and ids[0] else []
```

## Diferença entre IMAP e webmail

```
Webmail (Gmail, Outlook.com):
  → Interface web que se comunica com o servidor internamente
  → Usa protocolos proprietários ou IMAP internamente
  → O usuário acessa via HTTPS/browser
  
IMAP:
  → Protocolo padrão aberto para clientes de e-mail (Outlook, Thunderbird)
  → O cliente instala localmente e conecta via IMAP ao servidor
  → O servidor pode ser Gmail, Outlook, ou qualquer servidor IMAP

Gmail e IMAP:
  Gmail expõe acesso IMAP na porta 993 (imap.gmail.com)
  → Thunderbird/Outlook se conectam via IMAP ao Gmail
  → "App Passwords" necessário (autenticação de 2 fatores)
  → Gmail implementa IMAP com algumas diferenças comportamentais
    (ex: labels do Gmail aparecem como pastas IMAP)
```

## Erros comuns e armadilhas

**Configurar POP3 com "baixar e deletar" em múltiplos clientes:** o primeiro cliente a conectar baixa todos os e-mails e os deleta do servidor. Outros clientes não encontram nada. Para uso com múltiplos clientes, sempre usar IMAP ou pelo menos "deixar cópia no servidor" no POP3.

**IMAP sem IDLE causando polling excessivo:** clientes que não suportam IDLE (ou onde está desabilitado) fazem polling constante (`CHECK` a cada 1-2 min) — consumindo bateria em mobile e sobrecarregando o servidor com muitos clientes. Habilitar IDLE para push email eficiente.

**Não fechar conexões IMAP:** conexões IMAP são persistentes e muitos servidores têm limite de conexões simultâneas por usuário. Código que abre conexões sem fechá-las (`LOGOUT`) pode bloquear acesso de outros clientes/dispositivos.

**Mover e-mail para Trash vs DELETE:** `STORE +FLAGS (\Deleted)` + `EXPUNGE` deleta permanentemente. A maioria dos clientes move para Trash primeiro. Implementar fluxo correto conforme a UX desejada.

## 🧩 Quiz de Fixação

1. Um usuário configura POP3 no Outlook do trabalho com "baixar e deletar do servidor". Ele volta para casa e configura o mesmo e-mail no Thunderbird via POP3. Quando o Thunderbird sincroniza, encontra 0 e-mails. Explique o que aconteceu e como o usuário deveria ter configurado para ter acesso em ambos os clientes.

2. Por que o comando IMAP `FETCH BODY.PEEK[]` é preferível ao `FETCH BODY[]` em uma aplicação que lista e-mails para o usuário mas não os marca como lidos automaticamente?

3. Uma aplicação móvel precisa receber notificações imediatas de novos e-mails sem consumir bateria excessivamente com polling. Como IMAP IDLE resolve isso, e qual é a diferença entre IDLE e fazer `CHECK` a cada 30 segundos?

**Respostas:**

1) O que aconteceu: o Outlook do trabalho conectou via POP3, baixou todos os e-mails **e os deletou do servidor** (comportamento "baixar e deletar"). Quando o Thunderbird conectou em casa, o servidor estava vazio — não havia nenhuma mensagem para baixar. Os e-mails existem apenas no Outlook do trabalho. **Como deveria ter configurado:** (a) **IMAP em ambos os clientes** — os e-mails ficam no servidor e ambos os clientes veem o mesmo estado sincronizado; (b) **POP3 com "deixar cópia no servidor"** nos dois clientes — ambos baixam os mesmos e-mails, mas sem sincronização de estado (ler num não marca como lido no outro). Para 2024, a resposta correta é IMAP, que foi projetado exatamente para esse cenário multi-dispositivo.

2) `FETCH BODY[]` baixa o e-mail E automaticamente seta a flag `\Seen` (lido) no servidor. Isso significa que um e-mail que o usuário apenas "abriu na lista" (sem realmente ler) seria marcado como lido em todos os dispositivos — comportamento indesejado. `FETCH BODY.PEEK[]` é a versão "espiar" — baixa o conteúdo completo **sem modificar as flags**, especificamente sem marcar como `\Seen`. Assim, a aplicação pode carregar e exibir o e-mail sem mudar seu estado no servidor, deixando a marcação como lido para quando o usuário realmente ler/confirmar.

3) **Sem IDLE (polling a cada 30s):** o cliente abre conexão, envia `CHECK` ou `NOOP` para ver se há mensagens novas, fecha ou aguarda resposta, repete. Para 1000 usuários: 1000 conexões × 2 checks/min = 2000 requisições por minuto ao servidor, mais latência máxima de 30 segundos para receber uma notificação. Consome bateria por manter a rádio ativa periodicamente. **Com IDLE:** o cliente envia `IDLE` e **mantém a conexão TCP aberta passivamente**. O servidor envia uma notificação `* N EXISTS` apenas quando chega um novo e-mail — o cliente não precisa perguntar. A rádio do dispositivo pode entrar em sleep até receber dados. Latência: sub-segundo (notificação chega assim que o e-mail é entregue). A conexão TCP keepalive é muito mais eficiente em bateria do que acordar a rádio periodicamente para fazer polling.
