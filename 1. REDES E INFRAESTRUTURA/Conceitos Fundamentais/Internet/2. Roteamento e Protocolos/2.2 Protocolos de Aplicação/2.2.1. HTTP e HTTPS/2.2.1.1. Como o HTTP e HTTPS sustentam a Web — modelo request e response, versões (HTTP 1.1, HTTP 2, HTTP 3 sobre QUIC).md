### HTTP e HTTPS — A Camada de Aplicação da Web

HTTP (HyperText Transfer Protocol) é o protocolo que sustenta a World Wide Web. Quando você acessa qualquer site, sua aplicação faz requisições HTTP. HTTPS é o HTTP protegido por TLS.

---

## O modelo request/response

HTTP é **stateless** — cada requisição é independente, sem memória do que veio antes.

```
Cliente                              Servidor
  │                                     │
  │── GET /index.html HTTP/1.1 ────────>│
  │   Host: exemplo.com                 │
  │   Accept: text/html                 │
  │                                     │
  │<── HTTP/1.1 200 OK ────────────────│
  │    Content-Type: text/html          │
  │    Content-Length: 1234             │
  │                                     │
  │    <html>...</html>                 │
```

**Métodos principais:**

| Método | Uso | Idempotente |
|--------|-----|-------------|
| `GET` | Buscar recurso | Sim |
| `POST` | Criar recurso | Não |
| `PUT` | Substituir recurso | Sim |
| `PATCH` | Atualizar parcialmente | Não |
| `DELETE` | Remover recurso | Sim |

## Evolução das versões

### HTTP/1.1 (1997)
- Uma requisição por vez por conexão TCP
- **Head-of-line blocking**: requisição lenta bloqueia as seguintes
- Workarounds: múltiplas conexões TCP paralelas (browsers abriam 6–8)
- Ainda muito usado — compatível com tudo

### HTTP/2 (2015)
- **Multiplexing**: múltiplas requisições simultâneas na mesma conexão TCP
- **Header compression** (HPACK): reduz overhead de cabeçalhos repetidos
- **Server Push**: servidor pode enviar recursos antes de serem pedidos
- Problema: ainda sofre de head-of-line blocking no nível TCP (um pacote perdido bloqueia tudo)

### HTTP/3 (2022)
- Substitui TCP por **QUIC** (UDP com confiabilidade embutida)
- **Sem head-of-line blocking**: fluxos independentes, perda em um não afeta outros
- **0-RTT**: conexões mais rápidas aproveitando handshake anterior
- **Migração de conexão**: troca de IP sem reconectar (importante para mobile)
- Hoje usado por Google, Meta, Cloudflare em produção

```
HTTP/1.1:  TCP → TLS → HTTP
HTTP/2:    TCP → TLS → HTTP/2 (multiplexado)
HTTP/3:    QUIC (UDP+TLS 1.3 integrado) → HTTP/3
```

## HTTPS = HTTP + TLS

HTTPS não é um protocolo separado — é HTTP rodando sobre TLS (Transport Layer Security):

```
Porta 80  → HTTP  (não criptografado)
Porta 443 → HTTPS (TLS + HTTP)
```

O TLS fornece:
- **Confidencialidade**: dados criptografados, ISP não lê o conteúdo
- **Integridade**: qualquer modificação no trânsito é detectada
- **Autenticação**: certificado garante que o servidor é quem diz ser

Hoje HTTPS é obrigatório na prática — browsers marcam HTTP como "não seguro", SEO penaliza, e APIs modernas exigem.

## 🧩 Quiz de Fixação

1. O que é head-of-line blocking e qual versão do HTTP o resolveu completamente?
2. Qual a diferença fundamental entre HTTP/2 e HTTP/3 na camada de transporte?
3. Por que HTTP é considerado stateless e como aplicações contornam isso?

**Respostas:**
1) Head-of-line blocking é quando um pacote perdido bloqueia todos os dados subsequentes na fila. HTTP/2 resolveu o problema no nível HTTP (com multiplexing), mas ainda sofre no nível TCP. HTTP/3 resolveu completamente usando QUIC (UDP), onde streams são independentes.
2) HTTP/2 roda sobre TCP; HTTP/3 roda sobre QUIC (que usa UDP). A mudança elimina o head-of-line blocking de TCP e permite migração de conexão sem reconectar.
3) Cada requisição HTTP não carrega contexto das anteriores. Aplicações contornam com cookies, sessões no servidor, tokens JWT ou outros mecanismos de estado na camada de aplicação.
