### IPv4, Esgotamento e a Transição para IPv6

O IPv4 foi projetado nos anos 1970 com 32 bits de endereçamento — 4,3 bilhões de endereços. Parecia suficiente. Não foi.

---

## O problema do IPv4

```
IPv4:  32 bits → 2³² = ~4,3 bilhões de endereços

População mundial: ~8 bilhões
Dispositivos conectados: ~15 bilhões (e crescendo)
```

O esgotamento foi previsto e mitigado por décadas com NAT, mas os blocos livres acabaram:

| Evento | Data |
|--------|------|
| IANA esgota últimos blocos para RIRs | Fevereiro 2011 |
| APNIC (Ásia-Pacífico) esgota | Abril 2011 |
| RIPE NCC (Europa) esgota | Setembro 2012 |
| LACNIC (América Latina) esgota | Junho 2014 |
| ARIN (América do Norte) esgota | Setembro 2015 |

Hoje IPs IPv4 são comprados e vendidos no mercado secundário por ~$40–60 cada.

---

## A solução: IPv6

O IPv6 usa **128 bits** de endereçamento:

```
IPv6:  128 bits → 2¹²⁸ = ~340 undecilhões de endereços
       (340.000.000.000.000.000.000.000.000.000.000.000.000)

Para comparação: há ~10²³ estrelas no universo observável
```

**Formato de endereço:**
```
IPv4: 192.168.1.10
IPv6: 2001:0db8:85a3:0000:0000:8a2e:0370:7334
      (abreviado: 2001:db8:85a3::8a2e:370:7334)
```

**Outras melhorias do IPv6:**
- Cabeçalho simplificado (melhor desempenho nos roteadores)
- Auto-configuração (SLAAC — sem precisar de DHCP)
- IPSec mandatório (segurança na camada de rede)
- Sem necessidade de NAT (cada dispositivo pode ter IP público)

---

## Mecanismos de coexistência

A transição não foi imediata — IPv4 e IPv6 coexistem há mais de 10 anos.

### NAT (Network Address Translation)
Permite que múltiplos dispositivos compartilhem um único IP público IPv4:
```
Dispositivos internos     ISP
192.168.1.10  ─┐
192.168.1.11  ─┤ NAT ─── 203.0.113.1 (IP público único)
192.168.1.12  ─┘
```
Solução paliativa que preservou o IPv4, mas quebra o modelo fim-a-fim da Internet (VoIP, jogos, P2P sofrem com NAT).

### Dual-Stack
Dispositivo e rede suportam IPv4 e IPv6 simultaneamente — o protocolo preferido é IPv6, com fallback para IPv4:
```
Seu browser tenta IPv6 primeiro → se funcionar, usa IPv6
Se IPv6 falhar → usa IPv4 automaticamente (Happy Eyeballs)
```
É o método de transição padrão recomendado.

### Tunneling (6in4, Teredo)
Encapsula pacotes IPv6 dentro de pacotes IPv4 para cruzar redes que só entendem IPv4:
```
[IPv6 header][dados] → encapsulado em → [IPv4 header][IPv6 header][dados]
```
Usado quando a rede do ISP ainda não tem IPv6 nativo.

```
Países líderes: Índia (~70%), EUA (~50%), Alemanha (~60%)
Brasil: ~35%
```

## 🧩 Quiz de Fixação

1. Por que o NAT foi adotado em larga escala se não era a solução ideal?
2. Qual mecanismo de transição é considerado o padrão recomendado e por quê?
3. Por que o IPv6 elimina a necessidade de NAT?

**Respostas:**
1) NAT foi adotado porque adiava o esgotamento do IPv4 sem exigir mudanças nos clientes finais — foi a solução de curto prazo que acabou durando décadas. A transição para IPv6 exige atualização de toda a pilha de rede.
2) Dual-stack — porque permite que o dispositivo use IPv6 quando disponível e caia para IPv4 automaticamente, sem quebrar compatibilidade. É transparente para o usuário.
3) No IPv6 há endereços suficientes para que cada dispositivo tenha seu próprio IP público globalmente único — não há necessidade de compartilhar IPs via NAT. O modelo fim-a-fim original da Internet é restaurado.
