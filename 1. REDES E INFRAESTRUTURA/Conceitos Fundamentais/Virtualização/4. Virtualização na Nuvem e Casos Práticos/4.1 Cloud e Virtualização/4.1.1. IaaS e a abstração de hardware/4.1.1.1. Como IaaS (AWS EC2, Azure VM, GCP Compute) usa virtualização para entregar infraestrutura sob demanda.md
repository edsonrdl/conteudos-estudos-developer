### IaaS — como a nuvem usa virtualização para infraestrutura sob demanda

IaaS (Infrastructure as a Service) é o modelo de nuvem onde o provedor oferece computação, storage e rede virtualizados sob demanda, cobrados por uso. É a aplicação direta de virtualização em escala massiva.

---

## O que acontece quando você cria uma EC2

```
Você: aws ec2 run-instances --image-id ami-xxx --instance-type t3.medium

Nos bastidores da AWS:
  1. Scheduler encontra host físico com capacidade disponível
  2. KVM/Nitro hypervisor cria nova VM naquele host
  3. Volume EBS é criado e anexado (storage virtualizado)
  4. Interface de rede virtual é provisionada na VPC
  5. Imagem AMI é restaurada como disco root
  6. VM inicia o boot

Você recebe: IP privado + IP público, acesso SSH em ~30 segundos
```

---

## Os três grandes e suas tecnologias

| Provedor | Hypervisor | Storage | Rede |
|---|---|---|---|
| **AWS** | Nitro (KVM modificado) + Xen (legado) | EBS | VPC |
| **Azure** | Hyper-V | Managed Disks | VNet |
| **GCP** | KVM | Persistent Disk | VPC |

---

## AWS Nitro System — a evolução do hypervisor

```
Hypervisor tradicional:
  Hypervisor gerencia: CPU, RAM, rede, storage, segurança
  → Overhead do hypervisor consome parte dos recursos

AWS Nitro:
  Nitro Cards (hardware dedicado): gerencia rede e storage
  Nitro Hypervisor (KVM minimalista): apenas CPU e RAM
  Nitro Security Chip: root of trust e isolamento

Resultado:
  Overhead mínimo — quase toda CPU/RAM vai para a instância
  Tipos "metal" (bare-metal): zero overhead de hypervisor
```

---

## Tipos de instâncias e virtualização

```
Instâncias regulares (t3, m6i, c6g...):
  → VM sobre Nitro hypervisor
  → Compartilham host físico com outras instâncias

Instâncias Bare Metal (m6i.metal, c6g.metal...):
  → Acesso direto ao hardware físico
  → Sem hypervisor overhead
  → Usado para: licenças que exigem hardware dedicado, 
                rodar seu próprio hypervisor
                cargas com requisitos extremos de latência

Instâncias Dedicated Host:
  → Host físico dedicado exclusivamente ao seu account
  → Conformidade com licenças por socket/core (Oracle, Windows)
```

## O modelo econômico que a virtualização viabiliza

```
Sem virtualização:
  Servidor físico para web:   $5.000 + energia + datacenter
  Prazo de provisionamento:   semanas
  Uso real de CPU:            5-15%

Com IaaS/virtualização:
  t3.small (2 vCPU, 2GB RAM): $0.0208/hora ≈ $15/mês
  Prazo de provisionamento:   30 segundos
  Uso real de CPU:            você controla
  Escala horizontal:          100 instâncias em minutos
```

## 🧩 Quiz de Fixação

1. O que a AWS Nitro System melhorou em relação ao hypervisor KVM tradicional?
2. Quando faz sentido usar uma instância bare-metal na AWS em vez de uma VM normal?
3. Por que IaaS só é economicamente viável com virtualização?

**Respostas:**
1) O Nitro offloada o gerenciamento de rede e storage para hardware dedicado (Nitro Cards) — o hypervisor principal gerencia só CPU e RAM com overhead mínimo, entregando quase 100% dos recursos da instância para o cliente.
2) Quando há requisitos de licença por socket/core (Oracle DB), necessidade de rodar seu próprio hypervisor dentro da instância, ou cargas de trabalho que exigem latência extremamente baixa sem nenhum overhead de virtualização.
3) Sem virtualização, cada cliente precisaria de hardware físico exclusivo — impossível alocar e desalocar em segundos, compartilhar hardware subutilizado entre clientes ou cobrar por hora de uso fracionado.
