### SDN e SDS — virtualização além do servidor

A virtualização não se limita a servidores. Redes e storage também podem ser abstraídos do hardware físico — permitindo o mesmo modelo de provisionamento rápido e programático que as VMs trouxeram para computação.

---

## SDN — Software-Defined Networking

Redes tradicionais têm o plano de controle (decisões de roteamento) e o plano de dados (encaminhamento de pacotes) acoplados no mesmo hardware (switch/roteador). O SDN os separa:

```
Rede Tradicional:
  [Switch A] — controle + dados acoplados → configuração manual por dispositivo

SDN:
  [Controlador SDN]  ← plano de controle centralizado (software)
       │
  [Switch A] [Switch B] [Switch C]  ← plano de dados (apenas encaminham)
       ↑
  Programáveis via API (OpenFlow, NETCONF)
```

**O que o SDN permite:**
- Criar e reconfigurar redes via API/código (sem tocar em hardware).
- VLANs, roteamento e firewall definidos por software.
- Visibilidade centralizada de todo o tráfego.
- Base das redes virtuais em nuvem (AWS VPC, Azure VNet).

**Exemplos:** VMware NSX, Cisco ACI, OpenDaylight, Open vSwitch.

---

## Rede Virtual em Nuvem — VPC

```
AWS:
  VPC 10.0.0.0/16
  ├── Subnet pública 10.0.1.0/24  → Internet Gateway
  └── Subnet privada 10.0.2.0/24 → NAT Gateway

Tudo isso é software — não há switch físico configurado manualmente.
Um terraform apply cria toda essa topologia em segundos.
```

---

## SDS — Software-Defined Storage

Separa o hardware de armazenamento do software que o gerencia — criando pools de storage que podem ser provisionados por API:

```
Storage Tradicional:
  SAN física dedicada → configuração manual por LUN → semanas para provisionar

SDS:
  Pool de discos físicos (qualquer hardware)
       ↓
  Camada de software (Ceph, vSAN)
       ↓
  Volume de 1TB criado em segundos via API
```

**Recursos que o SDS oferece:**
- **Thin provisioning:** aloca espaço sob demanda (não reserva tudo de uma vez).
- **Replicação:** copia dados automaticamente entre nós.
- **Deduplicação:** elimina dados duplicados para economizar espaço.
- **Tiering:** move dados quentes para SSD e frios para HDD automaticamente.

**Exemplos:** Ceph, VMware vSAN, AWS EBS, Azure Managed Disks.

---

## A tríade da virtualização moderna

```
Computação virtualizada:  VMs / Contêineres
Rede virtualizada:        SDN / VPC / NSX
Storage virtualizado:     SDS / EBS / vSAN

Juntos = Infraestrutura completamente programável
→ Infrastructure as Code (IaC) — Terraform, Pulumi
→ Provisionamento completo via API em minutos
```

## 🧩 Quiz de Fixação

1. Qual o problema das redes tradicionais que o SDN resolve?
2. O que é thin provisioning em SDS e por que é vantajoso?
3. Por que a combinação de SDN + SDS + VMs é considerada "infraestrutura programável"?

**Respostas:**
1) O acoplamento do plano de controle ao hardware — cada switch/roteador precisa ser configurado individualmente. O SDN centraliza o controle, permitindo reconfigurar toda a rede via software.
2) Thin provisioning aloca espaço de storage conforme os dados são escritos, não na reserva inicial — um volume de 1TB pode ser criado para 100 VMs sem precisar de 100TB físicos disponíveis imediatamente, aproveitando melhor o espaço real.
3) Porque todos os três podem ser criados, modificados e destruídos via API/código — um arquivo Terraform pode definir VMs, redes e volumes de disco e provisioná-los em minutos, sem intervenção manual em hardware.
