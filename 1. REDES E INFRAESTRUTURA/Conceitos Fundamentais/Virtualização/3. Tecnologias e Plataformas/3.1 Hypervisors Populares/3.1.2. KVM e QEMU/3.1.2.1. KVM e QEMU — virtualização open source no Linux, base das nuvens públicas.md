### KVM e QEMU — virtualização open source base das nuvens públicas

KVM (Kernel-based Virtual Machine) e QEMU (Quick Emulator) são as tecnologias open source que alimentam a maioria das nuvens públicas e privadas. Juntos, formam o stack de virtualização padrão do Linux.

---

## KVM — o hypervisor no kernel

O KVM é um módulo do kernel Linux que converte o Linux em um hypervisor Tipo 1. Usa as extensões de virtualização da CPU:

```
CPU Intel: Intel VT-x (Virtualization Technology)
CPU AMD:   AMD-V (AMD Virtualization)

Verificar suporte:
  grep -E 'vmx|svm' /proc/cpuinfo
  vmx = Intel VT-x
  svm = AMD-V
```

O KVM expõe o dispositivo `/dev/kvm` — cada VM é um processo Linux com acesso privilegiado ao hardware via esse dispositivo.

---

## QEMU — a emulação

QEMU emula os dispositivos de hardware que as VMs enxergam (disco, NIC, USB, BIOS). Sem KVM, emula em software (lento). Com KVM, executa código guest diretamente na CPU (rápido):

```
KVM sozinho:    executa CPU e memória com performance nativa
QEMU sozinho:   emula tudo em software (lento, mas suporta qualquer arquitetura)
KVM + QEMU:     CPU/RAM nativos (KVM) + dispositivos emulados (QEMU) = produção
```

---

## libvirt — a camada de gerenciamento

libvirt é a API/daemon que abstrai KVM+QEMU, oferecendo interface consistente:

```
CLI:         virsh
GUI:         virt-manager
API:         libvirt (Python, Go, C)
Cloud:       OpenStack, oVirt usam libvirt internamente

Comandos básicos (virsh):
  virsh list --all              # lista VMs
  virsh start vm-nome           # inicia VM
  virsh shutdown vm-nome        # desliga graciosamente
  virsh snapshot-create-as vm-nome snap1   # cria snapshot
  virsh migrate vm-nome qemu+ssh://host2   # live migration
```

## Formatos de disco

| Formato | Extensão | Características |
|---|---|---|
| **QCOW2** | `.qcow2` | Padrão KVM — thin provisioning, snapshots, compressão |
| **RAW** | `.img` | Performance máxima — sem features adicionais |
| **VMDK** | `.vmdk` | Compatível com VMware |
| **VHD/VHDX** | `.vhd` | Compatível com Hyper-V |

```bash
# Criar disco QCOW2 de 20GB
qemu-img create -f qcow2 vm-disco.qcow2 20G

# Converter entre formatos
qemu-img convert -f vmdk -O qcow2 vm.vmdk vm.qcow2

# Ver informações do disco
qemu-img info vm-disco.qcow2
```

## 🧩 Quiz de Fixação

1. O que o KVM faz que o QEMU não faz sozinho?
2. Por que o formato QCOW2 é preferido ao RAW para desenvolvimento e testes?
3. Como verificar se a CPU do servidor suporta virtualização por hardware?

**Respostas:**
1) O KVM permite que o código guest execute diretamente na CPU física com performance nativa — usando as extensões VT-x/AMD-V. O QEMU sozinho emula toda a CPU em software, sendo muito mais lento.
2) QCOW2 suporta thin provisioning (ocupa apenas o espaço realmente usado), snapshots nativos e compressão — muito mais flexível para dev/testes. RAW tem melhor performance pura mas sem esses recursos.
3) `grep -E 'vmx|svm' /proc/cpuinfo` — `vmx` indica Intel VT-x, `svm` indica AMD-V. Se o comando retornar resultado, a CPU suporta virtualização por hardware.
