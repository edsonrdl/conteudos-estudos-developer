### VMware vSphere e Microsoft Hyper-V — virtualização enterprise

VMware vSphere e Microsoft Hyper-V são as duas plataformas de virtualização enterprise mais usadas em data centers corporativos. Cada uma tem ecossistema próprio, modelo de licenciamento e pontos fortes distintos.

---

## VMware vSphere

O vSphere é o ecossistema completo da VMware para virtualização enterprise. O hypervisor em si é o **ESXi**.

### Componentes principais

```
vSphere (ecossistema)
  ├── ESXi          → hypervisor bare-metal instalado nos servidores físicos
  ├── vCenter       → painel central para gerenciar múltiplos hosts ESXi
  ├── vSAN          → storage distribuído entre os hosts
  ├── NSX           → virtualização de rede (SDN)
  └── vMotion       → live migration de VMs entre hosts
```

### vCenter — gerenciamento centralizado

```
[vCenter Server]
      │
      ├── Host ESXi 1 (192.168.1.10)
      │     ├── VM-web-01
      │     └── VM-db-01
      ├── Host ESXi 2 (192.168.1.11)
      │     ├── VM-app-01
      │     └── VM-cache-01
      └── Host ESXi 3 (192.168.1.12)
            └── VM-worker-01
```

**Recursos enterprise do vSphere:**

| Recurso | Função |
|---|---|
| **vMotion** | Live migration sem downtime entre hosts |
| **HA (High Availability)** | Reinicia VMs automaticamente em host alternativo se host falhar |
| **DRS (Distributed Resource Scheduler)** | Balanceia carga de VMs entre hosts automaticamente |
| **FT (Fault Tolerance)** | VM espelho em outro host — zero downtime em falha |
| **Storage vMotion** | Move disco de VM entre datastores sem downtime |

## Microsoft Hyper-V

Hypervisor da Microsoft, integrado ao Windows Server. Alternativa corporativa com profunda integração ao ecossistema Microsoft.

### Modos de uso

```
Modo 1 — Role do Windows Server:
  Windows Server → instala Role "Hyper-V" → passa a ser hypervisor Tipo 1

Modo 2 — Hyper-V Server (standalone):
  Hyper-V Server (free) → hypervisor bare-metal sem licença Windows Server
```

### Gerenciamento

- **Hyper-V Manager:** GUI local/remota.
- **Windows Admin Center:** interface web moderna.
- **System Center VMM (SCVMM):** equivalente ao vCenter para grandes ambientes.
- **PowerShell:** automação completa.

```powershell
# Criar VM via PowerShell
New-VM -Name "WebServer01" -MemoryStartupBytes 4GB -Generation 2
Add-VMHardDiskDrive -VMName "WebServer01" -Path "D:\VMs\WebServer01.vhdx"
Start-VM -Name "WebServer01"
```

## VMware vs Hyper-V

| Aspecto | VMware vSphere | Microsoft Hyper-V |
|---|---|---|
| Performance | Excelente | Muito boa |
| Ecossistema | Mais maduro e completo | Integrado ao Windows |
| Custo | Alto (licenças caras) | Incluído no Windows Server |
| Live Migration | vMotion (excelente) | Live Migration (muito bom) |
| Automação | PowerCLI, REST API | PowerShell nativo |
| Multicloud | VMware Cloud (AWS, Azure) | Azure Arc, Azure Stack |
| Suporte Linux | Muito bom | Bom |

## 🧩 Quiz de Fixação

1. O que o DRS do vSphere faz automaticamente?
2. Qual a diferença entre HA e Fault Tolerance no vSphere?
3. Por que o Hyper-V pode ser mais econômico que o VMware em ambientes já usando Windows Server?

**Respostas:**
1) O DRS monitora a utilização de CPU e RAM dos hosts do cluster e migra VMs automaticamente (via vMotion) para balancear a carga — evitando hosts sobrecarregados enquanto outros ficam ociosos.
2) HA reinicia a VM em outro host após uma falha (há alguns segundos/minutos de downtime). FT mantém uma VM espelho sincronizada em tempo real em outro host — em caso de falha, o espelho assume instantaneamente sem downtime perceptível.
3) A licença do Hyper-V está incluída no Windows Server (que a empresa provavelmente já possui) — não há custo adicional de hypervisor. O VMware ESXi + vCenter têm licenças separadas e caras.
