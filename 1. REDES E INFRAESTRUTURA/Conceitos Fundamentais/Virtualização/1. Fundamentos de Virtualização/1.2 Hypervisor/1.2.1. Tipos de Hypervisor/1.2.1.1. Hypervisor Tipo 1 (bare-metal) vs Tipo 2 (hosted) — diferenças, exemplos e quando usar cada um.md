### Hypervisor Tipo 1 vs Tipo 2 — bare-metal e hosted

O hypervisor é o software que cria e gerencia máquinas virtuais. A classificação em Tipo 1 e Tipo 2 define onde ele se situa na pilha de software — diretamente no hardware ou sobre um SO hospedeiro.

---

## Hypervisor Tipo 1 — Bare-Metal

Roda **diretamente no hardware**, sem SO intermediário. É ele próprio o sistema operacional do servidor.

```
┌──────────────────────────────────────┐
│  VM 1  │  VM 2  │  VM 3  │  VM 4    │
├──────────────────────────────────────┤
│         HYPERVISOR TIPO 1            │  ← roda direto no hardware
├──────────────────────────────────────┤
│           Hardware Físico            │
└──────────────────────────────────────┘
```

**Exemplos:**
- VMware ESXi
- Microsoft Hyper-V (quando instalado standalone)
- KVM (Linux como hypervisor)
- Xen (usado pela AWS historicamente)
- Oracle VM Server

**Características:**
- **Performance máxima** — sem overhead de SO hospedeiro.
- **Segurança maior** — superfície de ataque menor.
- **Produção** — padrão em data centers e nuvens públicas.
- Gerenciado remotamente (sem teclado/monitor no servidor).

---

## Hypervisor Tipo 2 — Hosted

Roda **sobre um sistema operacional** já instalado. O SO hospedeiro gerencia o hardware; o hypervisor roda como aplicação.

```
┌──────────────────────────────────────┐
│  VM 1  │  VM 2  │  VM 3             │
├──────────────────────────────────────┤
│         HYPERVISOR TIPO 2            │  ← aplicação sobre o SO
├──────────────────────────────────────┤
│    Sistema Operacional Hospedeiro    │  ← Windows, macOS, Linux
├──────────────────────────────────────┤
│           Hardware Físico            │
└──────────────────────────────────────┘
```

**Exemplos:**
- VirtualBox (Oracle)
- VMware Workstation / Fusion
- Parallels Desktop (macOS)
- QEMU (modo user-space)

**Características:**
- **Fácil instalação** — instala como qualquer aplicativo.
- **Desenvolvedor/testes** — ideal para ambientes locais.
- **Performance menor** — duas camadas de SO.
- Compartilha recursos com o SO hospedeiro.

---

## Comparativo

| Aspecto | Tipo 1 (Bare-Metal) | Tipo 2 (Hosted) |
|---|---|---|
| Instalação | Substitui o SO | Sobre o SO existente |
| Performance | Alta (acesso direto ao HW) | Menor (overhead do SO host) |
| Uso | Produção, data center | Desenvolvimento, testes |
| Gerenciamento | Remoto (vCenter, SSH) | Interface gráfica local |
| Segurança | Maior | Menor (ataque ao SO host compromete tudo) |
| Custo | Licenças enterprise (VMware) ou free (KVM) | Geralmente free ou barato |

---

## A zona cinza — KVM

O KVM (Kernel-based Virtual Machine) é tecnicamente classificado como Tipo 1, pois o kernel Linux **se torna** o hypervisor. Mas como o Linux é um SO completo, muitos o descrevem como híbrido:

```
Linux (KVM habilitado) = SO + Hypervisor simultaneamente
  ├── Processos Linux normais rodam normalmente
  └── VMs rodam com acesso privilegiado ao hardware via kernel
```

---

## 🧩 Quiz de Fixação

1. Por que o Tipo 1 tem melhor performance que o Tipo 2?
2. Em qual cenário um desenvolvedor usaria VirtualBox em vez de ESXi?
3. O KVM é Tipo 1 ou Tipo 2? Justifique.

**Respostas:**
1) O Tipo 1 acessa o hardware diretamente, sem passar pelo SO hospedeiro — elimina uma camada de overhead e competição de recursos com outros processos.
2) Em ambiente local de desenvolvimento — VirtualBox instala sobre o SO existente (Windows/macOS/Linux) sem precisar dedicar hardware exclusivo. ESXi exigiria um servidor dedicado só para virtualização.
3) Tipo 1 tecnicamente — o módulo KVM converte o kernel Linux no hypervisor, com acesso direto ao hardware via extensões de virtualização da CPU (Intel VT-x, AMD-V). Embora o Linux seja um SO completo, o KVM opera com privilégios equivalentes ao bare-metal.
