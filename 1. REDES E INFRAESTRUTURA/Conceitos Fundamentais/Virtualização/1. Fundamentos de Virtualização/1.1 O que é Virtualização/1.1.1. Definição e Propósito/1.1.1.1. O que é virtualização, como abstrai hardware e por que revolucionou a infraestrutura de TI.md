### O que é virtualização e como abstrai o hardware

Virtualização é a tecnologia que permite criar versões lógicas (virtuais) de recursos físicos — servidores, redes, storage, sistemas operacionais. Em vez de um servidor físico rodar um único SO, ele pode rodar dezenas de ambientes isolados simultaneamente.

---

## O problema antes da virtualização

```
Era pré-virtualização (anos 90/2000):
  Servidor físico A → apenas Windows Server (uso de CPU: 5%)
  Servidor físico B → apenas Linux (uso de CPU: 8%)
  Servidor físico C → apenas banco de dados (uso de CPU: 12%)

Resultado:
  ├── Dezenas de servidores físicos subutilizados
  ├── Alto custo de hardware, energia e refrigeração
  ├── Meses para provisionar novo servidor
  └── Falha no servidor = aplicação offline
```

---

## O que a virtualização muda

```
Com virtualização:
  Servidor físico único (uso de CPU: 70%)
  ├── VM 1: Windows Server
  ├── VM 2: Linux (web server)
  ├── VM 3: Linux (banco de dados)
  ├── VM 4: Linux (cache)
  └── VM 5: Windows (aplicação legada)

Resultado:
  ├── Hardware consolidado — menos máquinas físicas
  ├── Provisionamento em minutos (não meses)
  ├── Isolamento — falha de uma VM não afeta outras
  └── Flexibilidade — move, copia, faz snapshot de VMs
```

---

## Como a abstração funciona

A virtualização insere uma camada de software (hypervisor) entre o hardware físico e os sistemas operacionais:

```
┌─────────────────────────────────────┐
│  VM 1  │  VM 2  │  VM 3  │  VM 4   │  ← SOs acham que têm hardware dedicado
├─────────────────────────────────────┤
│            HYPERVISOR               │  ← gerencia e arbitra acesso ao hardware
├─────────────────────────────────────┤
│         Hardware Físico             │  ← CPU, RAM, Disco, Rede
└─────────────────────────────────────┘
```

Cada VM recebe uma visão virtualizada de CPU, RAM, disco e rede — o SO da VM não sabe (nem precisa saber) que está virtualizado.

---

## O que pode ser virtualizado

| Recurso | Virtualização | Exemplos |
|---|---|---|
| **Servidor** | Múltiplos SOs em um hardware | VMware, KVM, Hyper-V |
| **Rede** | Switches, roteadores virtuais | VMware NSX, Open vSwitch |
| **Storage** | Pools de disco virtuais | SAN, NAS, vSAN |
| **Desktop** | VDI — desktops remotos | Citrix, VMware Horizon |
| **Aplicação** | Contêineres | Docker, containerd |

---

## Por que revolucionou a TI

- **Antes:** semanas/meses para provisionar servidor → comprar hardware, instalar, configurar.
- **Depois:** minutos para criar VM → clonar template, ajustar recursos, ligar.
- **Na nuvem:** segundos para criar instância → API call → servidor disponível.

A virtualização é a fundação técnica que tornou a computação em nuvem possível.

## 🧩 Quiz de Fixação

1. Qual problema de infraestrutura a virtualização resolve principalmente?
2. O que é o hypervisor e qual seu papel?
3. Por que a virtualização é considerada a base técnica da computação em nuvem?

**Respostas:**
1) A subutilização de hardware — servidores físicos rodando com baixa ocupação de CPU/RAM enquanto consomem energia e espaço. A virtualização consolida múltiplos workloads em menos hardware.
2) É a camada de software entre o hardware físico e as VMs — gerencia e arbitra o acesso dos SOs virtuais aos recursos físicos (CPU, RAM, disco, rede).
3) Porque permite provisionar e destruir servidores em segundos via software, escalar horizontalmente e cobrar por uso — sem virtualização, cada instância cloud exigiria hardware físico dedicado.
