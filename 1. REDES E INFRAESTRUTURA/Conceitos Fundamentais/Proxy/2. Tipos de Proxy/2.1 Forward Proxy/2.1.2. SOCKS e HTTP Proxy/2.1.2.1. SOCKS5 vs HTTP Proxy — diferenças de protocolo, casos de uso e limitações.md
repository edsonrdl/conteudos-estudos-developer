### SOCKS5 vs HTTP Proxy — diferenças de protocolo

HTTP Proxy e SOCKS são os dois protocolos de proxy mais usados em forward proxies. Diferem fundamentalmente em qual camada operam e quais tipos de tráfego conseguem encaminhar.

---

## HTTP Proxy

Projetado especificamente para tráfego HTTP/HTTPS. Entende o protocolo HTTP — pode ler, modificar e cachear as requisições.

```
Para HTTP (porta 80):
  Cliente → Proxy → GET http://site.com/pagina HTTP/1.1

Para HTTPS (porta 443) — método CONNECT:
  Cliente → Proxy: CONNECT site.com:443 HTTP/1.1
  Proxy → Cliente: 200 Connection Established
  [Túnel opaco — proxy não vê o conteúdo HTTPS]
```

**Características:**
- Entende headers HTTP — pode adicionar/remover (X-Forwarded-For, etc.).
- Cache nativo de conteúdo HTTP.
- Só funciona com HTTP/HTTPS (e protocolos que usam CONNECT).
- Autenticação via header `Proxy-Authorization`.

---

## SOCKS Proxy (SOCKS5)

Opera na camada de sessão (Layer 5) — abaixo de HTTP. É agnóstico ao protocolo: não entende o conteúdo, apenas encaminha bytes.

```
Cliente → Proxy SOCKS5: "conecte-me a 142.250.79.46:443"
Proxy → Destino: estabelece conexão TCP
Proxy ↔ Cliente: túnel bidirecional de bytes raw

O proxy não sabe (nem precisa saber) o que trafega dentro.
```

**Protocolos que o SOCKS5 encaminha:**
- HTTP e HTTPS
- SSH
- FTP
- SMTP / IMAP
- Qualquer protocolo TCP ou UDP

---

## SOCKS5 vs SOCKS4

| Versão | UDP | Autenticação | IPv6 | DNS remoto |
|---|---|---|---|---|
| SOCKS4 | Não | Não | Não | Não |
| SOCKS4a | Não | Não | Não | Sim |
| **SOCKS5** | **Sim** | **Sim** | **Sim** | **Sim** |

O SOCKS5 é o padrão atual. O suporte a DNS remoto é crítico — sem ele, o DNS é resolvido localmente, vazando informação sobre os sites acessados.

---

## Comparativo

| Aspecto | HTTP Proxy | SOCKS5 |
|---|---|---|
| Camada | Aplicação (L7) | Sessão (L5) |
| Protocolos suportados | HTTP, HTTPS | Qualquer TCP/UDP |
| Cache | Sim | Não |
| Inspeção de conteúdo | Sim (HTTP) | Não |
| Modificação de headers | Sim | Não |
| Autenticação | Via header HTTP | Nativa no protocolo |
| Overhead | Maior | Menor |
| Uso com SSH/FTP | Não | Sim |

---

## Quando usar cada um

| Cenário | Proxy recomendado |
|---|---|
| Cache e filtragem web corporativa | HTTP Proxy (Squid) |
| Tunelar qualquer protocolo | SOCKS5 |
| Privacidade geral com múltiplos apps | SOCKS5 |
| SSH over proxy | SOCKS5 |
| Inspecionar e modificar tráfego HTTP | HTTP Proxy |

## 🧩 Quiz de Fixação

1. Por que um HTTP Proxy não consegue encaminhar tráfego SSH diretamente?
2. O que é "DNS leak" e como o SOCKS5 com DNS remoto previne?
3. Para qual cenário o SOCKS5 é claramente superior ao HTTP Proxy?

**Respostas:**
1) O HTTP Proxy entende apenas HTTP/HTTPS e o método CONNECT — SSH usa um protocolo diferente que o proxy HTTP não sabe encaminhar.
2) DNS leak ocorre quando as consultas DNS são feitas localmente (revelando os domínios acessados ao ISP). SOCKS5 com DNS remoto envia as consultas pelo túnel — o DNS é resolvido pelo servidor proxy, não pelo cliente.
3) Quando se precisa tunelar protocolos além de HTTP — SSH, FTP, SMTP, jogos online — o SOCKS5 encaminha qualquer tráfego TCP/UDP sem precisar entender o protocolo.
