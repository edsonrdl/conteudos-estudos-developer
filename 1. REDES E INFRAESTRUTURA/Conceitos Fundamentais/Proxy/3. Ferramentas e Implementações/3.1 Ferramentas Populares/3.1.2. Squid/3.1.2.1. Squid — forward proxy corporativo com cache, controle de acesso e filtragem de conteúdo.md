### Squid — forward proxy corporativo

Squid é o forward proxy open source mais usado em ambientes corporativos. Combina cache HTTP, controle de acesso granular e filtragem de conteúdo — sendo a solução padrão para gerenciar e auditar o acesso à internet de funcionários.

---

## O que o Squid faz

```
[Rede interna]                              [Internet]
  PC Funcionário ──► [SQUID] ──► google.com (permitido)
  PC Funcionário ──► [SQUID] ──✗ facebook.com (bloqueado)
  PC Funcionário ──► [SQUID] ──► imagem.jpg (servida do cache)
```

**Funções principais:**
- **Cache HTTP:** armazena respostas e serve do cache — economiza banda.
- **ACLs (Access Control Lists):** define quem pode acessar o quê.
- **Autenticação:** integra com LDAP/AD para autenticar por usuário.
- **Logging:** registra todas as requisições (URL, usuário, horário, bytes).
- **SSL Bump:** inspeção de HTTPS (com CA instalada nos clientes).

---

## Configuração básica

```
# /etc/squid/squid.conf

# Porta padrão
http_port 3128

# ACLs de rede interna
acl rede_interna src 192.168.0.0/16
acl horario_comercial time MTWHF 08:00-18:00

# Listas de bloqueio
acl sites_bloqueados dstdomain "/etc/squid/blacklist.txt"
acl categorias_adulto url_regex -i adult sex porn

# Regras (processadas em ordem)
http_access deny sites_bloqueados
http_access deny categorias_adulto
http_access allow rede_interna horario_comercial
http_access deny all   # default deny

# Cache
cache_mem 256 MB
cache_dir ufs /var/spool/squid 10000 16 256   # 10GB em disco
maximum_object_size 50 MB

# Log
access_log /var/log/squid/access.log squid
```

## Autenticação integrada com Active Directory

```
# Autenticação NTLM/Kerberos com AD
auth_param ntlm program /usr/lib/squid/ntlm_auth --helper-protocol=squid-2.5-ntlmssp
auth_param ntlm children 30

acl usuarios_autenticados proxy_auth REQUIRED
http_access allow rede_interna usuarios_autenticados
```

Cada requisição é associada ao usuário do AD — os logs registram `usuario@domínio` em vez de apenas IP.

---

## SSL Bump — inspeção de HTTPS

```
# Requer CA instalada nos clientes
ssl_bump stare all        # inspeciona sem decifrar (vê SNI)
ssl_bump peek all         # vê o certificado do servidor
ssl_bump bump all         # decifra completamente (MITM)

# Exceções — não inspeciona bancos e saúde
acl no_bump dstdomain .bancobrasil.com.br .unimed.com.br
ssl_bump splice no_bump   # passa sem inspecionar
```

## Relatórios e auditoria

O log padrão do Squid (`access.log`) gera dados para ferramentas de relatório:

```
# Formato do log:
1704067200.123  245 192.168.1.50 TCP_MISS/200 15234 GET http://site.com/ usuario@empresa DIRECT/93.184.216.34 text/html

Campos: timestamp | duração(ms) | IP cliente | resultado/código | bytes | método | URL | usuário | como chegou ao destino | tipo
```

Ferramentas de relatório: **SARG**, **LightSquid**, **Calamaris**.

## 🧩 Quiz de Fixação

1. Qual a vantagem de autenticar usuários no Squid via Active Directory em vez de por IP?
2. O que é SSL Bump e por que requer uma CA instalada nos clientes?
3. Como o Squid economiza banda da empresa?

**Respostas:**
1) Permite logs e políticas por usuário — rastrear quem acessou o quê independente do IP (que pode mudar por DHCP), além de aplicar políticas diferentes por grupo do AD.
2) SSL Bump é a inspeção de HTTPS — o Squid age como MITM, decifra o tráfego, inspeciona e re-cifra. Requer que os clientes confiem na CA do Squid para não receberem alerta de certificado inválido.
3) Armazenando em cache as respostas HTTP — quando múltiplos funcionários acessam o mesmo recurso (ex.: Windows Update, repositórios de pacotes, imagens populares), o Squid serve do cache local sem buscar novamente na internet.
