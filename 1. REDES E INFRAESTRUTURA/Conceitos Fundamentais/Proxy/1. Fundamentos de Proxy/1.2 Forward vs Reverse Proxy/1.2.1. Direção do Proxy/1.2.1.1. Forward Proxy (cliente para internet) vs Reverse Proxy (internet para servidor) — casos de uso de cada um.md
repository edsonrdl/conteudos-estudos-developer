### Forward Proxy vs Reverse Proxy — direção e casos de uso

A distinção mais fundamental entre tipos de proxy é a **direção** em que ele atua. O forward proxy serve os clientes; o reverse proxy serve os servidores. São soluções para problemas opostos.

---

## Forward Proxy — proxy do cliente

O forward proxy fica entre os **clientes e a internet**. O cliente o configura explicitamente (ou é interceptado por ele) para acessar recursos externos.

```
[Clientes internos]
   ├── PC 1 ─┐
   ├── PC 2 ─┼──► [FORWARD PROXY] ──► Internet
   └── PC 3 ─┘

Quem configura: o cliente (ou a rede)
Quem ele protege/serve: os clientes
O servidor externo vê: o IP do proxy
```

**Casos de uso:**
- Controle de acesso à internet em empresas (bloquear redes sociais, etc.)
- Cache de conteúdo (economiza banda quando vários clientes acessam o mesmo recurso)
- Anonimização de IP do cliente
- Bypass de restrições geográficas

---

## Reverse Proxy — proxy do servidor

O reverse proxy fica entre a **internet e os servidores**. O cliente não sabe que existe — acha que está falando diretamente com o servidor.

```
Internet
   ├── User 1 ─┐
   ├── User 2 ─┼──► [REVERSE PROXY] ──► Servidor A
   └── User 3 ─┘                    └──► Servidor B
                                     └──► Servidor C

Quem configura: a equipe de infraestrutura
Quem ele protege/serve: os servidores
O cliente vê: apenas o IP do reverse proxy
```

**Casos de uso:**
- Load balancing entre múltiplos servidores
- Terminação SSL/TLS (centraliza certificados)
- Cache de conteúdo estático
- Proteção contra DDoS (absorve e filtra)
- API Gateway

---

## Comparativo direto

| Aspecto | Forward Proxy | Reverse Proxy |
|---|---|---|
| Posição | Entre cliente e internet | Entre internet e servidores |
| Configurado por | Cliente / administrador de rede | Equipe de infra/servidores |
| Oculta | IP do cliente | IP/quantidade de servidores |
| Serve | Os clientes | Os servidores |
| Exemplos | Squid, Privoxy, Tor | Nginx, HAProxy, Cloudflare |

---

## O mesmo software, dois papéis

O Nginx, por exemplo, pode atuar como:
- **Forward proxy:** com módulo `ngx_http_proxy_module` e configuração de CONNECT.
- **Reverse proxy:** configuração padrão mais comum — recebe requisições e encaminha para backends.

## 🧩 Quiz de Fixação

1. Em qual cenário um administrador usaria forward proxy em vez de reverse proxy?
2. O reverse proxy oculta o IP de quem — do cliente ou do servidor?
3. Um usuário acessa `api.empresa.com` que usa Nginx como reverse proxy com 3 servidores backend. O usuário consegue descobrir quantos servidores existem?

**Respostas:**
1) Quando quer controlar/monitorar o acesso dos clientes internos à internet — o forward proxy fica no caminho de saída da rede.
2) Do servidor (ou servidores) — os clientes veem apenas o IP do reverse proxy, não sabem quantos ou quais servidores existem atrás.
3) Não diretamente — o reverse proxy é o único ponto de contato; os servidores backend ficam em rede privada, inacessíveis diretamente da internet.
