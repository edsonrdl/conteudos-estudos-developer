### DNS Spoofing, DNS Hijacking e DNSSEC

O DNS foi projetado originalmente sem mecanismos de autenticação — qualquer resposta que chegasse primeiro era aceita. Isso criou vetores de ataque explorados até hoje. O DNSSEC é a principal resposta técnica a esses problemas.

---

## DNS Spoofing (Cache Poisoning)

O atacante injeta registros falsos no cache de um resolver recursivo. Após a contaminação, todos os clientes daquele resolver recebem IPs falsos.

```
Ataque Kaminsky (2008):
1. Atacante força o resolver a consultar domínio sob controle do atacante
2. Enquanto o resolver aguarda, o atacante envia milhares de respostas falsas
   com IDs de transação diferentes tentando acertar o ID legítimo
3. Se acertar, injeta registro falso no cache
4. Todos os clientes do resolver são redirecionados para IP malicioso
```

**Mitigações:**
- Randomização da porta de origem (port randomization)
- DNSSEC (valida criptograficamente as respostas)
- DNS over HTTPS/TLS (DoH/DoT) — criptografa o canal

---

## DNS Hijacking

Diferente do spoofing (ataque ao cache), o hijacking compromete o próprio domínio ou a infraestrutura DNS:

| Tipo | Como ocorre |
|---|---|
| **Hijacking de registrar** | Credenciais do registrar comprometidas; NS alterado |
| **BGP hijacking + DNS** | Roteamento desviado para AS malicioso |
| **Resolver comprometido** | ISP ou resolver público alterado pelo atacante |
| **Malware local** | hosts file ou configuração de DNS local alterada |

---

## DNSSEC — DNS Security Extensions

O DNSSEC adiciona assinaturas criptográficas aos registros DNS, permitindo que o resolver verifique a autenticidade da resposta.

```
Cadeia de confiança:
Root (.) → assina chave do TLD .com
TLD .com → assina chave de empresa.com
empresa.com → assina seus próprios registros A, MX, etc.
```

### Registros do DNSSEC

| Registro | Função |
|---|---|
| `DNSKEY` | Chave pública da zona |
| `RRSIG` | Assinatura criptográfica dos registros |
| `DS` | Hash da chave filho publicado na zona pai (elo da cadeia) |
| `NSEC/NSEC3` | Prova que um nome **não existe** (authenticated denial) |

### Limitações do DNSSEC

- Não criptografa o tráfego (apenas autentica) — o conteúdo ainda é visível.
- Adoção parcial: muitos domínios ainda não têm DNSSEC configurado.
- Aumenta o tamanho das respostas DNS.
- Para privacidade do canal, use **DoH** (DNS over HTTPS) ou **DoT** (DNS over TLS).

## 🧩 Quiz de Fixação

1. Qual a diferença entre DNS Spoofing e DNS Hijacking?
2. O DNSSEC protege a privacidade das consultas DNS? Por quê?
3. O que é a cadeia de confiança do DNSSEC?

**Respostas:**
1) Spoofing contamina o cache de um resolver com respostas falsas; Hijacking compromete o domínio ou infraestrutura DNS diretamente (ex.: altera NS no registrar).
2) Não — o DNSSEC autentica (garante que a resposta não foi adulterada) mas não criptografa. Para privacidade use DoH ou DoT.
3) É a sequência de assinaturas que parte da raiz (.) confiada pelos resolvers, passa pelos TLDs e chega até o domínio final — cada nível assina a chave do próximo, criando uma cadeia verificável.
