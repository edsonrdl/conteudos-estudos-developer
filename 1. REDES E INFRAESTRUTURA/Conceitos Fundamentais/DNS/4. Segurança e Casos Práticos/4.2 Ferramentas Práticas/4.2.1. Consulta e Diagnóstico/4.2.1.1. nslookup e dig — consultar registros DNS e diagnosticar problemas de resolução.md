### nslookup e dig — consultar registros DNS e diagnosticar problemas

`nslookup` e `dig` são as ferramentas de linha de comando para inspecionar registros DNS diretamente. Essenciais para diagnosticar problemas de resolução, verificar propagação de mudanças e depurar configurações.

---

## nslookup

Disponível em Windows, Linux e macOS. Interface interativa ou por argumento.

### Consultas básicas

```bash
# Consulta padrão (registro A)
nslookup google.com

# Consulta um tipo específico
nslookup -type=MX gmail.com
nslookup -type=TXT empresa.com
nslookup -type=NS empresa.com

# Consulta usando servidor DNS específico (bypass do resolver padrão)
nslookup google.com 8.8.8.8
```

### Saída típica

```
Server:  8.8.8.8          ← resolver usado
Address: 8.8.8.8#53

Non-authoritative answer:  ← resposta do cache (não do servidor autoritativo)
Name:    google.com
Address: 142.250.79.46
```

"Non-authoritative" significa que a resposta veio do cache do resolver, não diretamente do servidor autoritativo do domínio.

---

## dig (Domain Information Groper)

Mais poderoso que nslookup. Padrão em Linux/macOS; disponível no Windows via instalação.

### Consultas básicas

```bash
# Consulta padrão
dig google.com

# Tipo específico
dig MX gmail.com
dig TXT empresa.com
dig NS empresa.com

# Usando servidor específico
dig @8.8.8.8 google.com

# Resposta curta (só o resultado)
dig +short google.com

# Rastrear toda a cadeia de resolução
dig +trace google.com
```

### Saída do dig

```
;; QUESTION SECTION:
;google.com.    IN    A

;; ANSWER SECTION:
google.com.    300    IN    A    142.250.79.46

;; Query time: 12 msec
;; SERVER: 8.8.8.8#53
;; MSG SIZE rcvd: 55
```

---

## dig +trace — seguindo a hierarquia

O `+trace` faz o dig percorrer toda a hierarquia como um resolver recursivo faria, mostrando cada passo:

```bash
dig +trace www.empresa.com
# Mostra: Root → TLD .com → NS de empresa.com → resposta final
```

Útil para diagnosticar onde na cadeia a resolução falha ou retorna resultado incorreto.

---

## Casos de uso práticos

| Situação | Comando |
|---|---|
| Verificar IP atual de um domínio | `dig +short meusite.com` |
| Confirmar MX após configurar e-mail | `dig MX empresa.com` |
| Testar propagação de DNS | `dig @ns1.cloudflare.com meusite.com` |
| Verificar TTL atual | `dig meusite.com` (coluna TTL na ANSWER SECTION) |
| Rastrear falha de resolução | `dig +trace dominio-com-problema.com` |

## 🧩 Quiz de Fixação

1. O que significa "Non-authoritative answer" na saída do nslookup?
2. Como usar o dig para consultar o registro MX de `empresa.com` diretamente no servidor `ns1.cloudflare.com`?
3. Para que serve o `dig +trace`?

**Respostas:**
1) A resposta veio do cache do resolver, não diretamente do servidor autoritativo do domínio.
2) `dig @ns1.cloudflare.com MX empresa.com`
3) Percorre toda a hierarquia DNS (Root → TLD → Autoritativo) mostrando cada passo — útil para identificar onde a resolução falha ou retorna dados incorretos.
