### Como o resolver recursivo percorre a hierarquia DNS

A resolução de um nome como `www.google.com` envolve múltiplos servidores trabalhando em conjunto. Entender esse processo explica por que o DNS é rápido, distribuído e resiliente.

---

## Os atores do processo

| Ator | Papel |
|---|---|
| **Stub resolver** | Biblioteca no SO do cliente — faz a consulta ao resolver recursivo |
| **Resolver recursivo** | Servidor do ISP ou público (8.8.8.8, 1.1.1.1) — faz o trabalho pesado |
| **Servidores raiz** | Conhecem os servidores TLD |
| **Servidores TLD** | Conhecem os servidores NS dos domínios |
| **Servidor autoritativo** | Tem a resposta final do domínio |

---

## Resolução Recursiva (do ponto de vista do cliente)

O cliente pergunta uma vez ao resolver recursivo e **espera a resposta final**. O resolver faz todo o trabalho:

```
Cliente → Resolver: "Qual o IP de www.google.com?"
                              ↓
         Resolver → Root: "Quem cuida de .com?"
         Root → Resolver: "ns1.gtld-servers.net"
                              ↓
         Resolver → TLD .com: "Quem cuida de google.com?"
         TLD → Resolver: "ns1.google.com"
                              ↓
         Resolver → ns1.google.com: "Qual o IP de www.google.com?"
         ns1.google.com → Resolver: "142.250.79.46"
                              ↓
Resolver → Cliente: "142.250.79.46" ✓
```

---

## Resolução Iterativa (o que o resolver faz internamente)

Em cada passo, o servidor consultado **não resolve o nome completo** — ele aponta para quem pode ajudar mais. O resolver vai de servidor em servidor até encontrar a resposta autoritativa.

---

## Por que o resolver recursivo é rápido na prática

O resolver usa **cache**: se já resolveu `google.com` recentemente, retorna o resultado em cache sem percorrer toda a hierarquia. O TTL do registro controla por quanto tempo a resposta é reutilizável.

```
Cache hit: cliente recebe resposta em < 1ms
Cache miss: percorre Root → TLD → Autoritativo (~50–200ms)
```

---

## 🧩 Quiz de Fixação

1. Qual a diferença entre resolução recursiva e iterativa?
2. Quem normalmente opera o resolver recursivo que seu computador usa?
3. Por que a maioria das consultas DNS é muito mais rápida do que percorrer toda a hierarquia?

**Respostas:**
1) Recursiva: o resolver faz todo o trabalho e retorna a resposta final ao cliente. Iterativa: cada servidor retorna uma referência ao próximo — o resolver percorre os passos manualmente.
2) O ISP do usuário, ou resolvers públicos como Google (8.8.8.8) e Cloudflare (1.1.1.1) se configurado manualmente.
3) O cache no resolver armazena respostas anteriores pelo tempo do TTL, evitando percorrer a hierarquia a cada consulta.
