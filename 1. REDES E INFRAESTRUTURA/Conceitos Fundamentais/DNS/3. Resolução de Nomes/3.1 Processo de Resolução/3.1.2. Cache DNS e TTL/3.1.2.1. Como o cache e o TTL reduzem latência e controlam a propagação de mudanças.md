### Cache DNS e TTL — latência e propagação de mudanças

O cache é o que torna o DNS viável em escala global. Sem ele, cada consulta percorreria toda a hierarquia. O TTL é o mecanismo que controla por quanto tempo uma resposta pode ser reutilizada.

---

## O que é TTL

TTL (Time To Live) é um valor em segundos definido em cada registro DNS que indica por quanto tempo resolvers e clientes podem armazenar a resposta em cache.

```
google.com.    300    IN    A    142.250.79.46
               ↑
           TTL = 300 segundos (5 minutos)
```

Após 300 segundos, o cache expira e uma nova consulta é necessária.

---

## Onde o cache existe

| Nível | Onde | Escopo |
|---|---|---|
| SO / Stub resolver | Máquina local | Só o próprio computador |
| Resolver recursivo | ISP / 8.8.8.8 / 1.1.1.1 | Todos os clientes daquele resolver |
| Navegador | Chrome, Firefox | Só aquela sessão do browser |

---

## TTL e propagação de mudanças

Quando você altera um registro DNS (ex.: muda o IP de um servidor), a mudança **não é imediata** — clientes que têm o valor antigo em cache continuarão usando-o até o TTL expirar.

### Estratégia para migrações sem downtime

```
Antes da migração:
  meusite.com    TTL=86400    A    203.0.113.10   (TTL alto = 24h)

72h antes:
  meusite.com    TTL=300      A    203.0.113.10   (reduz TTL para 5min)

Na migração:
  meusite.com    TTL=300      A    198.51.100.20  (troca o IP)

Após estabilizar:
  meusite.com    TTL=86400    A    198.51.100.20  (restaura TTL alto)
```

Reduzir o TTL antes da mudança garante que o cache expira rapidamente e os clientes pegam o novo valor logo.

---

## TTL alto vs TTL baixo

| | TTL Alto (ex.: 86400) | TTL Baixo (ex.: 60) |
|---|---|---|
| Latência | Menor (mais cache hits) | Maior (mais consultas) |
| Propagação | Lenta (até 24h) | Rápida (1 minuto) |
| Carga nos servidores | Menor | Maior |
| Uso ideal | Registros estáveis | Failover, migrações |

---

## Negative caching

Se um domínio não existe (NXDOMAIN), o resolver também armazena essa resposta negativa pelo tempo definido no campo **Minimum TTL** do SOA. Isso evita que consultas por domínios inexistentes sobrecarreguem os servidores.

---

## 🧩 Quiz de Fixação

1. Um registro tem TTL de 3600. Você altera o IP agora. Em quanto tempo todos os clientes verão a mudança?
2. Por que reduzir o TTL antes de uma migração é uma boa prática?
3. O que é negative caching e por que é útil?

**Respostas:**
1) Até 3600 segundos (1 hora) — clientes que cachearam agora mesmo só buscarão o novo valor depois de 1h.
2) Porque ao reduzir o TTL antecipadamente, quando a mudança ocorrer, os caches expirarão muito mais rápido — minimizando o tempo em que clientes apontam para o destino antigo.
3) É o cache de respostas negativas (domínio não existe). Evita que consultas repetidas por nomes inválidos sobrecarreguem os servidores autoritativos.
