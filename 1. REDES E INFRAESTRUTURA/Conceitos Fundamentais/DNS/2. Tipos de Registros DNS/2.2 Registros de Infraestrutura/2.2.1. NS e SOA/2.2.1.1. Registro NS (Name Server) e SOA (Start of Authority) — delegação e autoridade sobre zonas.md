### Registros NS e SOA — delegação e autoridade sobre zonas

NS e SOA são os registros que definem a estrutura administrativa do DNS. Enquanto o NS diz "quem responde por este domínio", o SOA contém metadados sobre a própria zona DNS.

---

## Registro NS — Name Server

O NS indica quais servidores são autoritativos para um domínio. Quando você registra um domínio, você configura os NS no registrar — isso é a **delegação**.

```
empresa.com.    IN    NS    ns1.cloudflare.com.
empresa.com.    IN    NS    ns2.cloudflare.com.
```

- Sempre há **pelo menos 2 registros NS** para redundância.
- O destino deve ser um nome com registro A/AAAA (nunca um CNAME).
- Os NS são o que o servidor TLD retorna quando você consulta um domínio.

### Fluxo de delegação

```
Root "." → "consulte o TLD .com"
TLD .com → "consulte ns1.cloudflare.com para empresa.com"
ns1.cloudflare.com → responde com o registro A final
```

---

## Registro SOA — Start of Authority

Existe **um único registro SOA** por zona. Ele define os parâmetros de controle da zona:

```
empresa.com.    IN    SOA    ns1.cloudflare.com. admin.empresa.com. (
    2024010101  ; Serial — versão da zona
    3600        ; Refresh — frequência que secondários buscam updates (segundos)
    900         ; Retry — intervalo de retry se refresh falhar
    604800      ; Expire — quanto tempo manter dados sem conseguir refresh
    300         ; Minimum TTL — TTL padrão para respostas negativas (NXDOMAIN)
)
```

| Campo | Função |
|---|---|
| `MNAME` | Servidor NS primário |
| `RNAME` | E-mail do admin (`.` no lugar de `@`) |
| `Serial` | Incrementado a cada mudança; secondários comparam para saber se precisam atualizar |
| `Refresh` | Com que frequência os secondários verificam updates |
| `Expire` | Quanto tempo dados ficam válidos se o primário sumir |

---

## A relação entre NS e SOA

- O NS define **quem serve** a zona (visto de fora).
- O SOA define **como a zona é gerenciada** (configuração interna da zona).
- O `MNAME` do SOA deve coincidir com um dos registros NS.

---

## 🧩 Quiz de Fixação

1. O que acontece se você alterar os registros NS de um domínio no registrar?
2. Por que o campo Serial do SOA é importante para servidores secondários?
3. Um domínio pode ter zero registros NS? E zero registros SOA?

**Respostas:**
1) O registrar atualiza os NS no servidor TLD — a delegação muda e o tráfego DNS passa a ser respondido pelos novos servidores (propagação pode levar até 48h).
2) Servidores secondários comparam o serial com o que têm; se o serial aumentou, buscam a versão atualizada da zona.
3) Não — toda zona DNS válida deve ter pelo menos dois NS e exatamente um SOA; são obrigatórios pela RFC.
