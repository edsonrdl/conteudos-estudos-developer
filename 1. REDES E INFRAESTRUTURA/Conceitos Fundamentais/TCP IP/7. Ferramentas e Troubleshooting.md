Saber a teoria do TCP/IP é metade do caminho. A outra metade é saber **diagnosticar problemas em tempo real**. O sistema operacional oferece ferramentas nativas que permitem verificar conectividade, rastrear rotas, inspecionar conexões ativas e capturar tráfego.

---

### 🔹 4.1.1 Ping — Teste de Alcançabilidade

O `ping` usa o protocolo **ICMP (Echo Request/Reply)** para verificar se um host está acessível e medir o tempo de resposta (RTT — Round Trip Time).

```bash
ping google.com

# Saída:
64 bytes from 142.250.79.14: icmp_seq=1 ttl=116 time=14.5 ms
64 bytes from 142.250.79.14: icmp_seq=2 ttl=116 time=14.2 ms

# 2 packets transmitted, 2 received, 0% packet loss
# rtt min/avg/max = 14.2/14.3/14.5 ms
```

**O que observar:**
- **time** — latência em ms. Acima de 200ms já é perceptível em aplicações
- **packet loss** — qualquer percentual indica problema na rota
- **TTL** — tempo de vida do pacote; decrementado a cada roteador

**Erros comuns:**
| Mensagem | Causa provável |
|---|---|
| `Request timeout` | Firewall bloqueando ou host offline |
| `Destination host unreachable` | Problema de roteamento local |
| `Network unreachable` | Sem rota para o destino |

### 🔹 4.1.2 TraceRoute — Mapeando o Caminho

O `traceroute` revela **cada roteador (hop)** no caminho entre origem e destino. Funciona enviando pacotes com TTL crescente (1, 2, 3...) — cada roteador que descarta o pacote ao zerar o TTL responde identificando a si mesmo.

```bash
# Linux / macOS
traceroute google.com

# Windows
tracert google.com

# Saída:
 1  192.168.1.1 (gateway)        1.2 ms
 2  10.0.0.1                     8.5 ms
 3  * * *                        (firewall bloqueando ICMP)
 4  72.14.238.100                22.1 ms
 5  142.250.79.14 (google.com)   24.3 ms
```

**Lendo a saída:**
- Cada linha é um roteador no caminho
- `* * *` significa que o roteador não respondeu (comum em firewalls)
- Latência crescente é normal; um salto com latência muito maior indica gargalo

### 🔹 4.1.3 Netstat e SS — Inspecionando Conexões

O `netstat` (ou o mais moderno `ss`) lista portas abertas, conexões ativas e estatísticas do protocolo.

```bash
# Ver portas em escuta
ss -tulnp
# -t TCP  -u UDP  -l listening  -n numérico  -p processo

# Ver conexões estabelecidas
ss -tnp | grep ESTAB

# Ver todas as conexões TCP
netstat -tan

# Saída exemplo:
# Proto  Local Address       Foreign Address     State
# tcp    0.0.0.0:80          0.0.0.0:*           LISTEN
# tcp    192.168.1.10:52341  93.184.216.34:443   ESTABLISHED
```

**Estados TCP mais importantes:**

| Estado | Significado |
|---|---|
| `LISTEN` | Aguardando conexões |
| `ESTABLISHED` | Conexão ativa |
| `TIME_WAIT` | Aguardando timeout após fechar |
| `CLOSE_WAIT` | Aguardando a aplicação fechar |

### 🔹 4.1.4 Wireshark — Inspeção Profunda de Pacotes

O **Wireshark** é um analisador de protocolos que captura e decodifica todo o tráfego de rede em tempo real. Indispensável para diagnosticar problemas que as outras ferramentas não revelam.

**Filtros mais úteis:**

```
# Ver apenas tráfego HTTP
http

# Ver handshake TCP (SYN)
tcp.flags.syn == 1

# Ver retransmissões (indica perda de pacotes)
tcp.analysis.retransmission

# Ver tráfego de um IP específico
ip.addr == 192.168.1.10

# Ver tráfego em uma porta
tcp.port == 443
```

**O que cada painel mostra:**
- **Packet List** — lista de todos os pacotes capturados
- **Packet Details** — decodificação camada por camada
- **Packet Bytes** — representação hexadecimal bruta

### 🔹 4.1.5 Metodologia — Como Diagnosticar em Camadas

Quando há um problema de rede, a abordagem mais eficiente é **descer pelas camadas**, partindo da mais básica:

```
1. Física:     cabo conectado? interface ativa?     → ip link show
2. Rede:       IP configurado? rota existe?         → ip addr / ip route
3. Conectividade local:  gateway responde?          → ping 192.168.1.1
4. Conectividade externa: internet acessível?      → ping 8.8.8.8
5. DNS:        resolução funcionando?               → nslookup google.com
6. Transporte: porta do serviço aberta?             → ss -tulnp
7. Aplicação:  serviço respondendo?                 → curl -v http://...
```

1. Qual protocolo o `ping` usa para testar conectividade?
2. O que significa `* * *` na saída do `traceroute`?
3. Qual comando mostra as portas em escuta no sistema junto com o processo que as abriu?

**Respostas:** 1) ICMP (Echo Request / Echo Reply), 2) O roteador naquele hop não respondeu, geralmente por firewall bloqueando ICMP, 3) `ss -tulnp` ou `netstat -tulnp`.
