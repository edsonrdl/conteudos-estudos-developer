### O que é uma Sub-rede e como funciona a segmentação

Uma sub-rede é uma segmentação **lógica** da rede física. O mecanismo que torna essa divisão possível é a **Máscara de Sub-rede** — ela diz ao roteador quais partes do endereço IP identificam a rede e quais identificam o host.

- Se você tem uma rede principal `/24` e vê um endereço com máscara `/25` ou `/26`, você está olhando para uma **sub-rede** dessa rede maior.

| Característica | Rede Principal | Sub-rede |
| -------------- | -------------- | -------- |
| **Endereço** | `192.168.1.0` | `192.168.1.0` ou `192.168.1.128` |
| **Máscara** | `/24` (255.255.255.0) | `/25` (255.255.255.128) |
| **Capacidade** | 256 endereços totais | 128 endereços totais |
| **Conceito** | O bloco original completo | Um pedaço do bloco original |

---

## O Problema do Broadcast

Quando um dispositivo precisa falar com todos na rede (ex: ARP — "quem tem esse IP?"), ele envia um **pacote de broadcast** para o endereço final da sub-rede (ex: `192.168.1.255`).

Todo dispositivo naquela rede precisa **parar e processar** esse pacote — mesmo que não seja o destinatário.

**O problema:** em uma rede plana com 500 dispositivos, cada broadcast interrompe todos os 500. Com tráfego intenso de ARP, DHCP e outros protocolos, isso degrada a performance.

**A solução:** dividir em sub-redes menores. Um broadcast em `192.168.1.0/26` (62 hosts) só interrompe aqueles 62 — não os dispositivos em `192.168.1.64/26`.

---

## O Problema de Segurança

Em uma rede plana, todos os dispositivos estão no mesmo segmento L2 — um atacante com acesso a qualquer ponto pode usar ARP spoofing para interceptar tráfego de qualquer outro dispositivo da rede.

**Segmentação como defesa:**

| Segmento | Conteúdo | Regra de isolamento |
| -------- | -------- | ------------------- |
| `10.0.1.0/24` | Servidores de produção | Sem acesso direto de usuários |
| `10.0.2.0/24` | Estações de trabalho | Acesso limitado a servidores |
| `10.0.3.0/24` | DMZ (serviços públicos) | Isolada da rede interna |
| `10.0.4.0/24` | Câmeras / IoT | Sem acesso a outros segmentos |

Cada segmento é um **domínio de broadcast independente**. Para comunicar entre eles, o tráfego precisa passar por um roteador ou firewall — que pode inspecionar e filtrar.

## Endereços Reservados em cada Sub-rede

Em toda sub-rede, dois endereços são sempre reservados e não podem ser atribuídos a hosts:

| Endereço | Nome | Função |
| -------- | ---- | ------- |
| Primeiro (todos os bits de host = 0) | **Network Address** | Identifica a sub-rede nas tabelas de roteamento |
| Último (todos os bits de host = 1) | **Broadcast Address** | Entrega mensagens para todos os hosts da sub-rede |

**Exemplo em `192.168.1.0/24`:**
- `192.168.1.0` → Network Address (não atribuível)
- `192.168.1.255` → Broadcast (não atribuível)
- `192.168.1.1` a `192.168.1.254` → 254 hosts utilizáveis

> **Na cloud (AWS/Azure) são reservados 5 IPs por sub-rede** — os 4 primeiros e o último. Isso impacta o planejamento de capacidade em clusters Kubernetes. Ver: [[IPs Reservados]]
