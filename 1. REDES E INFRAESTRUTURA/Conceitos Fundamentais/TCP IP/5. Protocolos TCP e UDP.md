O modelo TCP/IP utiliza dois protocolos principais na camada de transporte: **TCP**, que garante entrega confiável e ordenada, e **UDP**, que prioriza velocidade sem verificação de entrega. A escolha entre eles define o comportamento de toda a comunicação da aplicação.

---

### 🔹 3.1.1 TCP — Transmission Control Protocol

O TCP é **orientado à conexão**: antes de transmitir qualquer dado, os dois lados precisam se sincronizar via handshake. Isso garante que os dados cheguem completos, em ordem e sem duplicatas.

**Características principais:**

| Característica | Descrição |
|---|---|
| Orientado à conexão | Requer handshake antes de transmitir |
| Entrega garantida | Retransmite pacotes perdidos |
| Ordenação | Reordena pacotes fora de sequência |
| Controle de fluxo | Ajusta velocidade ao receptor |
| Controle de congestionamento | Evita saturar a rede |

**Three-Way Handshake (como a conexão é estabelecida):**

```
Cliente          Servidor
   |  — SYN —>     |   "Quero me conectar"
   |  <— SYN-ACK — |   "Pode vir, estou pronto"
   |  — ACK —>     |   "Confirmado, iniciando"
   |   CONECTADO   |
```

**Quando usar TCP:**
- Transferência de arquivos (FTP, SFTP)
- Navegação web (HTTP/HTTPS)
- Acesso remoto (SSH)
- Bancos de dados
- Email (SMTP, IMAP)

---

### 🔹 3.1.2 UDP — User Datagram Protocol

O UDP é **sem conexão**: os dados são enviados diretamente, sem handshake, sem confirmação de entrega e sem reordenação. O que se ganha é velocidade e baixa latência.

**Características principais:**

| Característica | Descrição |
|---|---|
| Sem conexão | Envia sem estabelecer sessão |
| Sem garantia de entrega | Pacotes podem se perder |
| Sem ordenação | Pacotes podem chegar fora de ordem |
| Baixa latência | Sem overhead de controle |
| Cabeçalho menor | Apenas 8 bytes vs 20 bytes do TCP |

**Analogia:** UDP é como enviar um cartão postal — você escreve, envia e não sabe se chegou. TCP é como uma ligação telefônica confirmada — você sabe que o outro lado está ouvindo.

**Quando usar UDP:**
- Streaming de vídeo e áudio (YouTube, Netflix)
- Chamadas de voz e vídeo (VoIP, WebRTC)
- Jogos online (latência é mais crítica que perda)
- DNS (consultas rápidas e simples)
- DHCP

---

### 🔹 3.1.3 Comparativo e Decisão

```
                     TCP              UDP
Conexão          Orientado         Sem conexão
Confiabilidade   Garantida         Melhor esforço
Ordenação        Sim               Não
Velocidade       Mais lento        Mais rápido
Overhead         Alto (20+ bytes)  Baixo (8 bytes)
Uso              Dados críticos    Tempo real
```

**Regra prática:**
- Dados que **não podem ser perdidos** → TCP
- Dados onde **velocidade importa mais que perfeição** → UDP
