Para que múltiplas aplicações no mesmo dispositivo possam se comunicar pela rede simultaneamente, o TCP/IP usa **portas** para identificar cada serviço e **sockets** para representar cada conexão individual. São os mecanismos que permitem ao sistema operacional entregar os dados à aplicação certa.

---

### 🔹 3.2.1 Portas — Well-Known Ports

Uma **porta** é um número de 16 bits (0 a 65535) que identifica um serviço ou aplicação específica dentro de um dispositivo. O endereço IP leva o pacote até a máquina; a porta entrega ao processo correto.

**Faixas de portas:**

| Faixa | Nome | Uso |
|---|---|---|
| 0 – 1023 | Well-Known Ports | Serviços padronizados (HTTP, SSH, DNS) |
| 1024 – 49151 | Registered Ports | Aplicações conhecidas (PostgreSQL, Redis) |
| 49152 – 65535 | Dynamic / Ephemeral | Portas temporárias criadas pelo SO para conexões de saída |

**Portas mais importantes:**

| Porta | Protocolo | Serviço |
|---|---|---|
| 20 / 21 | TCP | FTP (dados / controle) |
| 22 | TCP | SSH |
| 25 | TCP | SMTP |
| 53 | TCP/UDP | DNS |
| 80 | TCP | HTTP |
| 110 | TCP | POP3 |
| 143 | TCP | IMAP |
| 443 | TCP | HTTPS |
| 3306 | TCP | MySQL |
| 5432 | TCP | PostgreSQL |
| 6379 | TCP | Redis |
| 27017 | TCP | MongoDB |

### 🔹 3.2.2 Sockets — Como o SO Gerencia Conexões

Um **socket** é a combinação de **IP + Porta** que forma o endereço completo de um endpoint de comunicação. Uma conexão TCP é identificada por 4 elementos:

```
[ IP origem : Porta origem ]  ←→  [ IP destino : Porta destino ]

Exemplo:
192.168.1.10:52341  ←→  93.184.216.34:443
(cliente)                  (servidor HTTPS)
```

Isso significa que o mesmo servidor na porta 443 pode atender milhares de conexões simultâneas, pois cada uma tem uma porta efêmera diferente no lado do cliente.

**Como o SO multiplexar conexões:**

1. Cliente cria socket com porta efêmera aleatória (ex: 52341)
2. Conecta ao servidor no IP + porta do serviço
3. SO registra a tupla de 4 elementos na tabela de conexões
4. Cada pacote recebido é roteado ao processo correto pela tabela

### 🔹 3.2.3 Visualizando na prática

**Ver portas em escuta:**
```bash
# Linux
ss -tulnp

# Saída exemplo:
# Proto  Local Address    State   PID/Program
# tcp    0.0.0.0:80      LISTEN  1234/nginx
# tcp    0.0.0.0:443     LISTEN  1234/nginx
# tcp    127.0.0.1:5432  LISTEN  5678/postgres
```

**Ver conexões estabelecidas:**
```bash
ss -tnp | grep ESTABLISHED
# tcp  192.168.1.10:52341  93.184.216.34:443  ESTABLISHED
```

### 🧩 Quiz de Fixação

1. Qual a faixa de portas Well-Known e quem as define?
2. Um servidor web recebe 1000 conexões simultâneas na porta 443. Como o SO distingue cada conexão?
3. O que forma um socket?

**Respostas:** 1) Portas 0–1023, definidas pela IANA, 2) Pela tupla de 4 elementos: IP/porta de origem + IP/porta de destino — cada cliente usa uma porta efêmera diferente, 3) A combinação de endereço IP e número de porta.
