### TCP vs UDP — Comparativo direto

```
                     TCP                    UDP
Conexão          Orientado (handshake)   Sem conexão
Confiabilidade   Garantida               Melhor esforço
Ordenação        Sim                     Não
Retransmissão    Automática              Não existe
Controle de fluxo Sim (sliding window)  Não
Overhead         20–60 bytes/segmento   8 bytes/datagrama
Velocidade       Mais lento             Mais rápido
Latência         Maior                  Menor
```

---

## A Regra de Decisão

**Use TCP quando:**
- A perda de qualquer parte dos dados invalida o resultado
- A ordem dos dados importa (ex: bytes de um arquivo devem chegar na sequência certa)
- O receptor precisa confirmar que recebeu tudo

**Use UDP quando:**
- Velocidade e latência são mais críticos que perfeição
- Dados ficam obsoletos rapidamente (posição em um jogo, frame de vídeo)
- A aplicação prefere gerenciar a confiabilidade por conta própria (QUIC, WebRTC)
- São operações stateless e simples (DNS, DHCP, SNMP)

---

## Casos de uso reais

| Protocolo de Aplicação | Camada de Transporte | Razão |
| ---------------------- | -------------------- | ----- |
| HTTP/HTTPS | TCP 80/443 | Páginas e APIs não podem ter bytes faltando |
| SSH | TCP 22 | Corrupção de bytes no terminal é inaceitável |
| FTP | TCP 20/21 | Arquivos corrompidos são inúteis |
| SMTP/IMAP | TCP 25/143 | Emails não podem chegar incompletos |
| DNS | **UDP 53** (TCP fallback para respostas grandes) | Consultas rápidas — retenta se não responder |
| DHCP | **UDP 67/68** | Broadcast — não há conexão possível antes de ter IP |
| VoIP / RTP | **UDP** | Latência importa; um pacote de voz perdido é inaudível |
| Streaming (RTSP) | **UDP** | Frame perdido é preferível a frame atrasado |
| HTTP/3 (QUIC) | **UDP** | Controle próprio de confiabilidade, sem head-of-line blocking |
| NFS | **UDP** (versões antigas) / TCP (moderno) | Historicamente UDP para performance em LAN |
| TFTP | **UDP 69** | Transferência simples sem negociação |

---

## Por que o DNS usa UDP e TCP?

DNS normalmente usa **UDP porta 53** para consultas comuns — uma pergunta curta, uma resposta curta.

Mas usa **TCP porta 53** quando:
- A resposta ultrapassa 512 bytes (ex: registros grandes, DNSSEC)
- Transferência de zona entre servidores DNS (AXFR)

O cliente tenta UDP primeiro; se receber resposta truncada (`TC=1`), reconecta via TCP automaticamente.

## 🧩 Quiz de Fixação

1. Por que jogos online preferem UDP mesmo perdendo pacotes?
2. Um sistema de pagamento deve usar TCP ou UDP? Por quê?
3. O HTTP/3 usa UDP — isso significa que não é confiável?

**Respostas:**  
1) Porque um pacote de posição atrasado é pior que um perdido — o próximo pacote já contém a posição atualizada; latência importa mais que completude.  
2) TCP — qualquer perda de pacote pode corromper a transação; integridade é não negociável.  
3) Não — o HTTP/3 usa QUIC sobre UDP, que implementa sua própria confiabilidade na camada de aplicação, com vantagens sobre TCP (sem head-of-line blocking, handshake mais rápido).
