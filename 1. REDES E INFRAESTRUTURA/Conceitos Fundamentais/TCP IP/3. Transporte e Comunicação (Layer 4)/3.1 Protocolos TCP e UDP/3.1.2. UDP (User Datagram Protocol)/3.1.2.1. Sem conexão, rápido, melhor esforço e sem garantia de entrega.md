### UDP — User Datagram Protocol

O UDP é **sem conexão**: os dados são enviados diretamente ao destino, sem handshake, sem confirmação de entrega e sem reordenação. O que se ganha é velocidade e latência mínima.

**Analogia:** UDP é como enviar um cartão postal — você escreve, envia e não sabe se chegou. TCP é como uma ligação telefônica confirmada — você sabe que o outro lado está ouvindo antes de começar a falar.

---

## Características do UDP

| Característica | Descrição |
| -------------- | --------- |
| Sem conexão | Envia sem estabelecer sessão prévia |
| Sem garantia de entrega | Pacotes podem se perder sem notificação |
| Sem ordenação | Pacotes podem chegar fora de ordem |
| Sem controle de congestionamento | Não reduz velocidade sob perda |
| Baixa latência | Sem overhead de handshake e confirmações |
| Cabeçalho mínimo | 8 bytes vs. mínimo 20 bytes do TCP |

---

## Estrutura do Cabeçalho UDP

O cabeçalho UDP é intencionalmente simples:

```
 0      7 8     15 16    23 24    31
+--------+--------+--------+--------+
| Source | Dest   |        |        |
| Port   | Port   | Length | Checksum|
+--------+--------+--------+--------+
```

Apenas 4 campos — 8 bytes totais. Comparado com o TCP que tem 20+ bytes de cabeçalho com sequência, ACK, flags, janela, etc.

---

## Quando o UDP é a escolha certa

A perda de um pacote UDP raramente é catastrófica nas aplicações que o usam — porque o dado já ficou obsoleto antes de ser retransmitido.

| Aplicação | Por que UDP? |
| --------- | ------------ |
| **Streaming de vídeo/áudio** (YouTube, Netflix) | Um frame perdido é menos ruim que travamento por retransmissão |
| **VoIP e chamadas** (Zoom, WhatsApp, WebRTC) | Latência importa mais que perfeição — 150ms de atraso é o limite perceptível |
| **Jogos online** | Um pacote de posição atrasado é pior que um perdido — o próximo pacote já tem a posição nova |
| **DNS** | Consultas pequenas e rápidas — se não responder em ~100ms, tenta novamente |
| **DHCP** | Broadcast de descoberta — não há conexão prévia possível |
| **SNMP** | Coleta de métricas — perder uma amostra não quebra o monitoramento |
| **NTP** | Sincronização de tempo — latência consistente importa mais que entrega garantida |

---

## UDP com confiabilidade na camada de aplicação

Algumas aplicações implementam **sua própria confiabilidade sobre UDP** quando precisam de controle mais fino do que TCP oferece:

- **QUIC** (base do HTTP/3): UDP com criptografia, multiplexação de streams e recuperação de perda sem o head-of-line blocking do TCP
- **WebRTC**: implementa ACKs seletivos e retransmissão apenas para dados críticos (sinalização), não para mídia
- **DTLS**: versão do TLS para UDP — segurança sem conexão TCP

---

## Quando **não** usar UDP

- Transferência de arquivos (qualquer corrupção invalida o arquivo)
- Transações financeiras (perder um pacote de commit é inaceitável)
- Acesso remoto (SSH perdendo bytes corrompe o terminal)
- Bancos de dados (integridade é não negociável)
