### Portas — como o SO entrega dados à aplicação certa

O endereço IP leva o pacote até a **máquina**. A porta entrega ao **processo** correto dentro dessa máquina.

Uma porta é um número de 16 bits (0 a 65535). Cada serviço "escuta" em uma porta específica — quando chega um pacote com `Destination Port: 443`, o SO sabe que deve entregar ao processo HTTPS.

---

## Faixas de Portas

| Faixa | Nome | Quem define | Uso |
| ----- | ---- | ----------- | --- |
| **0 – 1023** | Well-Known Ports | IANA | Serviços padronizados — HTTP, SSH, DNS |
| **1024 – 49151** | Registered Ports | IANA (registro voluntário) | Aplicações conhecidas — PostgreSQL, Redis, MongoDB |
| **49152 – 65535** | Dynamic / Ephemeral | Sistema Operacional | Portas temporárias criadas pelo SO para conexões de saída |

## Portas Efêmeras — o lado do cliente

Quando você abre um navegador e acessa `https://google.com:443`, seu SO cria automaticamente uma **porta efêmera** no seu lado da conexão:

```
Seu navegador:   192.168.1.10:54231  →  142.250.79.14:443
                 (sua porta efêmera)     (porta HTTPS do Google)
```

A porta efêmera é aleatória dentro do range 49152–65535 (Linux usa 32768–60999 por padrão). Isso permite que o mesmo cliente tenha **milhares de conexões simultâneas** para o mesmo servidor — cada uma com uma porta de origem diferente.

## Como ver portas em uso no sistema

```bash
# Linux — portas em escuta com processo
ss -tulnp

# Linux — conexões estabelecidas
ss -tnp | grep ESTAB

# Windows
netstat -ano

# Filtrar por porta específica
ss -tulnp | grep :443
```
