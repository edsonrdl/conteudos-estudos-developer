### O que é um Socket

Um **socket** é a combinação de **endereço IP + número de porta** que forma o endereço completo de um endpoint de comunicação. É a abstração que o sistema operacional usa para representar uma ponta de uma conexão de rede.

```
Socket = IP : Porta

Exemplos:
192.168.1.10:54231   ← socket do cliente
93.184.216.34:443    ← socket do servidor
```

---

## A Tupla de 4 Elementos

Uma conexão TCP é identificada de forma única pela **combinação de 4 valores**:

```
[ IP origem : Porta origem ]  ←→  [ IP destino : Porta destino ]

Exemplo real:
192.168.1.10:54231  ←→  93.184.216.34:443
(cliente)                  (servidor HTTPS)
```

Isso é chamado de **4-tuple** (ou socket pair). É o que permite ao SO identificar a qual processo cada pacote pertence.

**Implicação importante:** o mesmo servidor na porta 443 pode atender **milhares de conexões simultâneas** — porque cada cliente usa uma porta efêmera diferente, gerando uma 4-tuple única para cada conexão.

---

## Como o SO multiplexa as conexões

1. Cliente cria socket local com porta efêmera aleatória (ex: 54231)
2. Cliente envia SYN para IP:porta do servidor
3. Após o handshake, o SO registra a 4-tuple na **tabela de conexões** do kernel
4. Cada pacote que chega é comparado com essa tabela para encontrar o socket correto
5. O kernel entrega os dados ao processo/thread que criou aquele socket

```
Tabela de conexões do SO:
Local            →  Remoto               Estado
0.0.0.0:443      →  *                    LISTEN
192.168.1.10:443 ←→ 203.0.113.5:51200   ESTABLISHED
192.168.1.10:443 ←→ 198.51.100.2:49876  ESTABLISHED
192.168.1.10:443 ←→ 192.0.2.7:55312     ESTABLISHED
```

O servidor tem **um único socket de escuta** na porta 443, mas **um socket diferente** para cada conexão estabelecida.

---

## Ciclo de vida de um socket TCP

```
Servidor                              Cliente
socket()                              socket()
bind(IP:443)
listen()
                                      connect(servidor:443)
accept()  ←── SYN/SYN-ACK/ACK ──→
                                      Conexão estabelecida
recv()/send()  ←── Dados ──→         send()/recv()
close()                               close()
```

- **`socket()`** — cria o descritor de arquivo que representa o socket
- **`bind()`** — associa o socket a um IP e porta locais
- **`listen()`** — marca o socket como passivo (aguarda conexões)
- **`accept()`** — bloqueia até chegar uma conexão; retorna um **novo socket** para essa conexão específica
- **`connect()`** — no cliente, inicia o handshake TCP

## Estados TCP dos sockets

| Estado | Descrição | Onde aparece |
| ------ | --------- | ------------ |
| `LISTEN` | Aguardando conexões | Servidores |
| `SYN_SENT` | SYN enviado, aguardando SYN-ACK | Cliente após connect() |
| `SYN_RECEIVED` | SYN recebido, SYN-ACK enviado | Servidor antes do ACK final |
| `ESTABLISHED` | Conexão ativa, dados fluindo | Ambos os lados |
| `FIN_WAIT_1/2` | Iniciou encerramento | Lado que enviou FIN primeiro |
| `CLOSE_WAIT` | Recebeu FIN, ainda pode enviar | Lado que recebeu FIN |
| `TIME_WAIT` | Aguardando timeout final (2×MSL) | Lado que encerrou ativo |
| `CLOSED` | Conexão completamente encerrada | — |

**TIME_WAIT na prática:** servidores com alto volume de conexões curtas (APIs REST) podem acumular muitos sockets em TIME_WAIT — cada um ocupa memória e uma 4-tuple por ~60 segundos. Soluções: `tcp_tw_reuse`, keep-alive, connection pools.

## 🧩 Quiz de Fixação

1. O que forma um socket?
2. Um servidor web tem 10.000 conexões simultâneas na porta 443. Quantos sockets de escuta ele tem nessa porta?
3. Por que conexões ficam em TIME_WAIT após serem fechadas?

**Respostas:**  
1) A combinação de endereço IP + número de porta.  
2) Apenas 1 socket de escuta (LISTEN) — cada conexão estabelecida cria um socket separado identificado pela 4-tuple única.  
3) Para absorver pacotes atrasados que ainda podem chegar após o fechamento — evita que uma nova conexão com a mesma 4-tuple receba dados da conexão anterior.
