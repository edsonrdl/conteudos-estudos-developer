### TraceRoute — Mapeando o Caminho até o Destino

O `traceroute` revela **cada roteador (hop)** no caminho entre origem e destino. É a ferramenta para responder: "o problema está na minha rede, no meu ISP, ou no destino?"

---

## Como funciona — o truque do TTL

O traceroute explora o campo **TTL (Time to Live)** do IP:

1. Envia o primeiro pacote com TTL = 1
2. O primeiro roteador decrementa o TTL para 0 e descarta o pacote — mas envia de volta um **ICMP Time Exceeded** identificando a si mesmo
3. Envia o próximo pacote com TTL = 2 → o segundo roteador responde
4. Repete incrementando o TTL até chegar ao destino

Cada roteador que responde revela seu IP (e geralmente seu hostname), construindo o mapa do caminho.

---

## Uso básico

```bash
# Linux / macOS (usa UDP por padrão)
traceroute google.com

# Linux com ICMP (como o Windows)
traceroute -I google.com

# Linux com TCP (atravessa firewalls que bloqueiam UDP/ICMP)
traceroute -T -p 80 google.com

# Windows
tracert google.com

# Com resolução de nomes desativada (mais rápido)
traceroute -n google.com
tracert -d google.com
```

## Lendo a saída

```bash
$ traceroute google.com

traceroute to google.com (142.250.79.14), 30 hops max
 1  192.168.1.1 (gateway)         1.2 ms   1.1 ms   1.3 ms
 2  10.0.0.1                      8.5 ms   8.2 ms   8.6 ms
 3  * * *
 4  72.14.238.100                22.1 ms  22.4 ms  22.0 ms
 5  142.250.79.14 (google.com)   24.3 ms  24.1 ms  24.5 ms
```

| Elemento | Significado |
| -------- | ----------- |
| Número à esquerda | Número do hop (distância em roteadores) |
| IP / hostname | Identidade do roteador naquele hop |
| 3 tempos (ms) | 3 medições de RTT — variação indica jitter |
| `* * *` | Roteador não respondeu — firewall ou ICMP filtrado |

## Identificando problemas

**Latência alta em um hop específico:**
```
 3   10.0.5.1     2ms
 4   203.0.113.1  180ms  ← salto de latência
 5   198.51.100.1 182ms
```
O salto brusco no hop 4 indica gargalo naquele link ou roteador.

**`* * *` no meio mas continua depois:**
```
 3  * * *
 4  72.14.238.100  22ms
```
Normal — o roteador no hop 3 bloqueia ICMP mas encaminha o tráfego normalmente. Não é um problema.

**`* * *` do hop X até o fim:**
```
 5  72.14.238.100  22ms
 6  * * *
 7  * * *
 8  * * *
```
O tráfego chegou até o hop 5 mas não passou — firewall bloqueando, link down, ou destino final descartando.

---

## Casos de uso práticos

| Situação | Como o traceroute ajuda |
| -------- | ----------------------- |
| "A internet está lenta" | Identifica em qual hop a latência aumenta — ISP, backbone, ou destino |
| "Não consigo acessar o servidor X" | Mostra onde o tráfego para — firewall? link down? |
| "Rota estranha" | Revela se o tráfego está passando por um país ou provedor inesperado |
| Comparar dois caminhos | Traceroute com e sem VPN para comparar rotas |

## MTR — traceroute contínuo

O `mtr` (My TraceRoute) combina ping e traceroute em tempo real — mostra estatísticas acumuladas de perda e latência por hop:

```bash
mtr google.com
mtr --report -n --report-cycles 100 google.com  # relatório de 100 amostras
```

Muito mais útil que traceroute para diagnosticar problemas intermitentes — você vê se a perda está em um hop específico ou distribuída.
