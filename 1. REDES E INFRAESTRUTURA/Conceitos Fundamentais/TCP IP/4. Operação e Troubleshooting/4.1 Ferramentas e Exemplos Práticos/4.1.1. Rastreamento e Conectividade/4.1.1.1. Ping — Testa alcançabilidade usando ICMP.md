### Ping — Teste de Alcançabilidade

O `ping` usa o protocolo **ICMP (Internet Control Message Protocol)** para verificar se um host está acessível e medir o tempo de ida e volta (RTT — Round Trip Time).

**Como funciona:** envia um **ICMP Echo Request** ao destino e aguarda um **ICMP Echo Reply**. Se o destino está acessível e não bloqueia ICMP, ele responde.

---

## Uso básico

```bash
# Linux / macOS
ping google.com
ping -c 4 google.com        # limita a 4 pacotes
ping -i 0.2 8.8.8.8         # intervalo de 0.2s entre pacotes
ping -s 1400 192.168.1.1    # tamanho do pacote (útil para testar MTU)

# Windows
ping google.com
ping -n 4 google.com        # 4 pacotes
ping -t google.com          # contínuo (Ctrl+C para parar)
```

---

## Lendo a saída

```bash
$ ping -c 4 google.com

PING google.com (142.250.79.14): 56 data bytes
64 bytes from 142.250.79.14: icmp_seq=1 ttl=116 time=14.5 ms
64 bytes from 142.250.79.14: icmp_seq=2 ttl=116 time=14.2 ms
64 bytes from 142.250.79.14: icmp_seq=3 ttl=116 time=15.1 ms
64 bytes from 142.250.79.14: icmp_seq=4 ttl=116 time=14.8 ms

--- google.com ping statistics ---
4 packets transmitted, 4 received, 0% packet loss
rtt min/avg/max/mdev = 14.2/14.6/15.1/0.3 ms
```

| Campo | O que significa |
| ----- | --------------- |
| `icmp_seq` | Número de sequência — detecta pacotes perdidos ou fora de ordem |
| `ttl` | Time to Live — decrementado a cada roteador; indica aproximadamente quantos hops até o destino |
| `time` | RTT em milissegundos — latência de ida e volta |
| `packet loss` | % de pacotes perdidos — qualquer valor > 0 indica problema |
| `mdev` | Desvio médio — jitter; valores altos indicam instabilidade |

---

## Interpretando resultados

**Latências de referência:**
| RTT | Interpretação |
| --- | ------------- |
| < 1ms | Rede local (LAN) |
| 1–20ms | Conexão regional de boa qualidade |
| 20–100ms | WAN ou internet normal |
| > 100ms | Latência alta — perceptível em VoIP e jogos |
| > 300ms | Problemático para qualquer aplicação interativa |

---

## Erros comuns e causas

| Mensagem | Causa provável | O que investigar |
| -------- | -------------- | ---------------- |
| `Request timeout` | Firewall bloqueando ICMP ou host offline | Verificar regras de firewall, testar outra porta |
| `Destination host unreachable` | Problema de roteamento local — o gateway não sabe como chegar | Verificar tabela de rotas com `ip route` |
| `Network unreachable` | Sem rota para o destino no host local | Interface down? Gateway configurado? |
| `TTL expired in transit` | Loop de roteamento ou TTL muito baixo | Usar traceroute para mapear o caminho |
| 100% packet loss | Host offline, firewall, ou link down | Testar gateway primeiro, depois host externo |

## Diagnóstico em camadas com ping

A sequência correta para isolar o problema:

```bash
# 1. Gateway local acessível? (problema físico/L2 se falhar)
ping 192.168.1.1

# 2. DNS resolver acessível?
ping 8.8.8.8

# 3. Resolução de nomes funciona?
ping google.com

# 4. Destino específico acessível?
ping servidor-interno.empresa.com
```

Se o passo 1 falha → problema local (cabo, Wi-Fi, interface)  
Se o passo 2 falha → problema no ISP ou gateway  
Se o passo 3 falha mas 2 passa → problema de DNS  
Se o passo 4 falha mas 3 passa → problema no caminho até esse servidor especificamente
