### Wireshark — Análise Profunda de Pacotes

O Wireshark é um **analisador de protocolo** que captura e decodifica todo o tráfego de rede em tempo real. Enquanto ping e traceroute testam conectividade e ss mostra conexões abertas, o Wireshark mostra **exatamente o que está dentro de cada pacote**.

É a ferramenta de último recurso: quando você sabe que há um problema mas as outras ferramentas não revelam o porquê.

## Filtros de exibição — os mais úteis

Os filtros de exibição são aplicados **após** a captura e permitem isolar exatamente o que você precisa analisar.

**Por protocolo:**
```
tcp
udp
icmp
dns
http
tls
arp
```

**Por endereço:**
```
ip.addr == 192.168.1.10           # qualquer tráfego desse IP
ip.src == 192.168.1.10            # apenas origem
ip.dst == 192.168.1.10            # apenas destino
ip.addr == 192.168.1.0/24         # toda uma sub-rede
```

**Por porta:**
```
tcp.port == 443
tcp.port == 80 or tcp.port == 443
tcp.dstport == 8080
```

**Por flags TCP:**
```
tcp.flags.syn == 1                # ver handshakes
tcp.flags.syn == 1 and tcp.flags.ack == 0   # apenas SYN (novas conexões)
tcp.flags.rst == 1                # conexões resetadas
tcp.flags.fin == 1                # encerramentos
```

**Diagnóstico de problemas:**
```
tcp.analysis.retransmission       # pacotes retransmitidos
tcp.analysis.duplicate_ack        # ACKs duplicados (indicam perda)
tcp.analysis.zero_window          # receptor sem buffer
tcp.analysis.window_full          # sender limitado pela janela
tcp.analysis.out_of_order         # pacotes fora de ordem
```

## Filtros de captura (BPF) — antes de capturar

Aplicados durante a captura para reduzir volume. Sintaxe diferente dos filtros de exibição:

```bash
host 192.168.1.10           # tráfego de/para esse host
port 443                    # apenas HTTPS
host 192.168.1.10 and port 443
not broadcast and not multicast
tcp and port 22             # apenas SSH
src net 192.168.0.0/16      # origem na rede privada
```

## Diagnósticos práticos

**Ver o Three-Way Handshake:**
```
Filtro: ip.addr == [IP_servidor] and tcp.flags.syn == 1
```
Você verá os pacotes SYN → SYN-ACK → ACK em sequência.

**Diagnosticar lentidão em conexão HTTP:**
```
Filtro: ip.addr == [IP_servidor] and tcp
Statistics → TCP Stream Graphs → Time Sequence
```
Procure por: retransmissões, janelas zeradas, gaps longos entre request e response.

**Ver retransmissões (perda de pacotes):**
```
Filtro: tcp.analysis.retransmission
```
Muitas retransmissões indicam perda no caminho — problema de link ou congestionamento.

**Identificar reset de conexão:**
```
Filtro: tcp.flags.rst == 1
```
RSTs indicam que uma das partes rejeitou abruptamente a conexão — firewall, porta fechada, ou aplicação encerrando sem FIN.

## tcpdump — Wireshark na linha de comando

Para servidores sem interface gráfica, o `tcpdump` é o equivalente CLI:

```bash
# Captura básica em interface eth0
sudo tcpdump -i eth0

# Capturar e salvar para análise posterior no Wireshark
sudo tcpdump -i eth0 -w captura.pcap

# Filtros
sudo tcpdump -i eth0 host 192.168.1.10
sudo tcpdump -i eth0 port 443
sudo tcpdump -i eth0 'tcp[tcpflags] & tcp-syn != 0'  # apenas SYNs

# Ler arquivo salvo
tcpdump -r captura.pcap
```

**Fluxo de trabalho comum:**
1. `tcpdump` no servidor para capturar durante o problema
2. Transferir o `.pcap` para a máquina local
3. Abrir no Wireshark para análise visual

## 🧩 Quiz de Fixação

1. Qual filtro usar no Wireshark para ver apenas pacotes retransmitidos?
2. O que indica `tcp.flags.rst == 1` em uma captura?
3. Qual a diferença entre filtro de captura e filtro de exibição no Wireshark?

**Respostas:**  
1) `tcp.analysis.retransmission`  
2) Uma das partes resetou a conexão abruptamente — pode indicar firewall bloqueando, porta fechada no destino, ou timeout de aplicação.  
3) Filtros de captura (BPF) definem o que é capturado — reduzem o volume mas não podem ser alterados depois. Filtros de exibição são aplicados sobre o que já foi capturado — mais flexíveis e podem ser mudados sem recapturar.
