### Netstat e SS — Inspecionando Conexões do Sistema

O `netstat` e seu substituto moderno `ss` mostram o estado das conexões de rede do sistema: quais portas estão abertas, quais conexões estão ativas e qual processo é responsável por cada uma.

**`ss` é preferível ao `netstat`** em sistemas Linux modernos — mais rápido, mais informações e suporte nativo a filtros.

---

## Comandos essenciais

```bash
# Portas em escuta com processo (o mais usado)
ss -tulnp
# -t TCP  -u UDP  -l listening  -n numérico (não resolve nomes)  -p processo

# Todas as conexões TCP estabelecidas
ss -tnp | grep ESTAB

# Todas as conexões (listening + established + etc.)
ss -tanp

# Estatísticas resumidas
ss -s

# Filtrar por porta específica
ss -tulnp | grep :8080
ss -tnp | grep ':443'

# Filtrar por processo
ss -tulnp | grep nginx
```

**Equivalentes no Windows:**
```cmd
netstat -ano                    # todas as conexões com PID
netstat -ano | findstr :443     # filtrar por porta
netstat -b                      # com nome do executável (requer admin)
```

## Lendo a saída do `ss -tulnp`

```
Netid  State   Recv-Q  Send-Q  Local Address:Port   Peer Address:Port  Process
tcp    LISTEN  0       128     0.0.0.0:80            0.0.0.0:*          users:(("nginx",pid=1234))
tcp    LISTEN  0       128     0.0.0.0:443           0.0.0.0:*          users:(("nginx",pid=1234))
tcp    LISTEN  0       5       127.0.0.1:5432        0.0.0.0:*          users:(("postgres",pid=5678))
udp    UNCONN  0       0       0.0.0.0:53            0.0.0.0:*          users:(("systemd-r",pid=456))
```

| Campo | Significado |
| ----- | ----------- |
| `Netid` | Protocolo: tcp, udp, unix |
| `State` | Estado da conexão |
| `Recv-Q` | Bytes recebidos aguardando leitura pela aplicação — se alto, app não está consumindo |
| `Send-Q` | Bytes enviados aguardando ACK — se alto, congestionamento ou receptor lento |
| `Local Address:Port` | IP e porta locais — `0.0.0.0` significa escutando em todas interfaces |
| `Peer Address:Port` | IP e porta remotos |
| `Process` | Nome e PID do processo |

## Estados TCP importantes

| Estado | O que significa | Onde ver |
| ------ | --------------- | -------- |
| `LISTEN` | Socket aguardando conexões | Servidores |
| `ESTABLISHED` | Conexão ativa, dados trafegando | Ambos os lados |
| `TIME_WAIT` | Aguardando timeout após fechar (60s) | Servidor com muitas conexões curtas |
| `CLOSE_WAIT` | Recebeu FIN do cliente, aplicação ainda não fechou | Indica vazamento no código da aplicação |
| `SYN_RECV` | Recebeu SYN, enviou SYN-ACK, aguardando ACK | Normal em baixa quantidade; muitos indicam SYN flood |
| `FIN_WAIT_1/2` | Encerramento em progresso | Normal durante fechamento |

**`CLOSE_WAIT` em quantidade:** geralmente indica bug na aplicação — ela não está chamando `close()` no socket após o cliente desconectar.

**`TIME_WAIT` em quantidade:** normal em servidores de alta carga com conexões curtas. Se causar esgotamento de portas, considerar `tcp_tw_reuse` ou connection pooling.

## Casos de uso práticos

```bash
# "A porta 8080 está ocupada?" — descobrir qual processo usa
ss -tulnp | grep :8080

# "Quantas conexões ESTABLISHED tem agora?"
ss -tn | grep ESTAB | wc -l

# "Tem vazamento de conexões CLOSE_WAIT?"
ss -tn | grep CLOSE_WAIT | wc -l

# "Qual processo está usando mais conexões?"
ss -tnp | grep ESTAB | awk '{print $6}' | sort | uniq -c | sort -rn

# "O cliente X ainda está conectado?"
ss -tn | grep 203.0.113.5
```
