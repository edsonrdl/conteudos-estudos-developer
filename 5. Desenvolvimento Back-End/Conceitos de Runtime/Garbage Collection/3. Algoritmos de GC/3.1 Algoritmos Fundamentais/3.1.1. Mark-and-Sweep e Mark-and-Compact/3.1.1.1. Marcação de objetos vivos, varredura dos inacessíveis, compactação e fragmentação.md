### Mark-and-Sweep e Mark-and-Compact

Os algoritmos de marcação e varredura são a base histórica do GC moderno. Entendê-los é entender o que todos os coletores sofisticados (G1, ZGC) fazem por baixo.

---

## Mark-and-Sweep

Funciona em duas fases:

```
FASE 1 — MARK (marcação):
  Começa pelas GC Roots
  Percorre o grafo de referências
  Marca cada objeto alcançável como "vivo"

FASE 2 — SWEEP (varredura):
  Percorre todo o heap
  Objetos NÃO marcados → memória liberada
  Objetos marcados → marcação removida (reset para o próximo ciclo)
```

**Resultado:**
```
Antes:  [A][B][morto][C][morto][morto][D]
Após:   [A][B][     ][C][              ][D]
```

**Problema:** A memória liberada fica fragmentada — buracos de tamanhos variados espalhados pelo heap. Um objeto grande pode não ter espaço contíguo para ser alocado mesmo com memória total suficiente.

---

## Mark-and-Compact

Adiciona uma terceira fase ao Mark-and-Sweep:

```
FASE 1 — MARK: igual ao anterior
FASE 2 — COMPACT (compactação):
  Move todos os objetos vivos para o início do heap
  Atualiza todas as referências para os novos endereços
FASE 3 — SWEEP: libera tudo após os objetos compactados
```

**Resultado:**
```
Antes:   [A][B][morto][C][morto][morto][D][espaço livre]
Após:    [A][B][C][D][espaço livre contíguo                   ]
```

**Vantagem:** Elimina fragmentação, alocação de novos objetos é trivial (bump pointer — só avança um ponteiro).

**Desvantagem:** Compactação é cara — move objetos e atualiza todas as referências. Mais STW.

---

## Comparação

| Algoritmo | Fragmentação | Custo de compactação | Usado em |
|-----------|-------------|---------------------|---------|
| Mark-and-Sweep | Alta | Nenhum | Versões antigas, base teórica |
| Mark-and-Compact | Zero | Alto (move tudo) | .NET CLR (padrão), Old Gen de alguns coletores JVM |
| Copying Collection | Zero | Médio (só copia vivos) | Young Generation (Eden→Survivor) |

## 🧩 Quiz de Fixação

1. Por que Mark-and-Sweep pode causar falha de alocação mesmo com memória disponível?
2. O que é "bump pointer allocation" e por que é rápida?
3. Por que compactação é cara?

**Respostas:**
1) Por fragmentação — a memória livre está distribuída em pequenos buracos não-contíguos. Um objeto grande precisa de espaço contíguo e pode não encontrar, mesmo que o total de memória livre seja suficiente.
2) Bump pointer é a técnica de alocação onde um ponteiro aponta para o próximo espaço livre. Alocar um novo objeto = apenas somar o tamanho ao ponteiro. É O(1) e extremamente rápida — possível só quando não há fragmentação.
3) Compactação precisa mover cada objeto vivo para um novo endereço e então atualizar **todas** as referências para esse objeto em todo o heap. É O(n) onde n é o número de referências — caro em heaps grandes.
