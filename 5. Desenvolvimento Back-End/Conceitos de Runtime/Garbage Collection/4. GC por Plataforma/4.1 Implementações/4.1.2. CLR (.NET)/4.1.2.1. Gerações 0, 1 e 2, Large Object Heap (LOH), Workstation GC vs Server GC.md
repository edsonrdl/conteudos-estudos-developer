### GC na CLR (.NET)

O GC da CLR (Common Language Runtime) é geracional, compactador e altamente otimizado. C#, F# e VB.NET compartilham o mesmo GC — é uma característica do runtime, não das linguagens.

---

## Gerações no .NET

O .NET usa 3 gerações (0, 1, 2) em vez das duas da JVM (Young/Old):

```
Gen 0: objetos recém-criados (mais efêmeros)
       → coletada mais frequentemente, pausas mínimas

Gen 1: objetos que sobreviveram à Gen 0
       → buffer entre objetos efêmeros e de longa duração

Gen 2: objetos de longa duração (sessions, cache, singletons)
       → coletada raramente, pode incluir Full GC
```

**Promoção:** objeto sobrevive coleta de Gen 0 → promovido para Gen 1. Sobrevive Gen 1 → promovido para Gen 2.

---

## Large Object Heap (LOH)

Objetos acima de **85KB** vão para o LOH — separado das gerações normais:

```
Heap normal (Gen 0/1/2):  objetos < 85KB
LOH:                      objetos ≥ 85KB (arrays grandes, strings longas, buffers)
```

**Características do LOH:**
- Coletado junto com a Gen 2 (raramente)
- **Não compactado por padrão** — fragmentação acumula ao longo do tempo
- Fragmentação no LOH pode causar `OutOfMemoryException` mesmo com memória disponível
- .NET 4.5.1+ permite compactação do LOH sob demanda: `GCSettings.LargeObjectHeapCompactionMode`

---

## Workstation GC vs Server GC

| Modo | Threads de GC | Uso típico | Throughput | Pausas |
|------|--------------|-----------|-----------|--------|
| **Workstation** | 1 (foreground ou background) | Aplicações desktop, processos únicos | Menor | Menores |
| **Server** | 1 thread por CPU core | ASP.NET Core, serviços em container | Maior | Maiores (mais paralelismo) |

ASP.NET Core em produção usa **Server GC** por padrão — mais throughput porque paraleliza a coleta em múltiplos cores.

```xml
<!-- runtimeconfig.json para forçar Workstation GC -->
{
  "configProperties": {
    "System.GC.Server": false
  }
}
```

---

## Background GC

Assim como o G1/ZGC no Java, o .NET tem **Background GC** para Gen 2 — coleta as gerações maiores concorrentemente enquanto a aplicação roda, minimizando pausas:

```
Gen 0/1 coletas: sempre foreground (STW curto)
Gen 2 coletas: background (concurrent) se possível
```

## 🧩 Quiz de Fixação

1. Por que o .NET usa 3 gerações (0/1/2) em vez de duas?
2. Por que objetos no LOH podem causar OutOfMemoryException mesmo com memória disponível?
3. Por que ASP.NET Core usa Server GC por padrão?

**Respostas:**
1) Gen 1 funciona como buffer — objetos que sobreviveram uma coleta mas ainda não são "velhos o suficiente" para Gen 2. Reduz promoções prematuras para Gen 2, mantendo a coleta de longa duração realmente rara.
2) O LOH não é compactado por padrão, acumulando fragmentação. Um array de 100KB pode não encontrar 100KB contíguos livres mesmo que o total de espaço livre seja maior — fragmentação impede a alocação.
3) Server GC usa uma thread de GC por core da CPU, paralelizando a coleta. Em servidores com muitos cores atendendo muitas requisições, o paralelismo aumenta significativamente o throughput de coleta, compensando o aumento nas pausas individuais.
