### Self-Attention — Query, Key, Value na Prática

O arquivo anterior (2.1.1.1) explicou por que o Transformer eliminou o processamento sequencial. Este arquivo entra no mecanismo que tornou isso possível: self-attention, o coração matemático de todo LLM moderno.

---

## A ideia: cada palavra "presta atenção" nas outras

Self-attention permite que cada token, ao ser processado, calcule o quanto deve "prestar atenção" em cada outro token da sequência para entender seu próprio significado em contexto. Na frase "O banco estava cheio de gente esperando para sacar dinheiro", a palavra "banco" precisa prestar muita atenção em "sacar" e "dinheiro" para resolver a ambiguidade — banco como instituição financeira, não como assento de praça.

**Analogia:** self-attention é como ler uma frase e, para cada palavra, perguntar mentalmente "quais outras palavras desta frase mudam o que esta palavra significa aqui?" — e ajustar a interpretação de acordo, tudo simultaneamente para todas as palavras da frase.

---

## O mecanismo matemático: Query, Key, Value

Cada token gera três vetores a partir de si mesmo, através de transformações aprendidas durante o treinamento:

| Vetor | Pergunta que representa |
|---|---|
| **Query** | "O que estou procurando?" |
| **Key** | "O que eu ofereço, para quem procura por mim?" |
| **Value** | "O conteúdo real que eu carrego, se alguém prestar atenção em mim" |

O "score de atenção" entre dois tokens é o produto escalar entre a Query de um e a Key do outro — quanto mais alinhados os vetores, maior o score. Esses scores passam por uma função `softmax` (que os transforma em uma distribuição de probabilidade somando 100%), e o resultado pondera quanto de cada Value entra na representação final daquele token. Isso acontece para **todos os pares de tokens simultaneamente** — daí a paralelização que tornou o treinamento de modelos gigantes viável.

```
Token A                          Token B
   │                                │
   ▼                                ▼
Query(A) ────· (produto escalar) ── Key(B)
   │                                │
   └──────► Score de atenção ◄──────┘
              │
              ▼ softmax (normaliza entre todos os tokens)
     Peso de atenção de A em B
              │
              ▼
   Peso × Value(B) é somado à nova representação de A
```

---

## Exemplo numérico simplificado

Considere a frase "gato dorme" reduzida a vetores de brinquedo, de apenas 2 dimensões cada, só para tornar a mecânica visível:

```
Vetores de entrada (simplificados):
  "gato"  = [1.0, 0.0]
  "dorme" = [0.0, 1.0]

Suponha que, após as transformações aprendidas, cada token gere:
  Query("gato")  = [0.9, 0.1]      Key("gato")  = [1.0, 0.0]     Value("gato")  = [2.0, 0.0]
  Query("dorme") = [0.1, 0.9]      Key("dorme") = [0.0, 1.0]     Value("dorme") = [0.0, 3.0]

Score de atenção de "gato" em relação a cada token (produto escalar Query·Key):
  "gato"  → Key("gato"):  (0.9×1.0 + 0.1×0.0) = 0.90
  "gato"  → Key("dorme"): (0.9×0.0 + 0.1×1.0) = 0.10

Após softmax (normalizando para somar 1): ≈ [0.69, 0.31]

Nova representação de "gato" = 0.69 × Value("gato") + 0.31 × Value("dorme")
                              = 0.69 × [2.0, 0.0] + 0.31 × [0.0, 3.0]
                              = [1.38, 0.93]
```

O vetor final de "gato" (`[1.38, 0.93]`) deixou de ser puramente "sobre gato" — ele já carrega uma mistura ponderada de "dorme", porque o score de atenção (mesmo pequeno, 0.31) trouxe parte do Value de "dorme" para dentro da representação de "gato". Em um Transformer real, esse processo acontece com vetores de centenas de dimensões e múltiplas cabeças de atenção (assunto do próximo arquivo, 2.3.1.1), refinando o significado de cada palavra a cada camada da rede.

---

## Por que isso resolve a ambiguidade de significado

Voltando ao exemplo do "banco": a palavra "banco" gera uma Query que, ao ser comparada com as Keys de "sacar" e "dinheiro", produz scores de atenção altos para essas duas palavras — porque, durante o treinamento, o modelo aprendeu que esse tipo de combinação (banco + sacar + dinheiro) costuma indicar o sentido financeiro. O Value dessas palavras, então, entra com peso maior na representação final de "banco", ajustando seu significado para o contexto certo — tudo isso acontece automaticamente, sem nenhuma regra explícita de desambiguação.

## 🧩 Quiz de Fixação

1. Qual é o papel de cada um dos três vetores gerados por um token — Query, Key e Value — no mecanismo de self-attention?
2. No exemplo numérico, por que o vetor final de "gato" não é idêntico ao seu vetor de entrada original `[1.0, 0.0]`?
3. Como o mecanismo de self-attention, sem nenhuma regra linguística explícita, consegue resolver a ambiguidade de uma palavra como "banco" dependendo do contexto da frase?

**Respostas:**
1) A Query representa "o que este token está procurando" nos outros tokens da sequência. A Key representa "o que este token oferece, para quem está procurando por algo parecido". O Value representa o conteúdo real que aquele token carrega, e é o que efetivamente contribui para a nova representação de outro token, ponderado pelo score de atenção calculado entre Query e Key.
2) Porque a nova representação de "gato" é uma soma ponderada entre o Value do próprio "gato" e o Value de "dorme", de acordo com os scores de atenção calculados (0.69 e 0.31 no exemplo). Como o peso de "dorme" não é zero, uma fração do seu Value entra na composição final, alterando o vetor resultante em relação ao vetor de entrada original.
3) Porque os vetores Query e Key de cada palavra são aprendidos durante o treinamento de forma a capturar relações contextuais relevantes — ao ver repetidamente frases como "banco... sacar... dinheiro" durante o treinamento, o modelo aprende a produzir Queries e Keys que geram scores de atenção altos entre essas palavras quando aparecem juntas, fazendo com que o Value de "sacar" e "dinheiro" influencie fortemente a representação final de "banco", resolvendo a ambiguidade sem nenhuma regra explícita programada.
