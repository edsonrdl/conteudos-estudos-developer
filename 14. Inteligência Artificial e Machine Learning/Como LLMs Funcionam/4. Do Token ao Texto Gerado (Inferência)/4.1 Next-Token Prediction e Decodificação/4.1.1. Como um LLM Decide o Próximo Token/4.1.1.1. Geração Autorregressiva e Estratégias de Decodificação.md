### Geração Autorregressiva e Estratégias de Decodificação

Com tokenização (Domínio 1), arquitetura (Domínio 2) e embeddings (Domínio 3) cobertos, chega o momento de juntar tudo: como um LLM decoder-only efetivamente **gera texto**, token por token.

---

## Um LLM não "sabe" nada — ele prevê o próximo token

Na sua essência mais crua, um LLM decoder-only faz uma única coisa repetidamente: dado uma sequência de tokens, calcular a **probabilidade de cada token possível do vocabulário ser o próximo**. Toda capacidade aparente de "raciocínio", "conhecimento" ou "criatividade" emerge de repetir essa previsão simples, token a token, usando cada saída como entrada para a próxima rodada — um processo chamado geração **autorregressiva**.

```
Entrada: "O céu é"
              │
              ▼ o modelo calcula uma probabilidade para CADA token do vocabulário
   ┌──────────────────────────────────┐
   │ "azul"     → 42%                  │
   │ "lindo"    → 18%                  │
   │ "grande"   → 7%                   │
   │ "verde"    → 0.3%                 │
   │ ... (todos os demais tokens)      │
   └──────────────────────────────────┘
              │
              ▼ um token é escolhido (ver estratégias abaixo)
Saída: "azul"
              │
              ▼ o token escolhido volta como parte da entrada
Nova entrada: "O céu é azul"
              │
              ▼ repete o processo para o próximo token
```

Esse ciclo se repete até o modelo gerar o token especial de fim de geração (`<|endoftext|>`, visto em 1.3.1.1) ou atingir um limite máximo de tokens configurado.

---

## Estratégias de decodificação: como escolher o próximo token

Ter uma distribuição de probabilidades não é o mesmo que ter uma decisão — é preciso uma **estratégia de decodificação** para transformar essas probabilidades em uma escolha concreta:

### Greedy decoding

Sempre escolhe o token de **maior probabilidade**. É determinístico (a mesma entrada sempre produz a mesma saída), mas tende a gerar texto repetitivo e genérico, porque nunca "arrisca" um token menos óbvio que poderia levar a uma continuação mais interessante.

### Temperature

Um parâmetro numérico que "achata" ou "afia" a distribuição de probabilidade antes da escolha final:

```
Temperature baixa (perto de 0):  distribuição fica mais "afiada"
  "azul" → 90%   "lindo" → 8%   outros → 2%
  (aproxima-se do greedy — mais determinístico e previsível)

Temperature alta (ex: 1.5):      distribuição fica mais "achatada"
  "azul" → 35%   "lindo" → 25%   "grande" → 15%   outros → 25%
  (mais chance de tokens menos prováveis serem escolhidos — mais "criativo", mais arriscado)
```

Para tarefas que exigem precisão (gerar código, extrair dados estruturados), a temperature costuma ser mantida próxima de 0. Para tarefas criativas (escrever uma história), uma temperature mais alta produz variedade.

### Top-k e Top-p (nucleus sampling)

Em vez de considerar todo o vocabulário na hora de escolher, essas estratégias restringem as opções antes da amostragem:

| Estratégia | Como funciona |
|---|---|
| **Top-k** | Considera apenas os *k* tokens mais prováveis (ex: top-10), descartando toda a "cauda longa" de tokens improváveis |
| **Top-p (nucleus sampling)** | Considera o menor conjunto de tokens cuja probabilidade acumulada ultrapasse *p*% (ex: 90%) — um conjunto que se adapta dinamicamente: pode ter poucos tokens quando o modelo está "confiante", e mais tokens quando está "incerto" |

Essas técnicas equilibram diversidade (evitar sempre a resposta mais óbvia) com coerência (evitar escolher um token completamente improvável e sem sentido).

## Por que isso conecta diretamente com o Domínio 2

A razão pela qual essa previsão simples, repetida, consegue produzir textos coerentes e até respostas complexas de raciocínio está diretamente ligada à arquitetura Transformer: cada previsão de próximo token se beneficia de toda a análise contextual feita pela self-attention (2.2.1.1) sobre a sequência inteira até aquele ponto — a "inteligência" aparente não está na etapa de decodificação (que é mecanicamente simples), mas na qualidade da distribuição de probabilidades que o Transformer já calculou antes.

## 🧩 Quiz de Fixação

1. O que significa dizer que um LLM decoder-only "não sabe nada, apenas prevê o próximo token"?
2. Por que o greedy decoding, apesar de ser a estratégia mais simples, tende a produzir textos repetitivos?
3. Qual é a diferença entre Top-k e Top-p (nucleus sampling) na forma como cada um restringe as opções de token antes da escolha final?

**Respostas:**
1) Significa que, em cada etapa da geração, o modelo apenas calcula uma distribuição de probabilidade sobre todos os tokens do vocabulário, indicando qual token é mais provável de vir a seguir, dado o texto já gerado. Não há nenhuma "compreensão" consciente envolvida — toda capacidade aparente de raciocínio ou coerência emerge da repetição desse processo simples, token a token, usando cada saída gerada como parte da entrada da próxima rodada (geração autorregressiva).
2) Porque o greedy decoding sempre escolhe o token de maior probabilidade em cada etapa, sem nenhuma variação. Isso tende a levar o modelo a repetir os mesmos padrões de resposta "mais seguros" e óbvios repetidamente, já que nunca há chance de escolher um token menos provável que poderia abrir caminho para uma continuação mais variada ou interessante.
3) O Top-k restringe as opções a um número fixo dos *k* tokens mais prováveis, independentemente de quão confiante o modelo esteja naquela previsão específica. O Top-p (nucleus sampling) restringe as opções dinamicamente, incluindo o menor conjunto de tokens cuja probabilidade acumulada ultrapasse um limiar (por exemplo, 90%) — esse conjunto pode ser pequeno quando o modelo está muito confiante em poucas opções, ou maior quando a probabilidade está mais distribuída entre muitos tokens.
