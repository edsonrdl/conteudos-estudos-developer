### JSON (application/json) — validação de sintaxe e formatação automática no Insomnia

O JSON é o formato de body padrão para APIs REST modernas. O Insomnia oferece um editor JSON com validação de sintaxe em tempo real, formatação automática com um clique e suporte completo a variáveis de ambiente e Template Tags dentro do payload. Este arquivo cobre como usar o editor JSON do Insomnia de forma eficiente e quais erros evitar.

---

## Configurando o body como JSON

```
Para usar JSON como body de uma requisição:

1. Selecionar o método que aceita body (POST, PUT, PATCH)
2. Clicar na aba "Body"
3. Clicar no dropdown de tipo de body → selecionar "JSON"

O Insomnia automaticamente:
  → Define o header: Content-Type: application/json
  → Abre o editor JSON com syntax highlighting
  → Ativa a validação de sintaxe em tempo real
```

## Editor JSON — recursos práticos

### Syntax highlighting e validação em tempo real

```
JSON válido (sem indicadores de erro):
{
  "nome": "João Silva",
  "email": "joao@empresa.com",
  "idade": 30,
  "ativo": true,
  "perfil": null,
  "roles": ["admin", "editor"],
  "endereco": {
    "rua": "Av. Paulista",
    "numero": 1000,
    "cidade": "São Paulo"
  }
}

JSON inválido (Insomnia destaca em vermelho):
{
  "nome": "João Silva",
  "email": "joao@empresa.com",   ← trailing comma (vírgula sem próximo campo)
  "ativo": true
}

Erros detectados em tempo real:
  → Trailing comma (vírgula no último elemento)
  → Aspas simples em vez de duplas
  → Chave sem aspas  { nome: "João" }
  → Corpo incompleto (JSON não fechado)
  → Valor undefined (não existe em JSON)
```

### Formatação automática (Prettify)

```
JSON "feio" (minificado ou mal indentado):
{"nome":"João","email":"joao@empresa.com","roles":["admin","editor"]}

Após clicar em "Beautify" (ícone de formatação):
{
  "nome": "João",
  "email": "joao@empresa.com",
  "roles": [
    "admin",
    "editor"
  ]
}

Atalho: Ctrl + Shift + P (ou botão no canto superior do editor)
Útil para: colar JSON de outra fonte e formatar imediatamente
```

## Usando variáveis de ambiente no JSON

O Insomnia permite inserir variáveis diretamente dentro do body JSON:

```json
{
  "usuario_id": "{{ user_id }}",
  "token": "{{ access_token }}",
  "ambiente": "{{ env_name }}",
  "timestamp": "{{ $timestamp }}",
  "request_id": "{{ $guid }}"
}
```

```
Environment "Dev":
  user_id: 42
  access_token: eyJhbGciOiJI...
  env_name: desenvolvimento

Body enviado (após substituição):
{
  "usuario_id": "42",
  "token": "eyJhbGciOiJI...",
  "ambiente": "desenvolvimento",
  "timestamp": "1705312800",
  "request_id": "a1b2c3d4-e5f6-7890-abcd-ef1234567890"
}

Atenção: variáveis são sempre inseridas como string no JSON
  "usuario_id": "{{ user_id }}"   → "usuario_id": "42"  (string "42", não número 42)
  
  Para inserir como número:
  "usuario_id": {{ user_id }}      → "usuario_id": 42   (sem aspas = número)
  (requer que a variável contenha apenas dígitos)
```

## Template Tags dentro do JSON

Além de variáveis simples, Template Tags permitem extrair valores de outras respostas:

```json
{
  "produto_id": "{{ _.response.body.id }}",
  "quantidade": 2,
  "observacao": "Pedido criado em {{ $timestamp }}"
}
```

```
Cenário de Request Chaining:

POST /produtos → retorna {"id": 456, "nome": "Notebook"}
POST /pedidos com body:
{
  "produto_id": "{{ _.response.body.id }}",   ← extrai 456 da resposta anterior
  "quantidade": 2
}

Body enviado:
{
  "produto_id": "456",
  "quantidade": 2
}

Sem copiar/colar o ID manualmente!
```

## Trabalhando com JSON complexo

### Arrays de objetos

```json
{
  "itens": [
    {
      "produto_id": "{{ produto_1_id }}",
      "quantidade": 2,
      "preco_unitario": 99.90
    },
    {
      "produto_id": "{{ produto_2_id }}",
      "quantidade": 1,
      "preco_unitario": 299.00
    }
  ],
  "observacoes": "Entregar no período da tarde",
  "forma_pagamento": "cartao_credito"
}
```

### JSON com campos condicionais (usando comentário temporário)

```
O JSON não suporta comentários — mas durante o desenvolvimento,
você pode "desativar" campos temporariamente removendo-os ou
usando uma string vazia:

Versão de teste (campo opcional comentado via remoção temporária):
{
  "nome": "João",
  "email": "joao@empresa.com"
}

Versão completa:
{
  "nome": "João",
  "email": "joao@empresa.com",
  "telefone": "11 9999-9999",
  "data_nascimento": "1990-01-15"
}

Dica: usar dois requests separados — um mínimo e um completo
```

## Copiando JSON da resposta como body de nova requisição

Fluxo comum: receber um objeto JSON, modificar um campo e reenviar como update.

```
1. GET /usuarios/123 → resposta:
{
  "id": 123,
  "nome": "João",
  "email": "joao_antigo@empresa.com",
  "ativo": true
}

2. Copiar o body da resposta (botão "Copy" no painel de resposta)

3. Criar PUT /usuarios/123
   → Colar o JSON no body
   → Beautify para formatar
   → Modificar apenas o campo desejado:

{
  "id": 123,
  "nome": "João",
  "email": "joao_novo@empresa.com",   ← campo atualizado
  "ativo": true
}

4. Enviar o PUT com o objeto completo modificado
```

## O header Content-Type gerado automaticamente

```
Ao selecionar "JSON" como tipo de body, o Insomnia adiciona:
  Content-Type: application/json

Verificar no Timeline após enviar:
  POST /usuarios HTTP/1.1
  Host: api.empresa.com
  Content-Type: application/json
  Content-Length: 87
  Authorization: Bearer eyJ...
  
  {"nome":"João","email":"joao@empresa.com","ativo":true}

Se precisar de charset explícito (algumas APIs antigas exigem):
  Modificar manualmente o header para: Content-Type: application/json; charset=utf-8
  (na aba Headers da requisição, sobrescreve o gerado automaticamente)
```

## Erros comuns e armadilhas

**Trailing comma no último campo:** é o erro de sintaxe JSON mais comum. `{"nome": "João",}` é inválido — a vírgula após o último campo não é permitida (diferente de JavaScript). O Insomnia destaca em vermelho imediatamente.

**Variável numérica entre aspas enviada como string:** se a API espera `"quantidade": 2` (número) e você escreve `"quantidade": "{{ qtd }}"` (string), a API pode retornar 422 ou erro de validação de tipo. Para garantir que a variável é enviada como número: `"quantidade": {{ qtd }}` (sem aspas, desde que qtd contenha apenas dígitos).

**JSON com campos sensíveis hardcoded:** senhas e tokens hardcoded no body (`"senha": "minhasenha123"`) ficam visíveis na collection compartilhada com o time. Usar sempre variáveis de ambiente: `"senha": "{{ user_password }}"` — o valor real fica apenas no environment local (que não é commitado no Git).

## 🧩 Quiz de Fixação

1. Um desenvolvedor cola o JSON abaixo no editor do Insomnia e o indicador de erro aparece. Por que e como corrigir?
```json
{
  "nome": 'João Silva',
  "ativo": true,
  "roles": ["admin", "editor"],
}
```

2. Uma API de pagamentos espera o payload `{"valor": 99.90, "parcelas": 3}`. O desenvolvedor configura o environment com `valor: 99.90` e escreve no body: `{"valor": "{{ valor }}", "parcelas": 3}`. A API retorna erro 422 "valor deve ser número". O que está errado e como corrigir?

3. Uma requisição POST cria um usuário e retorna `{"id": 789, "nome": "Maria"}`. A próxima requisição PUT `/usuarios/789/perfil` precisa usar o ID retornado no body: `{"usuario_id": 789, "foto": "url_da_foto"}`. Como configurar isso com Template Tag para eliminar a necessidade de copiar o ID manualmente?

**Respostas:**

1) **Dois erros:** (a) **Aspas simples:** `'João Silva'` — JSON exige aspas duplas. Corrigir para `"João Silva"`; (b) **Trailing comma:** a vírgula após `"editor"` (último elemento do array `roles`) e após o campo `roles` são ambas inválidas em JSON estrito. Corrigir removendo as vírgulas finais. JSON corrigido:
```json
{
  "nome": "João Silva",
  "ativo": true,
  "roles": ["admin", "editor"]
}
```

2) O problema é que `"{{ valor }}"` (com aspas) envia a variável como **string JSON** — o valor enviado é literalmente `"99.90"` (com aspas), não o número `99.90`. A API esperava um número e recebeu uma string, gerando o erro 422. **Correção:** remover as aspas ao redor da Template Tag: `{"valor": {{ valor }}, "parcelas": 3}`. Sem aspas, o Insomnia insere `99.90` diretamente — JSON válido com número. Verificar no Timeline que o body enviado é `{"valor":99.90,"parcelas":3}` e não `{"valor":"99.90","parcelas":3}`.

3) No body do PUT, usar Template Tag do tipo **Response**: `{"usuario_id": {{ _.response.body.id }}, "foto": "url_da_foto"}`. Configurar a Tag para: (a) apontar para o request "POST /usuarios" (pelo nome ou ID); (b) extrair o campo `id` via JSON Path `$.id` ou Body Attribute `id`; (c) selecionar "Latest" para pegar sempre a resposta mais recente. Com isso, ao enviar o PUT, o Insomnia automaticamente busca o `id` da última resposta do POST e o insere no body. O ID `789` é inserido como número (sem aspas na template tag), satisfazendo a tipagem esperada pela API.
