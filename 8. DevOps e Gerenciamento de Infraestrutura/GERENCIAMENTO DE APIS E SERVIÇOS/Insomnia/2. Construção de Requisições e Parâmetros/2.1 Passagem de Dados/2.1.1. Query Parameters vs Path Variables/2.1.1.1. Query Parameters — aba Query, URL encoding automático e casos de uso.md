### Query Parameters — aba Query, URL encoding automático e casos de uso

Query Parameters são pares `chave=valor` adicionados ao final de uma URL após o `?`. No Insomnia, eles podem ser gerenciados via aba **Query** (interface visual) ou diretamente na barra de URL — com a vantagem de o Insomnia fazer o **URL encoding automático** de caracteres especiais, evitando erros manuais de encoding que tornam requisições inválidas.

---

## Como o Insomnia gerencia Query Parameters

```
Opção 1 — Aba "Query" (recomendado):
  Interface visual com campos Chave/Valor separados
  → URL construída automaticamente com & e encoding correto
  → Cada parâmetro pode ser habilitado/desabilitado com checkbox
  → Facilidade para adicionar, remover e reordenar

Opção 2 — Diretamente na URL:
  Digitar manualmente: https://api.exemplo.com/produtos?cat=eletronicos&page=2
  → Funciona, mas sem encoding automático
  → Difícil de manter com muitos parâmetros
  → O Insomnia sincroniza bidirecional: digitar na URL aparece na aba Query e vice-versa
```

### Interface da aba Query

```
URL: https://api.exemplo.com/produtos

Aba Query:
  ┌─────────────────────────────────────────────┐
  │ ☑  categoria    │  eletrônicos              │
  │ ☑  page         │  2                        │
  │ ☑  limit        │  20                       │
  │ ☑  sort         │  preco_asc                │
  │ ☐  debug        │  true      ← desabilitado │
  └─────────────────────────────────────────────┘

URL resultante gerada:
  https://api.exemplo.com/produtos?categoria=eletr%C3%B4nicos&page=2&limit=20&sort=preco_asc
                                                  ↑
                                    "ô" encodado automaticamente como %C3%B4

O parâmetro "debug" está desmarcado → não aparece na URL
```

## URL Encoding automático — por que importa

Caracteres especiais na URL precisam ser percent-encoded para ser válidos. O Insomnia faz isso automaticamente ao usar a aba Query.

```
Exemplos de encoding automático:

Valor que você digita    → URL encoding aplicado
──────────────────────────────────────────────────────
café & bolo              → caf%C3%A9%20%26%20bolo
João Silva               → Jo%C3%A3o%20Silva
produto/especial         → produto%2Fespecial
100% desconto            → 100%25%20desconto
data=2024-01-15          → data%3D2024-01-15  (quando valor interno contém =)
chave[0]                 → chave%5B0%5D

Sem encoding (digitado na URL manualmente):
  ?nome=café & bolo
  → Parser vê: nome=café e bolo (dois params: nome e bolo)
  → Resultado incorreto!

Com encoding via aba Query:
  ?nome=caf%C3%A9%20%26%20bolo
  → Parser vê: nome=café & bolo (um param com valor correto)
```

## Usando variáveis do ambiente em Query Params

```
Combinação Query Params + Environments:

Environment "Dev":
  base_url: https://api-dev.empresa.com
  page_size: 10
  tenant_id: tenant-dev-001

Environment "Prod":
  base_url: https://api.empresa.com
  page_size: 50
  tenant_id: tenant-prod-001

URL base: {{ base_url }}/produtos

Aba Query:
  limit    → {{ page_size }}
  tenant   → {{ tenant_id }}
  page     → 1

URL gerada no Dev:
  https://api-dev.empresa.com/produtos?limit=10&tenant=tenant-dev-001&page=1

URL gerada no Prod (só mudando o ambiente):
  https://api.empresa.com/produtos?limit=50&tenant=tenant-prod-001&page=1
```

## Casos de uso mais comuns

### Filtragem

```
GET /produtos
  aba Query:
    categoria → eletrônicos
    marca     → samsung
    preco_min → 100
    preco_max → 5000
    ativo     → true

URL: /produtos?categoria=eletr%C3%B4nicos&marca=samsung&preco_min=100&preco_max=5000&ativo=true
```

### Paginação

```
GET /usuarios
  aba Query:
    page    → 3
    limit   → 20

URL: /usuarios?page=3&limit=20

Alternativas de paginação que você pode testar:
  offset/limit:  ?offset=40&limit=20
  cursor:        ?cursor=eyJpZCI6NDJ9&first=20
  after/first:   ?after=abc123&first=10  (Relay/GraphQL)
```

### Ordenação

```
GET /pedidos
  aba Query:
    sort  → data_criacao
    order → desc

URL: /pedidos?sort=data_criacao&order=desc
```

### Busca e filtragem textual

```
GET /produtos
  aba Query:
    q → notebook gamer

URL: /produtos?q=notebook%20gamer

Nota: o espaço vira %20 automaticamente — sem o encoding,
      a URL ficaria /produtos?q=notebook gamer (inválida)
```

### Múltiplos valores para o mesmo parâmetro (arrays)

```
O Insomnia permite adicionar a mesma chave múltiplas vezes na aba Query:

  aba Query:
    tag → javascript
    tag → python
    tag → go

URL: /produtos?tag=javascript&tag=python&tag=go

Isso é equivalente a arrays — o servidor recebe uma lista de valores para "tag"
```

## Habilitando e desabilitando parâmetros

Uma das funcionalidades mais práticas do Insomnia: você pode **desmarcar** um parâmetro para excluí-lo temporariamente da URL sem deletá-lo.

```
Uso prático — testar com e sem filtro:

Com filtro ativo:
  ☑ status → pendente

GET /pedidos?status=pendente    → retorna apenas pedidos pendentes

Desmarcar "status":
  ☐ status → pendente

GET /pedidos    → retorna todos os pedidos (sem filtro)

Utilidade:
  → Comparar comportamento da API com e sem parâmetro
  → Manter parâmetros "opcionais" prontos mas desativados
  → Testar defaults da API quando parâmetro está ausente
  → Evitar deletar e recriar parâmetros frequentemente
```

## Inspecionando a URL final — o que é enviado de verdade

O Insomnia mostra exatamente o que foi enviado na aba **"Timeline"** após a requisição:

```
Timeline (após enviar):
  ─────────────────────────────────────────────────────────
  GET /produtos?categoria=eletr%C3%B4nicos&page=2&limit=20
  Host: api.empresa.com
  User-Agent: insomnia/9.3.0
  Authorization: Bearer eyJ...
  Accept: */*
  ─────────────────────────────────────────────────────────

Aqui você vê:
  → A URL exatamente como foi enviada (com encoding)
  → Todos os headers (incluindo os da pasta pai)
  → O método HTTP
  → Útil para confirmar que o encoding está correto
  → Útil para copiar e colar como cURL para compartilhar com o time
```

## Erros comuns e armadilhas

**Digitar query params diretamente na URL com caracteres especiais:** `?nome=João Silva` na barra de URL sem passar pela aba Query pode não ser encodado corretamente dependendo da versão do Insomnia. Sempre usar a aba Query para parâmetros com caracteres especiais.

**Confundir Query Param com Path Variable:** `GET /usuarios?id=123` (query param — filtra a coleção) vs `GET /usuarios/123` (path variable — identifica o recurso). Para IDs de recursos específicos, o caminho correto é path variable. Query params são para filtros e modificadores.

**Deixar parâmetros de debug ativos em requisições compartilhadas:** se você adicionou `?debug=true` para testar e vai compartilhar a collection com o time, lembre de desmarcar o parâmetro de debug — ou ele vai nas requisições de outros desenvolvedores também.

## 🧩 Quiz de Fixação

1. Você precisa buscar produtos com o nome "notebook c/ SSD 512GB". Como o Insomnia lida com os caracteres `c/` e os espaços, e como verificar que o encoding está correto?

2. Uma API de relatórios aceita múltiplos filtros de data: você quer testar com `data_inicio=2024-01-01` e `data_fim=2024-01-31`, mas às vezes quer testar sem o filtro de data. Como configurar isso eficientemente no Insomnia sem precisar deletar e recriar os parâmetros?

3. Qual é a diferença prática entre adicionar `?status=ativo` via aba Query vs digitar diretamente na URL, e em qual situação cada abordagem é mais adequada?

**Respostas:**

1) O Insomnia encodará automaticamente via aba Query: espaços viram `%20` e `/` vira `%2F`. A URL resultante seria `/produtos?q=notebook%20c%2F%20SSD%20512GB`. Para verificar: após enviar a requisição, abrir a aba **Timeline** que mostra a URL exatamente como foi enviada. Se os caracteres aparecem corretamente encodados no Timeline, o servidor recebeu o valor correto. Alternativamente, comparar o encoding com a saída de `encodeURIComponent("notebook c/ SSD 512GB")` no console do browser.

2) Adicionar ambos os parâmetros na aba Query e **deixar os dois marcados** inicialmente. Quando quiser testar sem filtro de data: **desmarcar** os dois checkboxes (☐ data_inicio, ☐ data_fim). Os parâmetros ficam salvos com seus valores mas não são enviados na URL. Quando quiser ativar novamente: marcar novamente. Isso é muito mais eficiente do que deletar e recriar — os valores são preservados entre os toggles.

3) **Via aba Query:** o Insomnia aplica URL encoding automático, o parâmetro aparece em linha separada (fácil de ver/editar), pode ser habilitado/desabilitado individualmente, e a URL é sincronizada bidirecionalmente. **Digitando na URL diretamente:** mais rápido para parâmetros simples sem caracteres especiais (números, letras básicas), mas sem encoding automático e sem a interface visual de toggle. **Quando usar cada um:** aba Query é sempre preferível para manutenção e parâmetros com caracteres especiais. Digitar na URL é adequado apenas para testes rápidos e descartáveis com valores simples como `?page=1&limit=10`.
