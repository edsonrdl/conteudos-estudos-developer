### Calculadoras de custos AWS — estimar, analisar e justificar investimentos

A AWS oferece um ecossistema de ferramentas para gestão financeira de nuvem, cada uma com um propósito distinto: estimar custos antes de criar recursos, analisar o que já está sendo gasto, prever o futuro e identificar oportunidades de economia. Saber qual ferramenta usar em cada momento é fundamental para decisões financeiras informadas.

---

## O mapa das ferramentas de custo AWS

```
ANTES de criar recursos          APÓS criar recursos
────────────────────────         ────────────────────────
AWS Pricing Calculator           AWS Cost Explorer
  → Estimar custo de               → Analisar custo histórico
    nova arquitetura                 e prever o futuro

AWS Migration Evaluator          AWS Cost and Usage Report
  → Business case de               → Dados granulares por
    migração on-prem→cloud           recurso/hora/tag (para BI)

                                 AWS Budgets
                                   → Alertas proativos de gasto

                                 AWS Compute Optimizer
                                   → Recomendações de right-sizing

                                 Savings Plans / RI Recommendations
                                   → Otimizar modelo de precificação
```

## 1. AWS Pricing Calculator — estimativa antes de criar

### O que é e para que serve

```
Acesso: calculator.aws (gratuito, sem login obrigatório)

Casos de uso:
  ├── Estimar custo de nova aplicação antes de construir
  ├── Comparar arquiteturas (ex: EC2 vs. ECS vs. Lambda)
  ├── Preparar orçamento para aprovação de budget
  ├── Comparar custo entre regiões
  └── Montar proposta de migração para stakeholders
```

### Como usar na prática

```
Passo 1: Criar uma estimativa
  → "Create estimate" → nomear o projeto
  → Opcional: selecionar região padrão

Passo 2: Adicionar serviços
  Exemplo — Arquitetura web 3-tier:

  [EC2]
  ├── Região: sa-east-1 (São Paulo)
  ├── Tipo: m6g.xlarge (Graviton, 4 vCPU, 16GB)
  ├── Quantidade: 3 instâncias
  ├── Uso: 730h/mês (24/7)
  ├── OS: Linux
  └── Modelo: On-Demand
  Resultado: $XX.XX/mês

  [RDS]
  ├── Engine: PostgreSQL
  ├── Tipo: db.r6g.large (Graviton)
  ├── Multi-AZ: sim
  ├── Storage: 500GB gp3
  └── Modelo: On-Demand
  Resultado: $XX.XX/mês

  [ALB]
  ├── LCUs processadas: estimativa de tráfego
  └── Resultado: $XX.XX/mês

  [S3]
  ├── Storage: 2TB
  ├── GET requests: 10 milhões/mês
  └── Resultado: $XX.XX/mês

Passo 3: Revisar e ajustar
  → Total mensal estimado: $XXX.XX
  → Exportar: CSV, PDF
  → Compartilhar via link público (URL permanente da estimativa)
```

### Comparando modelos de precificação na calculadora

```
A calculadora permite comparar On-Demand vs. Reserved side-by-side:

Exemplo: m6i.xlarge, us-east-1, Linux, 24/7

On-Demand:
  $0.192/hora × 730h = $140.16/mês = $1.681.92/ano

Reserved 1 ano (No Upfront):
  $0.121/hora × 730h = $88.33/mês = $1.059.96/ano
  Economia vs On-Demand: $621.96/ano (37%)

Reserved 3 anos (Partial Upfront):
  $1.460 upfront + $0.058/hora × 8.760h = $1.968.08 total
  = $54.67/mês equivalente
  Economia vs On-Demand: 51%

Savings Plans (Compute, 1 ano, No Upfront):
  Similar ao Reserved 1yr mas com flexibilidade de tipo/região
  ~37% de desconto aplicável

→ A calculadora mostra esses cenários automaticamente
  ao selecionar a opção de Reserved ou Savings Plans
```

### Limitações importantes

```
A calculadora é uma ESTIMATIVA, não uma garantia:
  ├── Data transfer depende de uso real (impossível estimar com precisão)
  ├── Requests (S3, API Gateway) variam com o tráfego real
  ├── Custos de suporte não incluídos por padrão
  ├── Preços mudam (AWS reduz preços periodicamente)
  └── Custo de desenvolvimento e operação não incluídos

Boas práticas:
  → Adicionar 15-20% de buffer para imprevistos
  → Incluir custo de data transfer (frequentemente subestimado)
  → Recalcular após 3-6 meses com dados reais do Cost Explorer
```

## 2. AWS Cost Explorer — análise do que já existe

### O que é e para que serve

```
Acesso: Console AWS → Billing → Cost Explorer
Custo: gratuito para uso básico
       $0.01 por consulta de API (para integração programática)

Casos de uso:
  ├── Entender para onde vai o dinheiro (por serviço, região, tag)
  ├── Detectar anomalias de custo (pico inesperado)
  ├── Prever gasto do mês atual e próximos 12 meses
  ├── Identificar oportunidades de Reserved Instances
  └── Analisar tendências ao longo do tempo
```

### Funcionalidades principais

```
1. Visualizações de custo:

   Por serviço (visão padrão):
   ┌─────────────────────────────────────────┐
   │ Custo por serviço — Últimos 6 meses     │
   │                                         │
   │ EC2-Instances  ████████████  $28.400    │
   │ RDS            █████         $8.200     │
   │ S3             ██            $2.100     │
   │ CloudFront     █             $1.400     │
   │ Outros         ███           $4.900     │
   │                                         │
   │ Total: $45.000/mês                      │
   └─────────────────────────────────────────┘

   Por tag (requer tagging adequado):
   ├── Product=checkout: $12.000
   ├── Product=search: $8.000
   ├── Environment=staging: $7.000  ← por que staging custa tanto?
   └── Team=data-science: $18.000

   Por conta (Organizations):
   ├── Conta de produção: $35.000
   ├── Conta de staging: $7.000
   └── Conta de dev: $3.000

2. Filtros disponíveis:
   ├── Serviço AWS
   ├── Região
   ├── Tag
   ├── Conta (em Organizations)
   ├── Tipo de instância
   ├── Tipo de uso (BoxUsage, DataTransfer, etc.)
   └── Modelo de precificação (On-Demand vs. Reserved vs. Spot)
```

### Forecasting — previsão de gastos

```
Cost Explorer → Forecasting

Baseado em:
  → 12 meses de histórico de uso
  → ML para identificar padrões sazonais
  → Tendência de crescimento

Exemplo de previsão:
  Histórico:
  Jan: $38.000
  Fev: $40.000
  Mar: $42.000 (atual, em andamento)
  
  Previsão:
  Mar (fim do mês): $45.000 (estimado)
  Abr: $46.500
  Mai: $47.800
  
  Alerta: "Você está no caminho para gastar $45.000 este mês"
  → Configurar Budget para alertar se ultrapassar $42.000

Acurácia: melhor com mais histórico e padrões regulares
           Workloads com crescimento acelerado podem ter
           previsão subestimada
```

### Recommendations — oportunidades de economia

```
Cost Explorer → Savings Plans Recommendations:
  
  Análise automática do seu uso atual:
  "Você usou em média $15.23/hora de EC2 e Lambda nos últimos 30 dias.
   Se comprar $10/hora de Compute Savings Plans por 1 ano (no upfront),
   economizará $12.847/ano (23% de desconto no uso coberto)"
  
  Mostra:
  ├── Quanto comprometer ($/hora)
  ├── Cobertura estimada do uso atual
  ├── Economia anual projetada
  └── Break-even point (quando o desconto paga o compromisso)

Cost Explorer → Reserved Instance Recommendations:
  Similar, mas por tipo específico de instância
  Recomendação por serviço (EC2, RDS, ElastiCache, etc.)
```

## 3. AWS Cost and Usage Report (CUR) — dados granulares

```
Para quem precisa de análise além do Cost Explorer:

O CUR exporta para S3:
  ├── Custo por hora para cada recurso individual
  ├── Detalhes de uso (tipo, quantidade, preço unitário)
  ├── Tags de alocação de custo
  └── Amortização de Reserved Instances/Savings Plans

Consulta via Athena:
  -- Qual instância EC2 custou mais no último mês?
  SELECT
    line_item_resource_id,
    SUM(line_item_unblended_cost) as custo_total
  FROM cur_table
  WHERE line_item_product_code = 'AmazonEC2'
    AND month = 3 AND year = 2024
  GROUP BY 1
  ORDER BY 2 DESC
  LIMIT 10;

Visualização via QuickSight:
  Dashboard de FinOps com:
  ├── Custo por produto/time (tags)
  ├── Tendência mensal
  ├── Cobertura de Savings Plans
  └── Top 10 recursos mais caros

Quando usar:
  ├── Chargeback entre departamentos/times
  ├── FinOps avançado com análise customizada
  └── Quando Cost Explorer não tem granularidade suficiente
```

## 4. AWS Budgets — controle proativo

```
Tipos de Budget e alertas:

1. Cost Budget (mais comum):
   Nome: "Produção - Custo Mensal"
   Valor: $45.000/mês
   
   Alertas configurados:
   ├── 80% real ($36.000): email para time de FinOps
   ├── 90% real ($40.500): Slack + email para manager
   ├── 100% real ($45.000): PagerDuty para CTO
   └── 110% previsão ($49.500): alerta antecipado

2. Usage Budget:
   "Lambda — Execuções Mensais"
   Limite: 50 milhões de invocações
   Alerta em 90%: investigar se há loop ou uso inesperado

3. Savings Plans Coverage Budget:
   "Cobertura de Savings Plans"
   Meta: 80% do uso coberto por Savings Plans
   Alerta se cair abaixo de 70%: renovar ou comprar mais

4. Actions automáticas (Budget Actions):
   Se gasto ultrapassar X:
   ├── Aplicar política IAM que bloqueia criação de novos recursos
   ├── Enviar notificação para SNS
   └── Executar SSM Document (automação customizada)
   
   Caso de uso: sandbox de desenvolvimento que não pode
                ultrapassar $500/mês — ao atingir, bloqueia
                automaticamente novos recursos
```

## Montando um business case de migração

```
Estrutura para apresentar ao board/CFO:

SLIDE 1 — Situação atual (TCO on-premises):
  Hardware + Infraestrutura física + Energia + Equipe + Licenças
  Total: R$ 94.167/mês = R$ 1.130.000/ano

SLIDE 2 — Custo projetado na AWS:
  Baseado no AWS Migration Evaluator (dados reais de utilização)
  Total: R$ 46.333/mês = R$ 556.000/ano

SLIDE 3 — Análise de retorno:
  Economia anual: R$ 574.000 (51%)
  Custo de migração (única vez): R$ 200.000
  Break-even: ~5 meses
  ROI em 3 anos: ~760%

SLIDE 4 — Benefícios não-financeiros:
  ├── Agilidade: provisionamento em minutos vs. meses
  ├── Escalabilidade: cresce com o negócio sem CapEx adicional
  ├── Resiliência: Multi-AZ, backups automáticos
  ├── Segurança: conformidade AWS (SOC2, PCI-DSS, ISO 27001)
  └── Inovação: equipe liberada de manutenção de hardware

SLIDE 5 — Riscos e mitigação:
  ├── Risco: lock-in de fornecedor
  │   Mitigação: arquitetura cloud-agnostic (Kubernetes, Terraform)
  ├── Risco: custo de egress
  │   Mitigação: CloudFront + arquitetura que minimiza saída
  └── Risco: curva de aprendizado
      Mitigação: treinamento + AWS Partner para migração
```

## 🧩 Quiz de Fixação

1. Um arquiteto precisa estimar o custo de uma nova aplicação antes de apresentar o projeto ao board. Qual ferramenta AWS usar e quais serviços incluir além do óbvio (EC2 e RDS)?
2. A fatura de março veio 40% maior que fevereiro sem crescimento de usuários. Qual sequência de passos no Cost Explorer você usaria para identificar a causa?
3. Qual a diferença fundamental entre AWS Pricing Calculator e AWS Cost Explorer, e quando cada um é a ferramenta correta?

**Respostas:**
1) AWS Pricing Calculator (calculator.aws). Além de EC2 e RDS, incluir: ALB (Application Load Balancer) — frequentemente esquecido, cobra por hora + LCUs; Data Transfer — egress para internet é o custo mais subestimado em estimativas; S3 — storage + requests (GET/PUT separados); CloudWatch — logs tem custo de ingestão e armazenamento; NAT Gateway — se há subnets privadas acessando internet; Route 53 — hosted zones + queries; e adicionar 15-20% de buffer para imprevistos como requests não mapeados e custo de desenvolvimento.
2) Sequência no Cost Explorer: (1) Filtrar por serviço, comparar março vs. fevereiro — identificar qual serviço cresceu (ex: EC2 aumentou 60%); (2) Filtrar pelo serviço problemático, detalhar por tipo de uso — identificar se é BoxUsage (instâncias rodando) ou DataTransfer (saída de dados); (3) Se EC2: filtrar por tipo de instância e região — identificar instâncias novas ou que passaram a rodar mais horas; (4) Filtrar por tag de ambiente/produto — identificar qual projeto/time é responsável; (5) Verificar Cost Anomaly Detection — se configurado, pode já ter o alerta com o recurso específico. A maioria dos casos se resolve no passo 1-3.
3) AWS Pricing Calculator é usada ANTES de criar recursos — você estima o custo de uma arquitetura hipotética inserindo manualmente os serviços, quantidades e configurações. É baseada em estimativas e padrões teóricos de uso. AWS Cost Explorer é usada DEPOIS — analisa dados reais de uso e gasto, gera previsões baseadas em histórico real e identifica oportunidades de otimização com base no comportamento atual. Pricing Calculator = estimativa prospectiva (business case, orçamento). Cost Explorer = análise retrospectiva e proativa (FinOps, otimização, forecasting).
