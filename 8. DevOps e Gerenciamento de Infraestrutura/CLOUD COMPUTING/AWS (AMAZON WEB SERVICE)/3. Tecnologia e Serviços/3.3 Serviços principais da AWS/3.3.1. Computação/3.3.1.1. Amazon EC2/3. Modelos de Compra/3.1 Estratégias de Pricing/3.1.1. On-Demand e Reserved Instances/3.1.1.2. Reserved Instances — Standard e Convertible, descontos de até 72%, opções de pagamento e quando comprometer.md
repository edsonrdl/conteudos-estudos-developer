### Reserved Instances — compromisso de capacidade com descontos de até 72%

Reserved Instances (RIs) não reservam literalmente um servidor físico para você — elas são um **compromisso de uso** com a AWS em troca de desconto. Ao afirmar "vou usar este tipo de instância por 1 ou 3 anos", a AWS oferece até 72% de desconto sobre o preço On-Demand. O desconto é aplicado automaticamente quando você roda instâncias que correspondem ao perfil da RI comprada.

---

## Como Reserved Instances funcionam

A RI é um atributo de billing, não um servidor dedicado. Quando você compra uma RI e inicia uma instância correspondente, a AWS aplica o desconto automaticamente na fatura — você não precisa "usar" a RI explicitamente.

```
Fluxo de aplicação de desconto:
                                          
[Você compra]                [Você inicia]
RI: m7g.large               Instância m7g.large
us-east-1a                  us-east-1a
Linux                       Linux (On-Demand normal)
1 ano                            │
    │                            │
    └────────────────────────────┘
             AWS aplica desconto automaticamente
             na cobrança horária da instância
```

Se você compra uma RI mas não roda a instância correspondente, **continua sendo cobrado** pela RI — o compromisso existe independentemente do uso. Isso é a principal armadilha das RIs.

---

## Tipos de Reserved Instances

### Standard Reserved Instances

RIs Standard têm o maior desconto (até 72%) mas a menor flexibilidade. Os atributos que definem a RI são **fixos** após a compra:

- Família de instância (ex: `m7g`)
- Tamanho da instância (ex: `large`)
- Região e Availability Zone (ou regional)
- Sistema operacional (Linux, Windows, RHEL...)
- Tenancy (shared ou dedicated)

**Modificações permitidas após a compra (sem troca):**
- Availability Zone dentro da mesma região
- Tamanho dentro da mesma família (ex: `m7g.large` → dois `m7g.small`) — *instance size flexibility*

**Não é possível alterar:** família de instância, região, SO ou tenancy.

### Convertible Reserved Instances

RIs Convertible têm desconto menor (até ~54%) mas permitem **trocar os atributos** durante a vigência:

- Pode trocar família (ex: `m7g` → `c7g`)
- Pode trocar tamanho (ex: `large` → `2xlarge`, desde que o valor seja igual ou maior)
- Pode trocar SO ou tenancy
- Pode trocar para Graviton se estava em Intel

```
Comparativo Standard vs Convertible:
──────────────────────────────────────────────────────────
                    │ Standard RI      │ Convertible RI
────────────────────┼──────────────────┼──────────────────
Desconto máximo     │ ~72%             │ ~54%
Troca de família    │ Não              │ Sim
Troca de tamanho    │ Limitada         │ Sim (igual ou maior valor)
Venda no Marketplace│ Sim              │ Não
Flexibilidade       │ Baixa            │ Alta
Quando usar         │ Workload estável │ Workload em evolução
──────────────────────────────────────────────────────────
```

## Opções de pagamento

A mesma RI pode ser comprada com três formas de pagamento, cada uma com desconto diferente:

| Opção | Pagamento | Desconto (exemplo m7g.large, 1 ano) | Quando usar |
|---|---|---|---|
| **No Upfront** | Mensal, sem entrada | ~37% | Fluxo de caixa restrito |
| **Partial Upfront** | Parte adiantada + mensal | ~40% | Equilíbrio |
| **All Upfront** | Tudo adiantado | ~42% | Máximo desconto, capital disponível |

```
Custo total para m7g.large, 1 ano (us-east-1):
On-Demand:        $0.0816/h × 8.760h = $714/ano
No Upfront RI:    $0.051/h  × 8.760h = $447/ano  (economia: $267)
Partial Upfront:  ~$425/ano                        (economia: $289)
All Upfront:      ~$413/ano                        (economia: $301)
```

Para 3 anos com All Upfront, o desconto total pode chegar a 72% sobre o On-Demand equivalente.

## Escopo: Regional vs Zonal

Ao comprar uma RI, você escolhe o escopo:

**Regional (recomendado na maioria dos casos):**
- O desconto se aplica a qualquer AZ na região
- Tem *instance size flexibility* — uma RI `m7g.xlarge` cobre dois `m7g.large`
- Mais flexível para Auto Scaling (instâncias podem subir em qualquer AZ)

**Zonal:**
- O desconto se aplica apenas à AZ específica
- **Garante capacidade reservada** naquela AZ (importante para compliance ou localidade)
- Sem instance size flexibility

```
Instance Size Flexibility (apenas Regional, Standard Linux):
                                                    
RI comprada: m7g.xlarge (= 4 unidades de normalização)
                                                    
Pode cobrir:
  ├── 1× m7g.xlarge    (4 unidades)   ✓
  ├── 2× m7g.large     (2×2 = 4)      ✓
  ├── 4× m7g.small     (4×1 = 4)      ✓
  ├── 1× m7g.large + 2× m7g.small     ✓
  └── 0.5× m7g.2xlarge (8÷2 = 4)     ✓ (cobre parcialmente)
```

Unidades de normalização por tamanho: nano=0.25, micro=0.5, small=1, medium=2, large=4, xlarge=8, 2xlarge=16...

## Reserved Instance Marketplace

RIs Standard não utilizadas ou indesejadas podem ser **vendidas no Reserved Instance Marketplace** da AWS — um mercado peer-to-peer onde terceiros compram suas RIs com desconto.

Regras relevantes:
- Apenas **Standard** RIs podem ser vendidas (Convertible não)
- A RI deve ter ao menos 1 mês de vigência restante
- A AWS retém uma taxa de 12% sobre o valor de venda
- O comprador assume o prazo restante da RI

Isso torna as Standard RIs menos arriscadas para compromissos longos: se o workload mudar, é possível recuperar parte do valor investido.

---

## Quando comprometer com Reserved Instances

A decisão de comprar RIs deve ser baseada em dados de uso histórico, não em suposições:

**Critérios para comprar RI:**
1. A instância roda mais de **70% do tempo** nos últimos 3-6 meses
2. O tipo de instância é **estável** — sem expectativa de mudança de família em breve
3. O workload é **previsível** — sem risco de descomissionamento em menos de 1 ano

**Ferramenta nativa:** AWS Cost Explorer tem a aba **"Reserved Instance Recommendations"** — analisa seu histórico de uso e recomenda quais RIs comprar, com estimativa de economia e payback period.

```
Processo recomendado de compra de RI:
                                             
1. Rodar workload On-Demand por 2-3 meses
           │
           ▼
2. Analisar no Cost Explorer:
   - Quais instâncias rodam >70% do tempo?
   - Qual o custo On-Demand mensal delas?
           │
           ▼
3. Verificar recomendações de RI do Cost Explorer
           │
           ▼
4. Decidir: Standard (mais desconto, workload fixo)
            ou Convertible (menos desconto, workload em evolução)?
           │
           ▼
5. Comprar com All Upfront se capital disponível
   (máximo desconto), caso contrário No Upfront
           │
           ▼
6. Monitorar utilização mensalmente no Cost Explorer
   (meta: >90% de utilização da RI)
```

## Comparativo com Savings Plans

Desde 2019, a AWS oferece **Savings Plans** como alternativa mais flexível às RIs. Vale entender a diferença:

| Aspecto | Reserved Instances | Compute Savings Plans |
|---|---|---|
| Compromisso | Tipo específico de instância | $/hora de gasto em compute |
| Flexibilidade | Baixa (Standard) / Média (Convertible) | Alta — cobre EC2, Lambda, Fargate |
| Desconto máximo EC2 | ~72% | ~66% |
| Troca automática | Não | Sim — aplica automaticamente onde for mais barato |
| Marketplace | Sim (Standard) | Não |
| Recomendação para novos projetos | Workloads muito estáveis | Maioria dos casos |

Para a maioria dos novos projetos, **Compute Savings Plans** oferece quase o mesmo desconto com muito mais flexibilidade. RIs ainda fazem sentido quando o desconto incremental (até 72% vs 66%) justifica a rigidez, ou quando é necessário reservar capacidade em uma AZ específica.

## Erros comuns e armadilhas

**Comprar RI sem dados históricos:** comprar uma `r7i.4xlarge` RI porque "acha que vai usar" é arriscado. Se o workload mudar, você paga pela RI mesmo sem usar.

**Misturar SO na RI:** uma RI Linux não cobre instâncias Windows e vice-versa. Checar o SO antes de comprar evita cobranças duplas.

**Ignorar a utilização da RI:** RIs subutilizadas são custo desperdiçado. Cost Explorer mostra o percentual de utilização de cada RI — meta é acima de 90%.

**Não considerar Savings Plans primeiro:** para a maioria dos times, Compute Savings Plans são mais simples de gerenciar e cobrem mudanças de workload automaticamente.

**Comprar RI para instâncias Spot:** RIs e Spot são modelos separados. Instâncias Spot não recebem desconto de RI — são cobradas pelo preço Spot independentemente.

## 🧩 Quiz de Fixação

1. Você tem uma RI Standard Regional `m7g.2xlarge` comprada com escopo Linux. Seu time decide escalar horizontalmente e agora roda quatro `m7g.large` em vez de uma `m7g.2xlarge`. O desconto da RI ainda se aplica? Explique como.

2. Por que uma RI Convertible pode ser a escolha certa mesmo tendo desconto menor que a Standard, para um time que está migrando gradualmente para Graviton?

3. Qual é o risco fundamental de comprar All Upfront RI para um workload novo, e como o Reserved Instance Marketplace mitiga (parcialmente) esse risco?

**Respostas:**

1) Sim, o desconto se aplica integralmente graças à **instance size flexibility** das RIs Standard Regional. A `m7g.2xlarge` equivale a 16 unidades de normalização. Quatro `m7g.large` equivalem a 4×4 = 16 unidades — exatamente o mesmo valor. A AWS aplica automaticamente o desconto às quatro instâncias `large`, como se fossem uma `2xlarge`. Essa flexibilidade só existe para RIs regionais (não zonais), Linux/Unix, e dentro da mesma família de instância.

2) A RI Convertible permite **trocar atributos durante a vigência**, incluindo família de instância. Se o time está em `m6i` (Intel) e planeja migrar para `m7g` (Graviton) nos próximos meses, uma Standard RI `m6i` seria desperdiçada quando a migração ocorrer — o desconto não se transfere para outra família. Com Convertible, é possível converter a RI `m6i` para `m7g` pagando apenas a diferença de valor (ou recebendo RIs adicionais se o novo tipo for mais barato), mantendo o desconto durante toda a transição.

3) O risco fundamental é o **pagamento antecipado de capacidade que pode não ser utilizada**: se o workload for descontinuado, reduzido ou migrado para outro tipo de instância, o valor pago no All Upfront não é reembolsável diretamente pela AWS. O **Reserved Instance Marketplace** mitiga isso parcialmente — é possível listar a RI Standard não utilizada para venda, recuperando o valor proporcional ao tempo restante (menos 12% de taxa da AWS). A mitigação é parcial porque o preço de mercado é determinado pela oferta e demanda de outros compradores, e pode ser menor que o valor investido, especialmente para RIs com pouco tempo restante ou de instâncias menos populares.
