### S3 Glacier — arquivamento de longo prazo, tempos de recuperação e custo

As classes Glacier do S3 são projetadas para dados que raramente ou nunca são acessados, mas que precisam ser preservados por meses, anos ou décadas. O trade-off é simples: armazenamento drasticamente mais barato em troca de latência de recuperação que pode variar de milissegundos a 12 horas. Escolher entre as três variantes do Glacier depende principalmente de quanto tempo você pode esperar quando precisar recuperar os dados.

## S3 Glacier Instant Retrieval

**Glacier Instant Retrieval** é para dados que são acessados raramente (uma vez por trimestre ou menos) mas exigem recuperação em **milissegundos** quando necessário. É o ponto de encontro entre armazenamento de arquivo barato e acesso imediato.

```
Características:
  Durabilidade:      99.999999999% (11 noves)
  Disponibilidade:   99.9%
  AZs:               ≥ 3
  Latência:          Milissegundos (mesmo que S3 Standard)
  Taxa de recuperação: $0.03/GB (vs $0.010 do Standard-IA)
  Mínimo de duração:   90 dias
  Mínimo de tamanho:   128 KB
  Preço armazenamento: $0.004/GB-mês (vs $0.0125 do Standard-IA = 68% mais barato)
```

### Comparativo Glacier Instant vs Standard-IA

```
Para dados acessados uma vez por trimestre (acesso muito infrequente):

1 TB armazenado, 50 GB acessados/trimestre (~17 GB/mês):

Standard-IA:
  Armazenamento: 1.024 × $0.0125 = $12.80/mês
  Recuperação:   17 GB × $0.010  = $0.17/mês
  Total:         ~$12.97/mês

Glacier Instant:
  Armazenamento: 1.024 × $0.004  = $4.10/mês
  Recuperação:   17 GB × $0.030  = $0.51/mês
  Total:         ~$4.61/mês   → 64% mais barato

Para dados acessados mensalmente (acesso mais frequente):
  Standard-IA:      ~$14.80/mês
  Glacier Instant:  ~$4.10 + (1.024 × 0.030) = ~$34.82/mês → mais caro!

Break-even: ~18% de acesso mensal é o ponto onde Glacier Instant
            se torna mais caro que Standard-IA.
```

### Quando usar Glacier Instant Retrieval

```
✓ Imagens médicas (radiografias, tomografias) — acessadas raramente
  mas devem estar disponíveis imediatamente se o paciente retornar
✓ Registros financeiros históricos — consultas eventuais mas urgentes
✓ Dados de compliance que podem ser auditados a qualquer momento
✓ Versões antigas de arquivos que podem precisar de restauração imediata
✓ Backups de recuperação de desastres com RTO baixo
```

## S3 Glacier Flexible Retrieval

**Glacier Flexible Retrieval** (anteriormente chamado apenas de "S3 Glacier") aceita latência de recuperação de minutos a horas em troca do menor custo de armazenamento entre as classes com acesso programático direto via S3.

```
Características:
  Durabilidade:      99.999999999%
  Disponibilidade:   99.99% (SLA de restauração)
  AZs:               ≥ 3
  Latência:          Varia por tipo de retrieval (ver abaixo)
  Mínimo de duração:   90 dias
  Mínimo de tamanho:   40 KB
  Preço armazenamento: $0.0036/GB-mês
```

### Tipos de retrieval no Glacier Flexible

```
Expedited:   1-5 minutos
  → Custo: $0.03/GB + $0.01/1.000 requisições
  → Para situações onde alguns minutos são aceitáveis
  → Capacidade pode não estar disponível em demanda alta
    (use Provisioned Capacity para garantir disponibilidade)

Standard:    3-5 horas
  → Custo: $0.01/GB + $0.05/1.000 requisições
  → O tipo padrão — equilíbrio custo/tempo para a maioria dos casos

Bulk:        5-12 horas
  → Custo: $0.0025/GB + $0.025/1.000 requisições
  → Mais barato — para recuperação de grandes volumes sem urgência
  → Ideal para migrações, análises batch não urgentes
```

### O processo de restauração — dois passos

Diferente das outras classes, objetos no Glacier Flexible não são acessados diretamente. O processo envolve **iniciar uma restauração** e depois **baixar a cópia temporária**:

```
Fluxo de restauração:

1. Iniciar restauração (async):
   aws s3api restore-object \
     --bucket meu-bucket \
     --key arquivo/backup-2023.tar.gz \
     --restore-request '{
       "Days": 3,
       "GlacierJobParameters": {"Tier": "Standard"}
     }'
   # Days: quantos dias a cópia restaurada fica disponível no S3 (1-30 dias)

2. Verificar se a restauração concluiu:
   aws s3api head-object \
     --bucket meu-bucket \
     --key arquivo/backup-2023.tar.gz
   # Resposta inclui:
   # "Restore": "ongoing-request=\"false\", expiry-date=\"2024-01-20T00:00:00.000Z\""
   # "ongoing-request=\"true\"" = ainda sendo restaurado

3. Após restauração concluída: baixar normalmente
   aws s3 cp s3://meu-bucket/arquivo/backup-2023.tar.gz ./backup.tar.gz
```

```python
# Automação via SDK — restaurar e aguardar
import boto3
import time

s3 = boto3.client('s3')

def restore_and_wait(bucket, key, days=3, tier='Standard'):
    # Iniciar restauração
    s3.restore_object(
        Bucket=bucket,
        Key=key,
        RestoreRequest={
            'Days': days,
            'GlacierJobParameters': {'Tier': tier}
        }
    )
    print(f"Restauração iniciada para {key}")
    
    # Aguardar conclusão (polling)
    while True:
        response = s3.head_object(Bucket=bucket, Key=key)
        restore_status = response.get('Restore', '')
        
        if 'ongoing-request="false"' in restore_status:
            print(f"Restauração concluída! Disponível até: {restore_status}")
            break
        
        print("Ainda restaurando... aguardando 5 minutos")
        time.sleep(300)  # verificar a cada 5 minutos
```

### Provisioned Capacity para Expedited

Para garantir disponibilidade de Expedited retrieval (1-5 minutos) mesmo em períodos de alta demanda na AWS:

```bash
# Comprar capacidade provisionada para Expedited (1 unidade = 3 retrievals por minuto)
aws glacier purchase-provisioned-capacity \
  --account-id -  # "-" usa a conta atual

# Custo: $100/mês por unidade de capacidade provisionada
# Cada unidade garante pelo menos 3 retrievals Expedited por minuto
```

## S3 Glacier Deep Archive

**Deep Archive** é a classe de armazenamento mais barata de toda a AWS — $0.00099/GB-mês, menos de 1/10 do S3 Standard. Projetada para dados que precisam ser retidos por anos ou décadas e raramente (ou nunca) serão acessados.

```
Características:
  Durabilidade:      99.999999999%
  Disponibilidade:   99.99% (SLA de restauração)
  AZs:               ≥ 3
  Mínimo de duração:   180 dias
  Mínimo de tamanho:   40 KB
  Preço armazenamento: $0.00099/GB-mês
```

### Tipos de retrieval no Deep Archive

```
Standard:  até 12 horas
  → Custo: $0.02/GB + $0.10/1.000 requisições
  → Para maioria dos casos de recuperação de Deep Archive

Bulk:      até 48 horas
  → Custo: $0.0025/GB + $0.025/1.000 requisições
  → Quando urgência não existe e custo é prioridade absoluta
```

### Casos de uso de Deep Archive

```
✓ Retenção regulatória de longo prazo:
  - Registros médicos por 7-10 anos (HIPAA)
  - Registros financeiros por 7 anos (SOX, BACEN)
  - E-mails corporativos por 5-7 anos
  - Gravações de chamadas por 5 anos

✓ Backups de última instância:
  - Backup final antes de descomissionar um sistema
  - Cópia de segurança de dados históricos sem valor operacional

✓ Preservação digital:
  - Arquivos de pesquisa científica (resultados de experimentos)
  - Acervos culturais e históricos
  - Logs de auditoria de longo prazo

Não adequado para:
✗ Qualquer dado que possa precisar de acesso em menos de 12 horas
✗ Backups de DR com RTO (Recovery Time Objective) < 12 horas
```

## Configurando classes Glacier via Lifecycle (recomendado)

Na prática, objetos raramente são enviados diretamente para Glacier. O mais comum é usar **Lifecycle Policies** para transição automática com o tempo (detalhado no arquivo de Lifecycle Policies):

```json
{
  "Rules": [{
    "ID": "arquivar-logs-antigos",
    "Status": "Enabled",
    "Filter": {"Prefix": "logs/"},
    "Transitions": [
      {
        "Days": 30,
        "StorageClass": "STANDARD_IA"
      },
      {
        "Days": 90,
        "StorageClass": "GLACIER_IR"
      },
      {
        "Days": 365,
        "StorageClass": "DEEP_ARCHIVE"
      }
    ],
    "Expiration": {
      "Days": 2555  // deletar após 7 anos (2555 dias)
    }
  }]
}
```

## Erros comuns e armadilhas

**Usar Glacier Flexible para backups de DR com RTO < 5 horas:** se o plano de recuperação de desastres exige restaurar em 4 horas, Glacier Flexible Standard (3-5h) está no limite e o Bulk (5-12h) está fora. Para RTO baixo, use Glacier Instant ou Standard-IA.

**Não contar o custo de retrieval na análise:** Glacier é barato para armazenar, mas caro para recuperar em grande volume. Uma restauração de 10 TB do Glacier Flexible Expedited custa: 10.000 GB × $0.03/GB = $300 de retrieval + o custo de armazenamento regular. Para migrações de saída do S3, sempre calcule o custo de egress + retrieval.

**Ignorar o mínimo de 180 dias no Deep Archive:** arquivos que precisam ser rotacionados com frequência (ex: logs semanais deletados após 6 meses) incorrem na penalidade de armazenamento mínimo se deletados antes de 180 dias. Verifique se a retenção real é compatível com o mínimo da classe.

**Não configurar Provisioned Capacity para Expedited crítico:** sem capacidade provisionada, o Expedited pode falhar com `GlacierInsufficientCapacityException` em períodos de pico na AWS. Para sistemas de DR que dependem de Expedited, a capacidade provisionada ($100/mês/unidade) é essencial.

## 🧩 Quiz de Fixação

1. Uma empresa de saúde precisa armazenar 500 TB de imagens de exames por 10 anos. As imagens raramente são acessadas, mas quando o são (em caso de consulta médica ou auditoria), o acesso deve ocorrer em menos de 5 minutos. Qual classe Glacier escolher e calcule o custo mensal aproximado de armazenamento?

2. Um backup de 2 TB está armazenado em Glacier Flexible. O sistema caiu e a equipe precisa restaurar os dados em 4 horas. Qual tipo de retrieval usar, qual é o custo da restauração e que precaução deveria ter sido tomada previamente para garantir que isso funcione?

3. Por que armazenar objetos de 10 KB diretamente em Glacier Deep Archive é ineficiente, e como contornar esse problema em um cenário com milhões de arquivos pequenos?

**Respostas:**

1) **Glacier Instant Retrieval** — é a única classe Glacier com recuperação em milissegundos (< 5 minutos com absoluta certeza). Glacier Flexible Expedited promete 1-5 minutos mas pode falhar sem Provisioned Capacity; para imagens médicas com requisito regulatório de acesso imediato, a certeza do Glacier Instant é mais adequada. **Custo mensal:** 500 TB = 512.000 GB × $0.004/GB-mês = **$2.048/mês** (vs $11.776/mês no Standard-IA para o mesmo volume). Sobre 10 anos: $245.760 total vs $1.413.120 no Standard-IA — economia de ~83% no armazenamento. Adicionar o custo de retrieval nas consultas ocasionais ($0.03/GB × volume acessado por mês).

2) **Expedited retrieval** (1-5 minutos). **Custo da restauração:** 2.048 GB × $0.03/GB = **$61.44** em taxa de retrieval + $0.01/1.000 requisições. **Precaução necessária:** comprar **Provisioned Capacity** previamente ($100/mês/unidade). Sem capacidade provisionada, o Expedited pode retornar `GlacierInsufficientCapacityException` exatamente quando mais necessário — em situações de DR, outros clientes também podem estar tentando Expedited, criando contenção de capacidade. Para um sistema crítico com RTO de 4 horas e backup em Glacier Flexible, Provisioned Capacity é obrigatório, não opcional. A alternativa mais segura seria usar Glacier Instant Retrieval para esse backup específico, eliminando a necessidade de Provisioned Capacity.

3) O problema é o **mínimo de tamanho de 40 KB**: objetos de 10 KB são cobrados como 40 KB — 4x o armazenamento real. Para 10 milhões de objetos de 10 KB: armazenamento real = 100 GB; armazenamento cobrado = 400 GB. **Solução:** **agrupar os pequenos arquivos em archives maiores** antes de enviar ao Glacier. Por exemplo, compactar diariamente todos os arquivos pequenos em um único TAR.GZ de vários GiB e enviar esse arquivo ao Deep Archive. Isso elimina o overhead do mínimo de tamanho, reduz o número de operações (e portanto o custo de retrieval por requisição quando necessário) e ainda mantém os dados compactados (economia adicional). O trade-off é que para recuperar um arquivo específico, é necessário baixar e descompactar o TAR inteiro — ou manter um índice externo (ex: DynamoDB) mapeando nome do arquivo → TAR + posição dentro do TAR.
