### S3 Standard, Intelligent-Tiering, Standard-IA e One Zone-IA — classes de acesso frequente e infrequente

As classes de armazenamento do S3 são o mecanismo central de otimização de custo: ao declarar com que frequência você precisa acessar um objeto, o S3 ajusta onde e como ele é armazenado fisicamente, resultando em custos radicalmente diferentes. Escolher a classe errada é um dos erros de FinOps mais comuns em arquiteturas AWS.

---

## O modelo de custo das classes de armazenamento

Todas as classes têm dois componentes de custo principais:

```
Custo = Armazenamento ($/GB-mês) + Recuperação ($/GB acessado)

Regra geral:
  Armazenamento caro   → Recuperação barata (classes "quentes")
  Armazenamento barato → Recuperação cara  (classes "frias")

S3 Standard:    $0.023/GB-mês armazenamento + $0.090/GB download
S3 Standard-IA: $0.0125/GB-mês             + $0.010/GB recuperação
S3 Glacier:     $0.004/GB-mês              + $0.010/GB recuperação + latência

Ponto de break-even Standard vs Standard-IA:
  Se você acessa < ~25-30% dos dados por mês:
  Standard-IA é mais barato mesmo com a taxa de recuperação
```

Há também uma **taxa mínima de armazenamento** para classes IA e Glacier:
- Standard-IA e One Zone-IA: mínimo de **30 dias** por objeto
- Objetos deletados antes de 30 dias são cobrados como 30 dias

---

## S3 Standard — a classe de propósito geral

**S3 Standard** é a classe padrão: maior disponibilidade (99.99%), replicação em ≥3 AZs, sem taxa de recuperação, sem mínimo de duração. É a escolha para dados acessados com frequência ou quando o padrão de acesso é desconhecido.

```
Características do S3 Standard:
  Durabilidade:      99.999999999% (11 noves)
  Disponibilidade:   99.99%
  AZs:               ≥ 3
  Latência:          Milissegundos
  Taxa de recuperação: Nenhuma
  Mínimo de duração:   Nenhum
  Preço armazenamento: $0.023/GB-mês (us-east-1)
```

### Quando usar S3 Standard

```
✓ Conteúdo de sites e aplicações web (imagens, CSS, JS)
✓ Dados de analytics ativos (dashboards que rodam queries frequentes)
✓ Logs de aplicação dos últimos 30 dias
✓ Artefatos de build e deploy
✓ Dados cujo padrão de acesso é desconhecido (antes de analisar)
✓ Cache de dados processados que são re-acessados frequentemente
✓ Qualquer dado onde a taxa de recuperação tornaria IA mais caro
```

## S3 Intelligent-Tiering — otimização automática sem gestão manual

**S3 Intelligent-Tiering** monitora os padrões de acesso de cada objeto individualmente e move automaticamente entre tiers conforme o padrão muda. É a classe ideal quando o padrão de acesso é **imprevisível ou variável**.

```
Tiers dentro do Intelligent-Tiering:

Frequent Access tier:    acesso nos últimos 30 dias
  → Mesmo custo e performance do S3 Standard

Infrequent Access tier:  sem acesso por 30 dias consecutivos
  → Custo de armazenamento ~40% menor
  → Taxa de recuperação: nenhuma (diferente do Standard-IA)

Archive Instant Access:  sem acesso por 90 dias
  → Custo ainda menor (ativação opcional)
  → Recuperação em milissegundos

Archive Access:          sem acesso por 90-180 dias
  → Custo muito baixo (ativação opcional)
  → Recuperação em horas (como Glacier Flexible)

Deep Archive Access:     sem acesso por 180 dias
  → Custo mínimo (ativação opcional)
  → Recuperação em até 12 horas
```

```
Fluxo automático de um objeto no Intelligent-Tiering:

Dia 1:   Upload → Frequent Access tier
Dia 30:  Sem acesso → move para Infrequent Access tier
Dia 35:  Acesso → volta para Frequent Access tier (automático)
Dia 65:  Sem acesso → Infrequent Access tier novamente
Dia 90:  Sem acesso → Archive Instant (se ativado)
Dia 95:  Acesso → recuperação em milissegundos, volta para Frequent Access
```

### Custo do monitoramento

O Intelligent-Tiering cobra uma **taxa de monitoramento de $0.0025 por 1.000 objetos/mês** para rastrear os padrões de acesso. Para objetos pequenos (< ~128 KB), essa taxa pode superar a economia de armazenamento — configurar lifecycle para não usar IT em objetos muito pequenos.

### Quando usar Intelligent-Tiering

```
✓ Dados de usuários com padrão de acesso imprevisível
  (alguns usuários acessam frequentemente, outros raramente)
✓ Datasets de ML que são usados intensamente durante treino
  e raramente depois
✓ Logs que são consultados ativamente por 30 dias e depois raramente
✓ Backups que precisam estar disponíveis imediatamente se necessário
✗ Objetos muito pequenos (< 128 KB) — custo de monitoramento supera economia
✗ Objetos que você já sabe que raramente acessará → use Standard-IA diretamente
```

## S3 Standard-IA — Infrequent Access com multi-AZ

**S3 Standard-IA** armazena dados em ≥3 AZs (mesma durabilidade e disponibilidade próxima do Standard) mas assume que o acesso será infrequente — cobra menos pelo armazenamento e mais pela recuperação.

```
Características do S3 Standard-IA:
  Durabilidade:       99.999999999% (11 noves)
  Disponibilidade:    99.9% (vs 99.99% do Standard)
  AZs:                ≥ 3
  Latência:           Milissegundos (sem degradação vs Standard)
  Taxa de recuperação: $0.010/GB acessado
  Mínimo de duração:   30 dias por objeto
  Mínimo de tamanho:   128 KB por objeto (objetos menores são cobrados como 128 KB)
  Preço armazenamento: $0.0125/GB-mês (vs $0.023 do Standard = 46% mais barato)
```

### Análise de break-even Standard vs Standard-IA

```
Para 1 TB armazenado:
  Standard:    1.024 GB × $0.023 = $23.55/mês (sem taxa de recuperação)
  Standard-IA: 1.024 GB × $0.0125 = $12.80/mês + taxa de recuperação

  Se acessar 200 GB/mês:
    Standard total: $23.55 + $0 = $23.55
    IA total:       $12.80 + (200 × $0.010) = $12.80 + $2.00 = $14.80

  Se acessar 500 GB/mês:
    Standard total: $23.55
    IA total:       $12.80 + (500 × $0.010) = $12.80 + $5.00 = $17.80

  Break-even: quando recuperação mensal > ~108 GB (~10,5% dos dados)
  → Abaixo de ~10% de acesso/mês: Standard-IA é mais barato
  → Acima de ~10% de acesso/mês: Standard é mais barato
```

### Quando usar Standard-IA

```
✓ Backups mensais / semanais que raramente são acessados
✓ Logs de aplicação com 30-90 dias (acesso ocasional para análise)
✓ Imagens de DR (Disaster Recovery) que precisam de acesso rápido se acionadas
✓ Dados de compliance que precisam existir mas raramente são consultados
✓ Versões anteriores de objetos em buckets com versionamento
✗ Dados acessados frequentemente (use Standard)
✗ Objetos < 128 KB (serão cobrados como 128 KB — ineficiente)
✗ Dados que serão deletados em < 30 dias (cobrado mínimo de 30 dias)
```

## S3 One Zone-IA — Infrequent Access em AZ única

**One Zone-IA** tem o mesmo modelo de custo do Standard-IA mas armazena dados em apenas **1 AZ**, resultando em 20% de economia adicional no armazenamento. O trade-off é a ausência de resiliência a falhas de AZ.

```
Características do S3 One Zone-IA:
  Durabilidade:       99.999999999% (dentro da AZ — se a AZ sobreviver)
  Disponibilidade:    99.5%
  AZs:                1
  Latência:           Milissegundos
  Taxa de recuperação: $0.010/GB
  Mínimo de duração:   30 dias
  Preço armazenamento: $0.010/GB-mês (vs $0.0125 do Standard-IA = 20% mais barato)
  
  RISCO: Se a AZ for destruída (raro mas possível):
  → Dados em One Zone-IA PERDIDOS PERMANENTEMENTE
```

### Quando usar One Zone-IA

```
✓ Dados que podem ser recriados ou re-gerados se perdidos:
  - Thumbnails de imagens (o original está em Standard, thumbnail é re-gerado)
  - Cache de resultados processados
  - Artefatos de transformação (CSV processado a partir do Parquet original)
  - Cópia secundária de dados que já têm backup primário em outro lugar

✗ NUNCA para:
  - Dados únicos sem outra cópia (documentos de usuários, fotos originais)
  - Dados regulatórios ou de compliance
  - Qualquer dado onde a perda seria catastrófica para o negócio
```

## Configurando classes de armazenamento

### No upload (definir na criação)

```bash
# Upload direto para Standard-IA
aws s3 cp arquivo.csv s3://meu-bucket/dados/ \
  --storage-class STANDARD_IA

# Opções: STANDARD | REDUCED_REDUNDANCY | STANDARD_IA |
#         ONEZONE_IA | INTELLIGENT_TIERING | GLACIER |
#         DEEP_ARCHIVE | GLACIER_IR

# Copiar e mudar a classe de um objeto existente
aws s3 cp s3://meu-bucket/arquivo.csv \
  s3://meu-bucket/arquivo.csv \
  --storage-class INTELLIGENT_TIERING
```

### Via SDK (Python)

```python
import boto3

s3 = boto3.client('s3')

# Upload para Intelligent-Tiering
s3.put_object(
    Bucket='meu-bucket',
    Key='dados/relatorio.parquet',
    Body=data,
    StorageClass='INTELLIGENT_TIERING'
)

# Verificar a classe atual de um objeto
response = s3.head_object(Bucket='meu-bucket', Key='dados/relatorio.parquet')
print(response['StorageClass'])  # INTELLIGENT_TIERING
```

## Erros comuns e armadilhas

**Usar One Zone-IA para backups únicos:** o cenário mais perigoso. Se o backup é a única cópia dos dados e está em One Zone-IA, uma falha de AZ (rara mas documentada — happened em us-east-1 em 2019) resulta em perda permanente de dados.

**Ignorar o mínimo de 30 dias no Standard-IA:** armazenar logs de curta duração no Standard-IA é contra-produtivo. Se você quer manter logs por 7 dias e usar Standard-IA, cada log é cobrado como 30 dias — mais caro que o Standard.

**Não considerar o tamanho mínimo de 128 KB:** buckets com milhões de objetos pequenos (thumbnails de 5 KB, registros JSON de 1 KB) em Standard-IA são cobrados como 128 KB cada. Para 1 milhão de objetos de 1 KB: Standard-IA cobra 128x o armazenamento real.

**Ativar Intelligent-Tiering em objetos muito pequenos:** o custo de monitoramento ($0.0025/1.000 objetos/mês) supera a economia para objetos abaixo de ~128 KB. Use Lifecycle Policy para excluir pequenos objetos do IT.

## 🧩 Quiz de Fixação

1. Um bucket S3 armazena 10 TB de thumbnails de imagens. Os thumbnails são acessados raramente (90% nunca são acessados após o primeiro mês), mas quando acessados precisam estar disponíveis em milissegundos. Os thumbnails são gerados a partir de imagens originais que estão em outro bucket em S3 Standard. Qual classe escolher e por quê One Zone-IA é aceitável nesse caso específico?

2. Uma empresa tem 500.000 objetos JSON com tamanho médio de 2 KB cada em S3 Standard. O time de FinOps quer migrar para Standard-IA para economizar. Por que essa migração pode resultar em custo MAIOR, não menor?

3. O Intelligent-Tiering não cobra taxa de recuperação quando o objeto está no tier Infrequent Access — diferente do Standard-IA que cobra $0.010/GB. Então por que ainda existe razão para usar Standard-IA em vez de Intelligent-Tiering para dados que sabidamente têm acesso infrequente?

**Respostas:**

1) **One Zone-IA é a classe ideal** para esse caso. Justificativa: (a) os thumbnails são dados **reproduzíveis** — se perdidos, podem ser re-gerados a partir das imagens originais em S3 Standard (que estão em ≥3 AZs e são duráveis); (b) o acesso é infrequente (< 10% dos objetos por mês) e quando ocorre precisa de latência de milissegundos — One Zone-IA atende ambos os requisitos; (c) One Zone-IA é 20% mais barato que Standard-IA. O risco de perda por falha de AZ é aceitável porque não há perda de dados de negócio — apenas de cache regenerável. Se os thumbnails fossem a única cópia de dados únicos (fotos originais de usuários), One Zone-IA seria inaceitável.

2) A migração pode sair mais cara por dois motivos: (a) **Mínimo de tamanho de 128 KB:** cada objeto de 2 KB é cobrado como 128 KB no Standard-IA — isso é 64x o armazenamento real. Para 500.000 objetos: Standard cobra 500.000 × 2 KB = ~1 GB de storage; Standard-IA cobra 500.000 × 128 KB = 64 GB de storage efetivo. Com preços de us-east-1: Standard = $0.023 × 1 GB ≈ $0.023/mês; Standard-IA = $0.0125 × 64 GB ≈ $0.80/mês — **35x mais caro**; (b) **Taxa de recuperação:** se qualquer processamento batch acessa esses objetos regularmente, a taxa de $0.010/GB se soma. Para objetos pequenos com acesso frequente, Standard é quase sempre mais barato. A regra: Standard-IA só compensa para objetos grandes (> 128 KB) com acesso verdadeiramente infrequente.

3) Duas razões justificam Standard-IA sobre Intelligent-Tiering para dados sabidamente infrequentes: (a) **Custo de monitoramento:** Intelligent-Tiering cobra $0.0025/1.000 objetos/mês. Para 10 milhões de objetos: $25/mês apenas em monitoramento. Se o padrão de acesso é previsível (sabidamente infrequente), esse custo de monitoramento é desperdício — Standard-IA elimina esse overhead; (b) **Preço de armazenamento:** Standard-IA cobra $0.0125/GB-mês para o tier IA, enquanto Intelligent-Tiering cobra o mesmo $0.0125/GB-mês para o Infrequent Access tier mais a taxa de monitoramento. Quando o padrão de acesso é **conhecido e estável** (dados de compliance que nunca são acessados, backups mensais previsíveis), Standard-IA + Lifecycle Policy é mais econômico e previsível que Intelligent-Tiering. IT vale a pena quando o padrão é imprevisível e o custo de monitoramento é diluído em grandes economias de storage.
