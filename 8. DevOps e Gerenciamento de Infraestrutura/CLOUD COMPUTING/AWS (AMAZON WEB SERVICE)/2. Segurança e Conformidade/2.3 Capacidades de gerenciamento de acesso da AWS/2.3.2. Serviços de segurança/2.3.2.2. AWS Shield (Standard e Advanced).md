### AWS Shield — proteção DDoS nativa da AWS

AWS Shield é o serviço de proteção contra ataques de negação de serviço distribuída (DDoS) da AWS. Existe em dois níveis: Standard (gratuito e automático para todos os clientes) e Advanced (pago, com proteção expandida e suporte dedicado). Entender a diferença entre os dois e quando cada um se justifica é fundamental para arquitetar aplicações resilientes a ataques volumétricos.

---

## O que é um ataque DDoS

```
DDoS (Distributed Denial of Service):
  → Atacante coordena milhares/milhões de máquinas comprometidas (botnet)
  → Todas enviam tráfego simultâneo para o alvo
  → Alvo fica sem capacidade de responder requisições legítimas
  → Resultado: serviço fora do ar para usuários reais

Tipos de ataques por camada:

Layer 3/4 (volumétrico/protocolo) — mais comum, maior volume:
  ├── UDP Flood: envia pacotes UDP massivos para portas aleatórias
  ├── SYN Flood: inicia handshake TCP mas nunca completa
  ├── ICMP Flood: sobrecarrega com ping massivo
  ├── DNS Amplification: usa servidores DNS abertos para amplificar tráfego
  └── Volumetria típica: 1 Gbps a 1 Tbps+

Layer 7 (aplicação) — mais sofisticado, menor volume:
  ├── HTTP Flood: simula tráfego web legítimo em volume alto
  ├── Slowloris: mantém conexões abertas lentamente
  ├── Cache busting: requests com parâmetros únicos (burla CDN)
  └── Volumetria típica: 10k-100k req/s de IPs distribuídos
  
Shield Standard: foco em L3/L4
Shield Advanced: L3/L4 + L7 (com WAF integrado)
```

---

## AWS Shield Standard — proteção automática e gratuita

```
Disponibilidade: todos os clientes AWS, automaticamente, sem custo

O que protege:
  ├── Amazon EC2 (via EIP ou ALB)
  ├── Amazon CloudFront (distribuições)
  ├── AWS Global Accelerator
  ├── Elastic Load Balancing (ALB, NLB, CLB)
  └── Amazon Route 53 (hosted zones)

Proteção em nível de rede AWS:
  → A infraestrutura AWS absorve o tráfego antes de chegar ao cliente
  → Mitigação automática de ataques L3/L4 conhecidos
  → Sem configuração necessária — acontece na borda da rede AWS

Capacidade de absorção:
  AWS tem uma das maiores infraestruturas de rede do mundo
  → Backbone global com múltiplos Tbps de capacidade
  → Edge locations absorvem tráfego antes de chegar à região
  → Escala de ataque que derrubaria qualquer data center próprio
    é absorvida pela infraestrutura AWS

O que o Standard NÃO faz:
  ├── Não protege contra ataques L7 (HTTP flood, cache busting)
  ├── Não tem suporte da AWS DRT (DDoS Response Team)
  ├── Não protege financeiramente (escalonamento de custo em ataque)
  ├── Não gera alertas específicos de DDoS para o cliente
  └── Não fornece visibilidade de ataques em andamento
```

## AWS Shield Advanced — proteção expandida e suporte dedicado

### O que é e quanto custa

```
Custo: $3.000/mês por organização (não por conta)
       + taxa de uso de dados (pequena)
       Mínimo: 1 ano de compromisso

O que muda vs Standard:

1. PROTEÇÃO EXPANDIDA:
   Recursos elegíveis adicionais:
   ├── EC2 com EIP (Elastic IP) — proteção de IP individual
   ├── ELB (todos os tipos)
   ├── CloudFront
   ├── Global Accelerator
   └── Route 53 (incluindo registros individuais)
   
   Proteção L7 via WAF:
   → Integra com AWS WAF automaticamente
   → Regras de rate limiting aplicadas durante ataque detectado
   → WAF pago incluso no Shield Advanced (sem custo adicional)

2. SUPORTE AWS DRT (DDoS Response Team):
   → Equipe especializada da AWS disponível 24/7 durante ataques
   → Contato via AWS Support (Business ou Enterprise plan necessário)
   → DRT pode criar regras WAF em tempo real
   → DRT analisa tráfego e ajusta mitigações on-the-fly
   → Tempo de resposta: minutos durante ataque ativo

3. VISIBILIDADE E DETECÇÃO:
   Shield Advanced Dashboard:
   ├── Métricas em tempo real de eventos DDoS
   ├── Histórico de ataques
   ├── Resumo de mitigações aplicadas
   └── CloudWatch metrics: DDoSDetected, DDoSAttackBitsPerSecond
   
   CloudWatch Alarm para DDoS:
   Metric: DDoSDetected
   Condition: >= 1 por 1 minuto
   → Notificação SNS → PagerDuty → equipe de operações

4. PROTEÇÃO FINANCEIRA (DDoS Cost Protection):
   Durante ataque DDoS, os recursos podem escalar automaticamente:
   → EC2 Auto Scaling: mais instâncias para absorver tráfego
   → Data transfer: mais dados enviados
   → Custo do escalonamento causado pelo DDoS:
     → Shield Advanced reembolsa os custos adicionais
     → Clientes elegíveis podem solicitar crédito via support
   
   Recursos cobertos pelo reembolso:
   ├── EC2 (custo de instâncias adicionais do Auto Scaling)
   ├── Elastic Load Balancing (LCUs adicionais)
   ├── CloudFront (data transfer adicional)
   └── Route 53 (queries adicionais)
```

### Como configurar o Shield Advanced

```
Ativação:
  Console → AWS Shield → Subscribe to Shield Advanced
  → Selecionar recursos para proteger
  → Configurar SNS para alertas
  → Associar WAF Web ACL (se não tiver, criar uma)

Proteger recursos específicos:
  Console → Shield Advanced → Protected Resources → Add
  ├── Tipo: CloudFront, ALB, NLB, EC2, Route 53
  ├── ARN do recurso
  └── Health check associado (Route 53)
  
  Via CLI:
  aws shield create-protection \
    --name "MeuALBProducao" \
    --resource-arn arn:aws:elasticloadbalancing:us-east-1:123:loadbalancer/app/meu-alb/xxx

Health-based detection:
  Shield Advanced + Route 53 Health Check:
  → Se o health check falhar durante detecção de DDoS:
    aumenta a confiança que é ataque real (não falso positivo)
  → Melhora a qualidade das mitigações automáticas
  → Configura: Shield Advanced → Protected Resource → Associate Health Check
```

## DDoS e arquitetura resiliente

### Posicionar corretamente os recursos protegidos

```
Arquitetura vulnerável:
  Internet → DNS → IP público do EC2 → aplicação
  → EC2 exposta diretamente: sem absorção de tráfego na borda
  → Ataque volumétrico: satura a rede da instância EC2
  → Even Shield Standard protege menos sem borda

Arquitetura resiliente a DDoS:

  Internet
    │
    ▼
  [Route 53] ← com Shield Advanced e health checks
    │
    ▼
  [CloudFront] ← borda global, absorve L7, Shield Advanced
  + WAF (rate limiting, geo-blocking)
    │
    ▼
  [ALB] ← região, segunda camada, Shield Advanced
    │
    ▼
  [EC2/ECS] ← sem IP público (subnet privada)
  
  Vantagens da arquitetura:
  ├── Ataque bate primeiro no CloudFront (borda global)
  ├── CloudFront tem Tbps de capacidade de absorção
  ├── L7 DDoS: WAF faz rate limiting antes de chegar ao ALB
  ├── EC2 sem IP público: não pode ser atacado diretamente
  └── Cada camada tem Shield Standard ou Advanced

Geo-blocking para reduzir superfície:
  CloudFront + WAF:
  → Bloquear todos os países onde não há usuários legítimos
  → Um e-commerce brasileiro bloqueando tráfego de 150 países
    reduz a superfície de ataque drasticamente
  → Atacantes frequentemente usam VPNs/proxies de outros países
```

### Rate Limiting como primeira linha de defesa L7

```
AWS WAF Rate-Based Rule (fundamental):
  Regra: qualquer IP que fizer mais de X requests em 5 minutos → bloquear

  Configuração típica:
  Rate limit geral: 2.000 req/5min por IP (bloqueia bots simples)
  Rate limit em /login: 20 req/5min por IP (previne brute force)
  Rate limit em /api/search: 100 req/5min por IP
  
  Considerações:
  → Usuários legítimos raramente passam de 100 req/min
  → Bots de DDoS podem fazer 1.000-100.000 req/min
  → O threshold precisa ser calibrado (muito baixo: bloqueia usuários)

Durante ataque detectado pelo Shield Advanced:
  → DRT pode ajustar rate limits temporariamente
  → Threshold mais agressivo enquanto ataque durar
  → Volta ao normal após mitigação
```

## Shield Standard vs Advanced — quando cada um faz sentido

```
SHIELD STANDARD (todos):
  Adequado para:
  ├── Sites institucionais sem requisito de alta disponibilidade
  ├── Aplicações com baixo risco de ser alvo
  ├── Ambientes de desenvolvimento e staging
  └── Qualquer workload onde o custo de $3.000/mês não se justifica

SHIELD ADVANCED ($3.000/mês):
  Justifica para:
  ├── E-commerce com alto faturamento diário
  │   "1 hora fora = $100k em vendas perdidas"
  │   $3.000/mês < custo de 1 hora de downtime → ROI claro
  │
  ├── Plataformas financeiras (bancos, fintechs, corretoras)
  │   → Regulação exige alta disponibilidade
  │   → Alvo frequente de ataques motivados
  │
  ├── Jogos online e plataformas de streaming
  │   → DDoS é táctica comum de concorrentes/trolls
  │   → Base de usuários paga por disponibilidade
  │
  ├── Infraestrutura crítica (saúde, governo, telecom)
  │   → Downtime tem consequências além do financeiro
  │
  └── Qualquer empresa que já foi alvo de DDoS
      → Ataque recorrente = Shield Advanced vale cada centavo

Cálculo de ROI:
  Shield Advanced: $3.000/mês = $36.000/ano
  
  Perguntas para justificar:
  1. Qual o custo de 1 hora de downtime? (receita perdida + reputação)
  2. Qual a probabilidade de ser alvo de DDoS?
  3. O reembolso de custo de escalonamento cobriria parte do custo?
  
  Se custo de 1h downtime > $3.000 → Shield Advanced justificado
```

## Respondendo a um ataque DDoS ativo

```
Processo durante ataque com Shield Advanced:

1. DETECÇÃO (automática):
   CloudWatch Alarm: DDoSDetected = 1
   → SNS → PagerDuty → Engenheiro de plantão alertado
   Shield Dashboard: mostra tipo, tamanho, recursos afetados

2. AVALIAÇÃO INICIAL (0-5 minutos):
   → Verificar Shield Dashboard: L3/L4 ou L7?
   → Verificar WAF Logs: qual padrão de requisições?
   → Verificar CloudFront metrics: qual região de origem?
   → Auto-mitigação já ativa? (Shield Standard/Advanced)

3. AÇÃO IMEDIATA (5-15 minutos):
   L7 flood detectado:
   → WAF: adicionar regra de rate limiting mais agressiva temporária
   → WAF: bloquear países de origem do ataque
   → CloudFront: habilitar geo-restriction se não estava ativo
   
   L3/L4 flood:
   → Verificar se Shield está mitigando automaticamente
   → Se não: contatar DRT (Shield Advanced) via AWS Support

4. SUPORTE DRT (Shield Advanced):
   aws shield create-emergency-contact-settings \
     --emergency-contact-list "[{EmailAddress=soc@empresa.com,PhoneNumber=+5511999}]"
   
   → Abrir case de suporte: "DDoS Attack in Progress"
   → DRT responde em minutos
   → DRT analisa tráfego e pode ajustar mitigações

5. PÓS-ATAQUE:
   → Solicitar relatório do Shield Advanced
   → Solicitar crédito de custo (DDoS Cost Protection)
   → Revisar regras WAF permanentes com base no padrão do ataque
   → Post-mortem: como detectamos, quanto tempo de mitigação
```

## 🧩 Quiz de Fixação

1. Uma aplicação usa apenas EC2 com IP público, sem CloudFront ou ALB. Durante um ataque SYN Flood (L3/L4), o Shield Standard está ativo. Por que a proteção é menos efetiva nessa arquitetura comparada a uma com CloudFront + ALB, mesmo que o Shield Standard seja o mesmo?
2. Uma fintech processa R$ 2 milhões em transações por dia (12 horas de operação). O custo do Shield Advanced é $3.000/mês. Calcule se o custo é justificado considerando que um ataque DDoS bem-sucedido causaria downtime médio de 2 horas.
3. O Shield Advanced tem "DDoS Cost Protection" (reembolso de custos). Em qual cenário esse benefício seria particularmente valioso, e como funciona o processo de reembolso?

**Respostas:**
1) O Shield Standard opera na borda da rede AWS (edge locations), mas quando o tráfego de um ataque L3/L4 chega diretamente ao IP público de uma instância EC2, ele já está dentro da região AWS — a mitigação na borda é menos precisa para tráfego direcionado a um IP específico de instância. Com CloudFront + ALB: o tráfego bate primeiro no CloudFront (edge locations globais com capacidade de Tbps) — o ataque é absorvido na borda antes de chegar à região, e o IP do CloudFront é o alvo (não o IP do EC2, que fica oculto em subnet privada). Com EC2 direto: o IP do EC2 é o alvo, o tráfego chega à região e à instância antes de poder ser totalmente mitigado, sobrecarregando a interface de rede da instância mesmo com Shield ativo. Além disso, sem CloudFront, não há cache de conteúdo estático — o backend recebe todo o tráfego.
2) Cálculo de ROI: R$ 2M/dia ÷ 12h de operação = R$ 167k/hora de receita. Um ataque DDoS com 2h de downtime = R$ 334k em receita perdida (apenas receita direta — não conta reputação, multas regulatórias de compliance financeiro, ou clientes perdidos). Shield Advanced: $3.000/mês × 5,5 (câmbio aproximado) = ~R$ 16.500/mês. Um único ataque bem-sucedido por mês (R$ 334k) supera em 20x o custo do Shield Advanced. Para uma fintech regulada, o cálculo é ainda mais desfavorável sem proteção: BACEN/CVM podem aplicar multas por indisponibilidade de serviços críticos, e a obrigação regulatória de alta disponibilidade torna o Shield Advanced praticamente mandatório. ROI: claramente positivo.
3) O DDoS Cost Protection é mais valioso quando o ataque força o Auto Scaling a escalar drasticamente — por exemplo, uma aplicação configurada com ALB + Auto Scaling que escala de 10 para 200 instâncias EC2 durante um ataque de 6 horas acumula um custo imenso de EC2 + data transfer que nunca estaria no orçamento. Com Shield Advanced, esses custos adicionais causados especificamente pelo ataque DDoS podem ser reembolsados via crédito AWS. O processo: (1) durante ou após o ataque, identificar quais recursos escalaram anormalmente; (2) verificar no Shield Dashboard que o período corresponde a um evento DDoS reconhecido; (3) abrir case no AWS Support com evidências do Shield Advanced mostrando o ataque e os recursos afetados; (4) a AWS analisa e emite créditos proporcionais aos custos de escalonamento causados pelo ataque. Importante: o reembolso é discricionário (não automático) e requer documentação do evento de DDoS reconhecido pelo Shield.
